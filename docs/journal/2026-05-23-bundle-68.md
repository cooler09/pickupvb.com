# Bundle 68 — 2026-05-23 — Model P1 `event_attendees.division_id` nullable: schema-enforcement bookkeeping close (Registration workflow, ✅ Live verified)

## Context

After Bundle 67 closed the Organization audit's Bundle 65/66 follow-ups,
the next implementation candidate up the queue was the Registration
audit's open-play division picker (UX P1 half) — the only remaining
P1-flavored item on the registration workflow board.

Scoping that against the codebase produced a surprise: open-play
events are single-division **by product design**, not by accident.
The event-create form gates `DivisionsRepeater` on
`EventType.Tournament` ([new-event-form.tsx#L515-L565](../../apps/web/src/app/events/new/new-event-form.tsx#L515)),
so no open-play path can ever produce a multi-division configuration.
A picker on `RsvpPanel` / `PaidTicketPanel` / `PositionRsvpPanel`
would have nothing to pick from. The Bundle 1/5 team + free-agent
boundary fixes already handled the multi-division case for the two
flows that genuinely have multiple divisions.

That kicked over a second rock: the original Model P1 finding —
"`event_attendees.division_id` is nullable and never populated for
multi-division events" — was listed inline in the Findings section
but never appeared in the Still-open list and never had its inline
header flipped. The schema-level fix (NOT NULL on all three
division-bearing child tables, plus a backfill of stragglers) had
actually shipped in migration `20260606000000_team_registration_model.sql`
(lines 269–271) at the same time as the ad-hoc team model work. The
bookkeeping just never caught up.

So Bundle 68 is the formal close, modeled on Bundle 62's
verify-and-close pattern: re-trace the layers, write the status
block, flip the inline header, retire the orphaned finding.

## Pattern notes

### Orphaned findings: listed inline, missing from Still-open

The Model P1 finding was present in the Findings section of the
audit but never made it into the Still-open list at the bottom.
Result: every Wontfix / closure sweep walked the Still-open list and
overlooked it, while the inline header never got flipped because
nobody re-read the Findings section linearly. Worth a sanity check
the next time a registration audit lands: cross-reference inline
P1/P2 headers against the Still-open list and make sure each one
either has a "✅ Closed" suffix or a Still-open bullet.

### Schema closures often pre-date their bookkeeping

This is the second time (after Bundle 62) that the audit text was
the lagging artifact. The pattern: a single broad migration ships
several invariants at once (here, migration 20260606000000 added
NOT NULL on `event_attendees.division_id` as a side effect of the
team-registration-mode work), but the audit was only updated for
the headline change. When writing a migration that touches more
than one audit finding, grep `docs/audits/` for the table / column
name and check whether anything else was implicitly closed.

### "Picker" findings that turn out to be product-design constraints

The UX P1 open-play picker turned out to be moot because open-play
is single-division by design (no `DivisionsRepeater` for non-tournament
events). Worth a pause when an audit asks for "wire a picker for X" —
first verify there's an `X` to pick from in the user's reach. If the
UI never generates the multi-X case, the picker is dead code waiting
to happen.
