# Bundle 119 — Per-division team registration mode (ADR 0016) (2026-05-27)

## Context

Bundle 117 (registration-workflow re-audit) logged six findings; Bundle
118 closed R1 / R2 / R6. This bundle closes **R3 (P2)** —
`team_registration_mode` lived on `events`, which forced hosts running a
multi-division tournament to pick one mode for the whole event. The
concrete pain the user described: a tournament with an A division
(roster-only, USAV-style competitive teams) **plus** a BB division
(ad-hoc, sign-up-as-a-pair). The only workaround on the old shape was
to split it into two events with the same date/venue, which forks the
attendee list, doubles host effort, and breaks the "the event is the
container" mental model Bundle 117 ratified.

R3 was tagged P2 in the audit; the user escalated by asking for it
explicitly after shipping Bundle 118.

R4 (walk-ins as first-class registrations) remains deferred — it needs
a product decision on `captain_id` nullability.

## Decisions

- **Move the column, don't add a join table.** `team_registration_mode`
  is a per-row attribute of a division, not a many-to-many relation;
  nesting it under `event_divisions` matches the existing pattern
  (capacity, surface, format, gender, skill tier, team composition,
  pricing, `allow_free_agents`) and removes the only event-level
  registration-shape field. Authored as **[ADR 0016](../adr/0016-per-division-team-registration-mode.md)**;
  supersedes ADR 0008 §2 and amends ADR 0012's matrix to be
  division-scoped.
- **Drop `events.team_registration_mode` in the same migration.** Two
  options on the table:
  - **A. Keep the column, mark deprecated, drop in a follow-up.** Lets
    code migrate gradually but leaves a foot-gun: any future writer
    that sets the event-level column would silently disagree with the
    per-division truth. The audit explicitly flagged this exact failure
    mode for R6 (parent/child redundancy).
  - **B. Drop it in the same migration.** Chosen. Backfill copies the
    event-level value into every division (so all existing tournaments
    keep their current behaviour), then `alter table … drop column`
    in the same file. Forces every reader/writer to be updated in this
    bundle — exactly what the type system and verify chain catch.
- **Truly mixed-mode events are allowed.** No invariant forbids one
  division being `ad_hoc` while another is `roster` (or `null`). The
  signup UI handles this by rendering both `AdHocTeamSignupPanel` and
  `TournamentSignupPanel` stacked, each filtered to its mode's
  divisions. The matrix invariant in ADR 0012 (composition ↔ price
  unit) now runs per division.
- **Default for new tournament divisions is `ad_hoc`.** Matches the
  prior event-level default; preserves the create-event form behaviour
  where ticking "tournament" + a non-solo composition gives the host
  ad-hoc out of the box without an extra click.
- **`UpdateEventDivisionHandler` merge semantics.** When the host
  edits a division and omits `teamRegistrationMode`, the handler keeps
  the current value. Explicit `null` is allowed and clears the mode
  (turning that division into individual-signup); the form maps the
  "None" `<select>` option to `null` via the existing
  `fieldOrUndefined` helper.
- **RLS rewritten, not extended.** The two policies that gated team
  inserts (`event_team_registrations_insert` for ad-hoc,
  `event_team_payments_insert` for roster) used to join `events`. They
  now join `event_divisions` (and `event_teams` for the payment
  policy). Same intent, division-scoped check.

## Changes

### Schema + ADR

- **ADR** —
  [docs/adr/0016-per-division-team-registration-mode.md](../adr/0016-per-division-team-registration-mode.md)
  — supersedes ADR 0008 §2; amends ADR 0012's matrix to per-division.
- **Migration** —
  [supabase/migrations/20260711000000_per_division_team_registration_mode.sql](../../supabase/migrations/20260711000000_per_division_team_registration_mode.sql)
  — adds nullable `event_divisions.team_registration_mode`, backfills
  from `events.team_registration_mode`, rewrites the two RLS policies
  to join `event_divisions`, drops `events.team_registration_mode`,
  and rebuilds `events_view` without the field.
- **Types stub** — hand-patched in
  [packages/supabase/src/database.types.ts](../../packages/supabase/src/database.types.ts)
  (Docker not running locally): removed from `events` Row/Insert/Update
  and `events_view` Row; added to `event_divisions` Row/Insert/Update.

### Domain

- [`Division`](../../packages/domain/src/events/division.ts) — adds
  optional `teamRegistrationMode` to `CreateDivisionProps`, ctor,
  `fromPersistence`.
- [`VolleyballEvent`](../../packages/domain/src/events/volleyball-event.ts)
  — removes `teamRegistrationMode` from `EventExtensionsInput` /

  event-level getter, and rewrites `assertRegistrationConfigValid()`
  to iterate divisions: ad-hoc / roster divisions require non-solo
  composition + per-team pricing; null-mode divisions require solo +
  per-player.

### Application

### Infrastructure

- [`EventRepository.DivisionLite`](../../packages/domain/src/events/event-repository.ts)

### Types

## Follow-ups deferred

- **R4 (P2) — walk-ins as first-class registrations.** Needs a
  product decision on `captain_id` nullability (host-entered walk-ins
  belong to the event-day roster but have no auth account). Tagged for
  Bundle D in the original re-audit plan.
- **Drop `events.team_registration_mode` reader columns elsewhere.**
  Grep shows the field removed from production code; remaining
  references are journal entries and the registration-workflow audit
  log itself (which gets a new remediation row in this bundle).
- **Multi-mode picker polish.** When an event has both an ad-hoc and
  a roster division, the signup area currently stacks the two panels
  vertically. A tab-or-segmented control could compress this once the
  pattern proves out with real hosts.
