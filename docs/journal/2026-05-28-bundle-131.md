# 2026-05-28 — Bundle 131 (M3 State Layers + Button Vocabulary)

Third installment of the M3 adoption plan from
[docs/audits/m3-alignment.md](../audits/m3-alignment.md). Bundle 129
shipped tokens, Bundle 130 swept touch targets, this bundle ships the
state-layer utility + three new button variants that complete the M3
button vocabulary.

## Context

Audit P2 #4 noted that hover/focus/pressed handling is bespoke per
component: `PrimaryButton` used `hover:opacity-90`, `MobileMenu` used
`hover:bg-fg/5`, `Pagination` used whatever was easiest at the call
site. M3 standardizes this as a **state layer** — a single
`currentColor` overlay at a per-state alpha (8% / 12% / 12% / 16% for
hover / focus / pressed / dragged). Defining the overlay once unblocks
Bundle 5 (FAB + BottomNav, which need consistent state handling) and
removes the visual drift that's accumulated across one-off hover rules.

The same bundle also adds the **three missing button variants** —
tonal, secondary (outlined), text — so the next bundles that need a
"quieter than the primary CTA" button (Bundle 4's toast action slot,
Bundle 5's BottomNav items, Bundle 6's dialog footer) have one in the
vocabulary.

## Decisions

- **`state-layer` as a single Tailwind 4 `@utility`.** The audit's
  starter pattern used `@apply` heavily. I expanded the body to plain
  CSS so it doesn't depend on Tailwind utilities existing for every
  property — easier to grep, easier to debug in DevTools, identical at
  runtime.
- **Gate the hover/active overlay on `:not(:disabled)`.** Without it,
  a `<button disabled>` would still paint the overlay on mouse-over —
  visually contradicts the disabled affordance. Focus-visible is left
  ungated so keyboard tab-through still surfaces the ring even if a
  disabled control briefly receives focus.
- **Transition uses the M3 motion tokens shipped in Bundle 129**
  (`--md-sys-motion-duration-short2`, `--md-sys-motion-easing-standard`).
  First call site that actually consumes them — proves the tokens
  resolve correctly through `:root`.
- **Variants reuse legacy color tokens, not M3 roles.** Tonal could
  have used `bg-md-secondary-container` but we'd then have two
  parallel palettes in the same component family. The buttons stay on
  `--color-primary` until the broader call-site migration flips
  everything in one bundle. Variants use `bg-primary/10` (tonal),
  `border-primary` + `bg-transparent` (outlined), `text-primary` only
  (text). All four variants share the same `state-layer` overlay so
  hover/focus/pressed reads identically across the family.
- **Did NOT migrate `MobileMenu`, `NavDropdown`, list rows, etc.**
  Each is a different surface category and lives in its own bundle.
  Doing them now would inflate this bundle and make a regression
  harder to bisect.

## Patterns observed

- **`isolation: isolate` + `::after` overlay** is the right primitive
  for any "tint on interaction" effect. Wherever we add a third-party
  primitive that needs hover feedback (Radix DropdownMenu items, etc.)
  the same pattern composes — wrap the trigger in `state-layer` and
  it inherits.
- **Refactoring `primaryButtonClass` into a `SIZING` + `BASE` const**
  surfaced that `inline-flex items-center justify-center rounded-md
font-semibold` is genuinely shared across all four variants. The
  audit's "every button looks slightly different" was already half
  centralized — the new variants just make the centralization
  observable.
- The `state-layer` overlay uses `currentColor`, which means the same
  utility produces a white-ish tint on filled-primary, a teal tint on
  outlined/text/tonal — the right thing per M3 without per-variant
  state-layer-color overrides. Worth knowing when adding the next
  variant.

## Follow-ups deferred

- **Bundle 4 — Radix Toast** (audit P2 #8). Drop in
  `@radix-ui/react-toast` while preserving the `useToast()` API.
  Tonal/secondary buttons land here for the toast action slot.
- **State-layer call-site sweep.** Once Bundle 5+ have migrated their
  respective surfaces, do a final grep for `hover:opacity-` and
  `hover:bg-fg/5` and migrate any stragglers.
- **PrimaryButton component for `tonal` / `secondary` / `text`.** I
  only added the class-string helpers, not React wrappers — the class
  helpers cover 95% of call sites (which spread onto `Link` / `a` /
  `SubmitButton`). Add wrappers if a real call site needs the
  `<button>` shorthand.
- **`disabled:opacity` levels diverge** between primary (0.6) and
  variants (0.5). The audit will eventually want one canonical
  disabled-opacity token — defer until the M3 token sweep adds
  `--md-sys-state-disabled-opacity` (M3 spec is 0.38, but that's a
  bigger visual change).
