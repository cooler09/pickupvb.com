# 2026-05-24 — Bundle 21: Drop /teams/[slug] login gate

## Context

Bundles 18 + 20 shipped `BreadcrumbList` + `SportsTeam` JSON-LD on
`/teams/[slug]`, and the page has been in [sitemap.ts](../../apps/web/src/app/sitemap.ts)
since Bundle 14. But the page handler still redirected unauthenticated
visitors to `/login` — so Googlebot, OpenGraph crawlers, and Knowledge
Graph scrapers never reached any of the structured data. The whole SEO
chain on this route was wasted spend. Both Bundle 18 and Bundle 19
logged it as a follow-up; this bundle resolves it.

## Decisions

- **Drop the gate, don't drop the sitemap entry.** Two ways to
  reconcile sitemap-vs-redirect: remove the URL from the sitemap (kill
  the discoverability we just added) or remove the gate (expose the
  page). Volleyball team rosters are not sensitive — display names +
  handles already appear on each player's `/players/[handle]` profile,
  which has no gate. Removing the gate preserves all the work we
  already did.
- **No new RLS work needed.** Verified [supabase/migrations/20260512000000_init.sql](../../supabase/migrations/20260512000000_init.sql) L242–L247:
  `teams_select` and `team_members_select` policies both use
  `USING (true)`. Anonymous SELECT was already permitted by the
  database; the handler-level redirect was the only thing keeping
  crawlers out.
- **Captain UI was already gated.** `AddTeamMemberForm`,
  `ExtraMembersForm`, `CaptainBroadcastPanel`, and per-row
  management actions are all wrapped in `isCaptain && …`. The viewer
  membership / pending-invite branch (`InviteResponse`) only renders
  when the viewer is in the roster. Making `user` optional cleanly
  short-circuits all of these.
- **Kept `force-dynamic`.** The page still has per-viewer state
  (`isCaptain`, `viewerHasPendingInvite`) that requires per-request
  rendering. ISR-ing the shell would require a Suspense refactor —
  that's the cross-listed SEO P2 / performance P1 item, scoped
  separately.
