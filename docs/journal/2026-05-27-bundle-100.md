# Bundle 100 — off-platform event upsell (P2 #7)

## Why

[Monetization audit](../audits/monetization.md) P2 #7 was the last
remaining "ship it" item that wasn't either already shipped or
deferred-on-trigger (P2 #6, metro sponsorship, is waiting on a
real anchor advertiser). The hole the audit named:

> A host who flips `payments_off_platform = true` uses every PickupVB
> feature (event page, RSVP management, broadcasts, reminders, roster)
> and pays $0. This is a deliberate product mode … but it caps lifetime
> revenue on those hosts at zero.

The audit explicitly forbids charging for off-platform mode (kills
the casual host on-ramp) and prescribes the fix as:

> Add a soft, dismissible upsell on the event detail page for
> off-platform events: "Tired of chasing Venmos? Switch to on-platform
> payments — automatic refunds, no chasing." Single-occurrence cookie
> to suppress per host.

Half a bundle.

## What changed

### 1. Cookie-name constant in `apps/web/src/lib`

[apps/web/src/lib/off-platform-upsell.ts](../../apps/web/src/lib/off-platform-upsell.ts)
exports `OFF_PLATFORM_UPSELL_COOKIE = 'pickupvb_op_upsell_dismissed'`.

This had to live outside the `'use server'` action file because Next
forbids non-function exports from server-action modules. The page
reads the cookie, the action writes it, both import the constant.

### 2. Server action

[apps/web/src/app/events/[id]/off-platform-upsell-actions.ts](../../apps/web/src/app/events/%5Bid%5D/off-platform-upsell-actions.ts)
exposes `dismissOffPlatformUpsell(returnPath)`. It writes the cookie
(`path=/`, `maxAge=1 year`, `sameSite=lax`, no `httpOnly` so the
banner can be toggled without a server round-trip in a future
iteration if we want), then `revalidatePath`s the event detail so
the page re-renders without the banner.

Mirrors the
[apps/web/src/app/theme-actions.ts](../../apps/web/src/app/theme-actions.ts)
pattern.

### 3. Banner component

[apps/web/src/app/events/[id]/\_components/off-platform-upsell.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/off-platform-upsell.tsx)
is a server component (no `'use client'`) that renders a
`<aside>` with the pitch copy, a "Switch" link to
`/events/[id]/edit`, and a "Dismiss" button inside a
`<form action={dismissOffPlatformUpsell.bind(null, returnPath)}>`.
Pure server-action form post — no JS required.

The component is presentational. All three render conditions are
enforced at the call site so the component is reusable and easy
to reason about in isolation.

### 4. Page wiring

[apps/web/src/app/events/[id]/page.tsx](../../apps/web/src/app/events/%5Bid%5D/page.tsx)
renders the banner above the hero image (between
`EventFlashBanners` and `HeroImage`) when **all three** conditions
hold:

```tsx
isHostOfEvent &&
  event.paymentsOffPlatform &&
  (await cookies()).get(OFF_PLATFORM_UPSELL_COOKIE)?.value !== '1';
```

- `isHostOfEvent` already comes off the `loadEventDetail` view
  model — no new query.
- `event.paymentsOffPlatform` is on the `EventDetailReadModel`
  ([packages/domain/src/events/volleyball-event.ts#L550-L551](../../packages/domain/src/events/volleyball-event.ts#L550-L551)).
- Cookie read is one `cookies()` call, already cheap.

Placement above the hero is intentional — the audit wants this to be
**seen** by hosts who are leaving revenue on the table, not buried in
the host-tools accordion. Attendees never see it because the host
gate is checked first.

## Follow-ups deferred

- **Analytics event.** A `cta_off_platform_switch_clicked` PostHog
  event would close the loop on whether the nudge actually moves
  hosts to on-platform. Trivial to add; deferred to keep this a
  half-bundle.
- **E2E spec.** An `@authed` spec asserting (a) free host on an
  off-platform event sees the banner, (b) after `Dismiss` form
  submit the banner is gone and the cookie is set, (c) host on an
  on-platform event never sees it. The dismiss form is a single
  server-action POST so the spec is short; deferred for the same
  reason as the analytics event.
- **Per-host vs per-browser cookie.** Today it's per-browser (one
  cookie scope). If two hosts share a browser the first to dismiss
  hides it for both. Acceptable for a soft nudge; revisit if a
  real complaint surfaces. Per-host scoping would need either an
  `op_upsell_dismissed_<userId>` cookie family (unbounded growth)
  or a `profiles.dismissed_off_platform_upsell_at` column.
- **Cross-device persistence.** Cookie is browser-local. A host who
  dismisses on laptop sees it again on phone. Same fix as above
  (DB column on `profiles`) would solve cross-device too.
