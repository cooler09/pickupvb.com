# 2026-05-24 — Bundle 5: free-agent division picker

## Context

After Bundle 4 closed the last Model P1 on the
[registration-workflow audit](../audits/registration-workflow.md), the
highest-priority remaining item was the **UX P1 leftover** — free-agent
and open-play signup paths had no division picker. The same surface
also carried a Model P2 — `event_free_agents.division_id` was nullable
with no UI to set it, leaving multi-division tournaments with free
agents that never declared which division they were available for.

The team-registration path already had a division picker via
[`TournamentSignupPanel`](../../apps/web/src/app/events/%5Bid%5D/_components/tournament-signup-panel.tsx)
(Bundle 2, 2026-05-22) plus an `attachTeamToDivision` port that
side-steps the aggregate (the aggregate's `_teams` set has no slot for
`division_id`). Free agents needed the mirror treatment.

## Decisions

### Side-step the aggregate (mirror teams)

The `VolleyballEvent` aggregate's `_freeAgents` map is
`Map<UserId, string | null>` — userId → notes only, no slot for
`divisionId`. Two options were considered:

1. **Extend the aggregate** to `Map<UserId, { notes, divisionId }>` and
   make `joinAsFreeAgent(userId, notes, divisionId)` the authoritative
   write path.
2. **Side-step like teams** — leave the aggregate alone; persist the
   division via a dedicated `attachFreeAgentToDivision` port called
   from the handler after `save(event)`.

Chose option 2 because:

- It matches the existing `attachTeamToDivision` precedent exactly, so
  the codebase carries a single pattern for "domain field that lives on
  the join row but not in the aggregate" rather than two.
- It avoids touching the aggregate's free-agent invariants and the
  large test surface in `volleyball-event.test.ts`.
- The trade-off (DB row is briefly created without `division_id` between
  `save` and `attachFreeAgentToDivision`) is bounded by a single
  request and self-heals on retry; the existing single-division
  trigger (`fill_default_division_id`) also covers the common case.

The deferred work — eventually moving division ownership into the
aggregate when the team-paradigm ADR lands — is captured under
follow-ups.

### Open-play out of scope

The audit grouped "free-agent and open-play division picker" together,
but the domain blocks `joinAsFreeAgent` on `EventType !== Tournament`
([volleyball-event.ts L698](../../packages/domain/src/events/volleyball-event.ts#L698)),
and open-play events don't model divisions at all (RSVP / position /
paid-ticket panels have no division context). Scoping Bundle 5 to
tournament free agents only.

### No new migration needed

`event_free_agents.division_id` was added (nullable, FK +
auto-fill trigger) in
[20260605000100_event_divisions.sql](../../supabase/migrations/20260605000100_event_divisions.sql).
Bundle 5 just populates the column — no schema change required.

## Patterns observed

- **The "side-step the aggregate" pattern is now a doctrine.** Both
  teams and free agents now use the same shape: aggregate runs the
  invariants, `save(event)` inserts the join row with whatever fields
  the aggregate knows about, then a dedicated `attach*ToDivision`
  port fills in the join-row-only column. Worth promoting into
  AGENTS.md "Patterns surfaced by audits" when a third instance
  appears.
- **Form flash codes scale linearly.** Adding `division_required` to
  `RESULT_MESSAGES` + the back() call was a 4-line diff; no machinery
  needed. The flash-param pattern continues to age well for plain
  `<form action={…}>` paths.
- **The `[id]` glob trap is still alive** — `file_search` / `grep_search`
  filter bracketed paths. Used `run_in_terminal grep -rn` whenever
  searching under `apps/web/src/app/events/[id]/`.

## Follow-ups deferred

- **Free-agent claim affordance** (audit UX P3): captains still can't
  pick up a free agent from the list. The natural place is a
  `claimFreeAgent(captainId, agentUserId)` action that adds the agent
  to the captain's team roster for this event. Out of scope for
  Bundle 5.
- **Free-agent list grouping by division** (audit UX P3): with the
  division pill in place, the next improvement is to group the list
  itself by division on multi-division events.
- **Move division ownership into the `VolleyballEvent` aggregate**
  for both teams and free agents — would obsolete both `attach*ToDivision`
  ports. Worth doing when the team-paradigm ADR is written
  (audit "Recommended sequencing step 1"), since that ADR will likely
  restructure the aggregate anyway.
- **`PaidTicketPanel` double-CTA** (audit UX P2): unchanged.
- **`TournamentRegistrationTabs` single-flow refactor** (audit UX P2):
  unchanged.
