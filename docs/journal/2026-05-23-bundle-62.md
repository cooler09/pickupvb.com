## Pattern notes

### Promote "discovery" notes into formal closures promptly

The Bundle 6 remediation log row said the audit's question was
already answered ("live, per Bundle 6 discovery") but the audit
checklist (the still-open list and the inline section header)
wasn't updated. Three weeks later this bundle had to re-do the
trace to validate that the Bundle 6 claim still held. Lesson:
when a bundle answers an audit question as a side effect of other
work, take the extra two minutes to flip the inline header and the
still-open bullet. Otherwise the next agent re-investigates.

### "Live-vs-dead audit" is a real audit-finding shape

Most audit findings are "do this thing." A few are "verify this
thing still works / is reachable." Treating the verification-only
findings as first-class items (with their own closure type \u2014
"✅ Live (verified)" alongside "✅ Fixed" and "✅ Wontfix") makes
it easier to grade them. The remediation log row in this bundle
uses that exact phrasing.

### Trace-by-layer table earns its space

The status block uses a table (`Layer | File | Wired`) instead of
prose. Reads at a glance, future re-verifications can diff against
it (which layers moved? which file references rotted?), and
narrowly fits the "concrete recommended fix" requirement \u2014
the table _is_ the answer to "what would the fix look like" by
showing the work is already complete.
