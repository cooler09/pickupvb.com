## Pattern notes

- **Code-closed ≠ audit-closed.** Bundle 17 shipped the FormData cap
  and Turnstile freshness fixes plus tests but left the finding
  headers untouched. The remediation log row is enough to find the
  closure after the fact, but the finding section itself still reads
  as open during scans. When closing an audit item, flip both: the
  finding header (with an inline `Status: ✅ Resolved YYYY-MM-DD
(Bundle N)` line pointing at the resolved file) **and** add the
  remediation log row. Bundle 51 (documentation `@throws` closeout)
  had the same pattern surface.
- **Preemptive findings without re-open triggers rot.** P3 #11 sat as
  "preemptive" for six months. A wontfix-with-trigger is more useful
  than a perpetual reminder: future readers can see at a glance whether
  the trigger condition has been met. Same shape applies to other
  preemptive items as they're identified.
- **Pure-bookkeeping bundles are valid when they remove an entire
  class of noise from a backlog.** This bundle clears the open P3
  list on the security audit down to a single substantive item (#8
  audit-log coverage), which sharpens the next-bundle decision.
