# Bundle 111 — Bracket: one-click spectator link share

## Why

The watch route shipped in bundle 108 with a single discovery
path: a "Open public spectator view →" anchor on the host
bracket page. To actually share that URL with players or
spectators a host had to open the watch page, copy from the
address bar, paste into a group chat — three context switches
for the most common ask at the venue ("what's the link to
follow along?").

Goal for this bundle: zero-friction copy + native-share for
that URL, from both the host page (where the host typically
sits) and the watch page itself (so spectators can re-share to
people who showed up late).

## What changed

### Reused `ShareLink` instead of building a new control

[apps/web/src/components/share-link.tsx](../../apps/web/src/components/share-link.tsx)
already had exactly the shape we wanted: a button that opens a
small popover with the canonical URL, a "Copy" action with
"Copied ✓" feedback, native `navigator.share` fallback, and
quick-share links (SMS, WhatsApp, X, email). It takes a
`path` + `title` + `label`. Bundle is two two-line drop-ins,
not a new component.

### Host bracket page

[apps/web/src/app/events/[id]/bracket/page.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/page.tsx)
— header now renders the existing "Open public spectator view
→" link **and** a `<ShareLink path="…/bracket/watch" label="Share spectator link" />`
side by side, wrapped in a `flex flex-wrap gap-3` row so they
stack on narrow viewports.

### Watch page

[apps/web/src/app/events/[id]/bracket/watch/page.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/watch/page.tsx)
— added the same `<ShareLink />` under the "Updates
automatically" line, labelled "Share this view". A spectator
who's already on the page can hand the URL to a friend without
fishing in the address bar.

Both surfaces share the same `title` (`Live bracket — {event.title}`)
so the native share sheet / SMS preview is consistent.

## Patterns observed

- **Check `src/components/` before writing a new client
  component.** `ShareLink` already covered the copy + native
  share + quick-share matrix; the work was wiring it in, not
  rewriting it. Worth grepping for `clipboard|writeText|navigator\.share`
  before reaching for `useState('idle' | 'copied')` yet again.
- **The "path + origin at mount" trick avoids hydration
  mismatches.** `ShareLink` computes the absolute URL from
  `window.location.origin + path` only after `useIsMounted()`
  resolves, falling back to the relative path on the server.
  Cleaner than passing `process.env.NEXT_PUBLIC_SITE_URL` down
  every caller — the component owns its own absolute-URL
  derivation.

## Follow-ups deferred

- **QR-code modal.** At the gym, "scan this on the projector"
  is faster than "type the URL." A second action in the share
  popover (or a dedicated `<ShareQR />` sibling) that renders a
  client-side QR for the same URL would slot in next to "Copy"
  and "Share via system…"
- **Per-division share URLs.** Today both buttons share the
  base `…/bracket/watch` URL — the recipient lands on division
  1 even if the host was looking at division 3. Plumbing the
  current `?division=…` param into the share `path` is a
  one-liner once we decide the UX (always default to division
  1 for "broadcast" sharing? or share what you see?).
- **Inline OG metadata.** The native share sheet on iOS pulls
  Open Graph tags; the watch route doesn't export `generateMetadata`
  yet, so the share preview is generic. Pairs naturally with
  the deferred "bracket OG image" item.
