# 2026-05-22 — Bundle 36: monitoring doc

## Context

After Bundle 35 closed the api-reference P2, three P2 docs items
remained: monitoring, JSDoc backfill, DB-ops. Monitoring is the
highest-signal of the three — there was no single document anyone
could open during an incident to answer "where do I look?". The
configuration itself is already in good shape (three-runtime Sentry
SDK split with deliberate noise filtering, a `log` wrapper that
threads through Sentry breadcrumbs / exceptions, Vercel cron tab,
SQL-probeable outbox + webhook tables) — Bundle 36 is consolidation,
not new infrastructure.

JSDoc and DB-ops stay open after this bundle. JSDoc needs the
bracket-generators P1 reclassification from the architecture audit
first (per the finding's own "Fix" note), and DB-ops is a multi-page
write that's better scoped on its own.

## Pattern notes (worth keeping in mind)

- **Cross-runtime env-var asymmetry.** `VERCEL_ENV` reads the server
  variable; the browser SDK has to use `NEXT_PUBLIC_VERCEL_ENV` (the
  non-prefixed name doesn't survive the client bundle). Both are
  preset by Vercel, so this is implicit knowledge worth surfacing if
  anyone ever tries to fork the SDK config.
- **Noise filtering is product-aware.** Dropping `DomainError`
  subclasses isn't a bypass — those are mapped to 4xx in
  [api-helpers.ts](../../apps/web/src/lib/api-helpers.ts) and
  represent user input, not server bugs. Worth documenting so the
  next person who sees the `ignoreErrors` list doesn't widen it
  thoughtlessly.
- **The `log` helper is the contract.** Calling
  `console.error` + `Sentry.captureException` separately works in dev
  but loses the serverless flush. Doc points people to the helper
  rather than the underlying SDK calls.
