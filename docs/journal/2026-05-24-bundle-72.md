# Bundle 72 — 2026-05-24 — Off-platform UX: hide rosters, warn on external links

## Context

Two related off-platform tournament UX papercuts surfaced while a host
was setting up a tournament listing that links out to a third-party
registration system:

1. **Roster / attendee panels showed empty state for off-platform
   events.** When `events.payments_off_platform = true`, we have no
   ticket rows, no team-registration rows, and no insight into who
   actually signed up at the upstream system — but the page still
   rendered "Attendees", "Teams registered", and the public "Registered
   teams" list, all permanently blank. Looked broken; implied users
   that we knew the roster when we didn't.
2. **External links opened blind.** The hero CTA, sticky CTA, social
   links, and community-listing "Open on …" button all hard-linked to
   user-supplied URLs with no interstitial. Users had no warning they
   were leaving pickupvb.com, and we had no way to mark untrusted
   destinations as off-platform. A malicious or just confusing URL in
   a host-supplied field would surface as "click this from
   pickupvb.com → land on anywhere.tld" with zero friction.

## Decision

### Hide rosters when `payments_off_platform`

Treat the off-platform flag as the single switch — we don't have the
data, don't render the section. Three guards:

- `AttendeesPanel` — early-return `null` after the existing
  open-play guard.
- `TeamsRegisteredSection` on the event detail page — wrap the JSX
  block with `event.type === 'tournament' && !event.paymentsOffPlatform`.
- `AdHocTeamSignupPanel` public "Registered" list — wrap the inline
  public listing with `!paymentsOffPlatform`. The captain's own
  "Your teams" block stays unconditional so a captain who _did_
  register on-platform (rare edge for partially-migrated events)
  still sees their own state.

Rejected: a banner that says "rosters managed off-platform." Too
chatty for what is effectively "this section doesn't apply" — and the
external CTA already tells the user where the real registration lives.

### External-link interstitial

Wrap every user-supplied outbound link in a `/leaving?url=…`
confirmation page unless the destination is on a trusted allowlist.

- New `apps/web/src/lib/external-link.ts` exports
  `TRUSTED_HOSTS` (pickupvb.com, localhost, stripe.com, supabase.co,
  instagram.com, facebook.com, twitter.com, x.com, tiktok.com,
  youtube.com, youtu.be), `isTrustedExternalUrl(href)`, and
  `externalLinkHref(href)`. Hosts match exactly or as
  `*.<trusted>` subdomains.
- New `apps/web/src/app/leaving/page.tsx` — server component, `robots:
{ index: false, follow: false }`. Awaits `searchParams`
  (Next 16 promise shape), parses with `new URL()`, redirects through
  if the destination is trusted (catches hand-typed URLs that bypass
  the helper), renders a "Bad link" page for unparseable / non-http(s)
  input, and otherwise renders the interstitial with host + full URL
  display, **Continue** (`<a rel="noopener noreferrer nofollow
external">`) and **Cancel** (`Link href="/"`).
- Wire-up at four call sites: `event-sticky-cta.tsx`,
  `event-hero.tsx`, `social-links.tsx`,
  `community/[slug]/page.tsx`. Each wraps `href={…}` →
  `href={externalLinkHref(…)}` and tightens `rel="noreferrer"` to
  `rel="noopener noreferrer"` where missing.

Rejected:

- Allow-listing per-event ("host marks this URL as trusted"). Adds a
  per-host admin surface for marginal value — the interstitial is
  cheap and explicit. Revisit if hosts complain.
- Confirming _every_ external link including socials. Social handle
  destinations are already implicit ("Open Instagram"), so the
  allowlist covers them. Only unknown / host-supplied URLs go
  through the warning.
- Routing the redirect through a server action / API route. The
  interstitial _is_ the friction; a one-step redirect would defeat
  the purpose.

### `redirect()` + `typedRoutes`

`redirect(externalUrl)` is fine at runtime but Next 16 typed-routes
narrows the parameter to `RouteImpl<string>`. Cast through `Route` at
the trusted-passthrough call site with a comment explaining why —
this is the documented escape hatch for genuinely external
destinations.

## Changes

### Off-platform roster hiding

- `apps/web/src/app/events/[id]/_components/attendees-panel.tsx` —
  early-return after the `event.type !== 'open_play'` guard when
  `event.paymentsOffPlatform`.
- `apps/web/src/app/events/[id]/page.tsx` — `<TeamsRegisteredSection>`
  rendered only when `event.type === 'tournament' &&
!event.paymentsOffPlatform`.
- `apps/web/src/app/events/[id]/_components/ad-hoc-team-signup-panel.tsx` —
  public "Registered" block wrapped with `!paymentsOffPlatform`.

### External-link interstitial

- `apps/web/src/lib/external-link.ts` (new) — allowlist + helpers.
- `apps/web/src/app/leaving/page.tsx` (new) — interstitial page.
- `apps/web/src/app/events/[id]/_components/event-sticky-cta.tsx` —
  wraps external CTA href; rel hardened.
- `apps/web/src/app/events/[id]/_components/event-hero.tsx` — same.
- `apps/web/src/components/social-links.tsx` — wraps each social
  item's href.
- `apps/web/src/app/community/[slug]/page.tsx` — wraps the
  external listing's "Open on …" href.

## Verification

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` — all green.
(One iteration: initial build failed on `redirect(string)` under
`typedRoutes: true`; fixed by casting to `Route` with a comment.)

## Follow-ups

- Audit other external-link surfaces we haven't wrapped yet (e.g.
  group page website link, future event detail location-link fields).
  Search for `target="_blank"` to enumerate. Not urgent — the four
  current sites cover host-supplied URLs that flow from event
  creation, the most likely vector.
- Consider promoting `externalLinkHref` into a `<ExternalLink>`
  component if more call sites appear, so the `rel`/`target`
  defaults can't drift.
- The trusted-host list is small and editable — if support sees
  recurring "we're sending users through a warning for our partner
  X" tickets, add the partner host to `TRUSTED_HOSTS`.
- Roster-hiding is currently boolean on `payments_off_platform`. If
  we eventually offer a hybrid mode (off-platform tickets but
  on-platform teams, or vice versa), revisit each guard
  individually.
