## Scope

Three independent one-file changes, each tied to an open audit finding:

1. **P2 #9 — Stripe webhook dedupe via `upsert`.**
   [apps/web/src/app/api/webhooks/stripe/route.ts](../../apps/web/src/app/api/webhooks/stripe/route.ts).
   Swapped the `insert` + `catch ('23505')` pattern for
   `upsert({ id, event_type }, { onConflict: 'id', ignoreDuplicates: true })
  .select('id')`. PostgREST returns `[]` on conflict and the inserted
   row(s) on first sight, so emptiness is the dedupe signal; the noisy
   exception path is gone.

2. **P2 #10 — Photon timeout.**
   [apps/web/src/app/api/geocode/autocomplete/route.ts](../../apps/web/src/app/api/geocode/autocomplete/route.ts).
   Added `signal: AbortSignal.timeout(1500)` to the Photon fetch.
   `TimeoutError` is swallowed by the existing `try { ... } catch { return
null; }`, and the GET handler already falls through to
   `fetchNominatim()` when Photon returns null. No new code paths.

3. **P3 #11 — OG image `Cache-Control`.**
   [apps/web/src/lib/og-image.tsx](../../apps/web/src/lib/og-image.tsx).
   Shared `brandOgImage()` helper now passes
   `{ ...OG_SIZE, headers: { 'Cache-Control': OG_CACHE_CONTROL } }`
   as the second arg to `new ImageResponse(...)`. All four
   `opengraph-image.tsx` routes (events / players / teams / groups) go
   through the helper, so they all inherit the header without a per-route
   change.

## Decisions

- **`upsert + .select() + length check` over `select('id', { count: 'exact' })`.**
  `count: 'exact'` would require a separate select after the upsert and
  doesn't actually tell us whether _this_ call did the insert. The
  empty-array-on-`ignoreDuplicates` semantic is the supported PostgREST
  contract for this exact use case.

- **1500 ms Photon timeout.** Autocomplete keystrokes target ~200 ms p50
  feedback. 1.5 s caps the worst case at "slow but tolerable," and is
  comfortably above Photon's normal response (~300–600 ms) so we don't
  prematurely abandon Photon results.

- **`stale-while-revalidate=86400` on OG images.** Real concern is the
  unfurler thundering-herd on share (Slack + Discord + Twitter all fetch
  in parallel) — that's a thundering miss on Supabase if uncached. SWR
  lets one stale fetch revalidate in the background while everyone else
  gets the cached image immediately; 24h staleness is fine for OG previews
  because the underlying event/group data rarely changes after the link is
  shared.

- **Headers set in shared helper, not per-route.** All four
  `opengraph-image.tsx` files already delegate to `brandOgImage()`. Adding
  the header in the helper means there is exactly one place to change
  cache policy; no chance of one route drifting.

## Patterns observed

- **`.upsert(…, { ignoreDuplicates: true }).select(col)` as a dedupe
  primitive** is cleaner than `insert` + `catch 23505`. Returned-row
  count is the "I did it" signal; no exception cost; works idempotently
  with retries. Worth reaching for next time a webhook / outbox / "first
  one wins" insert shows up.

- **`AbortSignal.timeout(ms)` + a fall-through `catch`** is the right
  shape for racing-providers / cancel-and-fallback fetches. No
  `Promise.race` plumbing, no manual `AbortController` lifecycle — the
  signal cleans itself up when the provider's already-existing catch
  returns null.

- **`ImageResponse`'s second arg accepts `headers`.** Documented in
  next/og as `ImageResponseOptions`. Easy to miss because most examples
  only pass `{ width, height }`.
