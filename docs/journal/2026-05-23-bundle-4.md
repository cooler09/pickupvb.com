# Bundle 4 — Roster-mode per-team captain checkout (2026-05-23)

## Context

[Bundle 3](2026-05-22-bundle-3.md) annotated the audit, shipped the
ADR 0007 §3 validation + editable `team_registration_mode`, and left a
detailed spec for the deferred Model P1: there was no Stripe path for a
roster-mode captain to pay the per-team fee on a tournament with a
`per_team`-priced division. Captains could register through `event_teams`,
but the platform never collected the entry fee — silent revenue gap.

This bundle ships that path end-to-end and closes the last open P1 on
[`docs/audits/registration-workflow.md`](../audits/registration-workflow.md).

## Scope

Single-feature bundle. No re-scoping vs. the journal-3 spec.

### Shipped

1. **`event_team_payments` sidecar table** —
   [`supabase/migrations/20260608000000_event_team_payments.sql`](../../supabase/migrations/20260608000000_event_team_payments.sql).
   Composite FK to `event_teams(event_id, team_id) on delete cascade`
   plus a unique constraint so each registered team has at most one
   payment row. RLS policies mirror `event_team_registrations`: public
   read, captain-only insert via `auth.uid()`, defensive update/delete
   for captain-or-host (most writes are service-role through the webhook
   and the server action anyway).

2. **`EventTeamPayment` aggregate** —
   [`packages/domain/src/events/event-team-payment.ts`](../../packages/domain/src/events/event-team-payment.ts)
   with the same `None → Pending → Paid (→ Refunded)` state machine as
   `EventTeamRegistration`, plus
   [`event-team-payment-repository.ts`](../../packages/domain/src/events/event-team-payment-repository.ts)
   port and the Supabase adapter
   [`supabase-event-team-payment-repository.ts`](../../packages/infrastructure/src/supabase-event-team-payment-repository.ts).
   Reuses `RegistrationPaymentStatus` so webhook plumbing stays symmetric.

3. **`startRosterTeamCheckout(eventId, teamId)` server action** —
   [`apps/web/src/app/events/[id]/roster-team-checkout-actions.ts`](../../apps/web/src/app/events/[id]/roster-team-checkout-actions.ts).
   Sibling of `startTeamRegistrationCheckout`. Guards: tournament + roster
   mode + on-platform + per_team-priced + price > 0 + captain ownership +
   team-registered-for-event. Find-or-create the payment row; if found
   `Pending` from a stale session, reset via `expireCheckout()` so the
   captain can start fresh without manual intervention.

4. **Stripe webhook branches** —
   [`apps/web/src/app/api/webhooks/stripe/route.ts`](../../apps/web/src/app/api/webhooks/stripe/route.ts).
   Extended `CheckoutMetadata` with `'roster_team_payment'` kind + the
   `team_id` / `payment_id` fields, added paid / expired / refund
   handlers that mediate through the aggregate (idempotent on
   double-fire, swallows `InvariantViolation` on already-terminal state).

5. **Success / cancel routes** —
   [`apps/web/src/app/events/[id]/roster-team-checkout/success/route.ts`](../../apps/web/src/app/events/[id]/roster-team-checkout/success/route.ts)
   reconciles synchronously to cover the redirect-vs-webhook race (same
   pattern as the ad-hoc route);
   [`cancel/route.ts`](../../apps/web/src/app/events/[id]/roster-team-checkout/cancel/route.ts)
   just bounces home with `?rsvp=team_cancelled`. Kept as parallel routes
   instead of branching the existing ad-hoc routes — the kind check is
   already `meta.kind !== 'team_registration'`, branching would just
   smuggle two flows into one URL surface for no clarity win.

6. **Read model + UI** — added `divisionId` and `payment` fields to
   [`TeamLite`](../../packages/domain/src/events/event-repository.ts),
   parallel-fetched the payment rows in
   [`SupabaseEventRepository`](../../packages/infrastructure/src/supabase-event-repository.ts),
   and threaded everything through
   [`TournamentSignupPanel`](../../apps/web/src/app/events/[id]/_components/tournament-signup-panel.tsx)
   so the captain sees a `Pay — $X` button (or `Resume checkout` when
   `Pending`) inline with their team row. Status pills (`· Paid`,
   `· Payment pending`, `· Refunded`) surface state to all viewers.

7. **Tests** —
   [`event-team-payment.test.ts`](../../packages/domain/src/events/event-team-payment.test.ts)
   exercises all state-machine transitions, the invariant guards on
   `markPaid` (negative / non-integer amounts), and the
   Refunded-is-terminal property.

## Decisions revisited from Bundle 3

- **Sidecar table vs. extending `EventTeamRegistration`** — held the line
  on the sidecar choice (journal-3 Decision 3). The persistent team's
  own roster lives in `team_members`, not in this aggregate, so the
  ad-hoc registration aggregate's `RegistrationMember` collection would
  be dead weight here. Two small aggregates beat one fat one with a
  `source_team_id` discriminator.

- **Parallel success/cancel routes vs. branching** — chose parallel.
  Adds two ~20-line files but keeps the metadata-kind check tight and
  avoids a stringly-typed `if (meta.kind === 'team_registration') … else
if (meta.kind === 'roster_team_payment') …` ladder in two HTTP routes.

## Patterns observed

- **The `[id]` glob trap.** `file_search` and `grep_search` silently
  filter bracketed paths under VS Code's exclude rules — every search
  in this bundle that targeted `apps/web/src/app/events/[id]/…` returned
  zero matches. Workaround is `run_in_terminal grep -rn` (with the
  brackets escaped). Same observation as Bundle 3; promoted to AGENTS.md
  worth considering if it bites again.

- **Enum naming drift.** `TeamRegistrationMode.Roster` (not
  `RosterTeams` — the spec drafted the wrong identifier). One-line fix
  but a reminder to grep the enum source before authoring guard
  conditions.

- **Migration → types regen → typecheck.** The order matters: writing
  the action against `event_team_payments` before regenerating the
  Supabase types would have produced misleading typecheck errors. The
  pattern this bundle followed (`pnpm db:migrate` → `pnpm --filter
@pickupvb/supabase gen:types` → write code → `pnpm typecheck`) is the
  one to keep.

## Follow-ups deferred

- **Captain notifications.** Successful payment fires
  `notify('payment.refunded', …)` for attendees on refund, but the
  parallel `'team_payment.paid'` / `'team_payment.refunded'` notifier
  channels don't exist. Worth adding once we have a second consumer.

- **Refund button for hosts.** The aggregate supports `markRefunded()`
  driven by the Stripe webhook (manual dashboard refund), but there's
  no in-app button for the host. Same story as
  `EventTeamRegistration` — both can ship in the same bundle later.

- **Co-host can-pay-on-behalf-of-captain.** Out of scope here; captains
  are the only ones who can initiate per-team checkout. ADR 0007 doesn't
  speak to this explicitly so it would need its own design pass.

- **`amount_paid_cents` reconciliation when Stripe sends partial
  refunds.** Charge.refunded fires with `amount_refunded` but the
  aggregate currently flips straight to `Refunded` regardless of
  partial-vs-full. Audit follow-up if/when partial refunds become a
  real feature.
