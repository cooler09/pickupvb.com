## What shipped

**[.github/ISSUE_TEMPLATE/feature-request.yml](../../.github/ISSUE_TEMPLATE/feature-request.yml).**
GitHub issue-form schema, matching the existing
[bug-report.yml](../../.github/ISSUE_TEMPLATE/bug-report.yml) shape:

- **Problem-first framing.** First textarea asks for the problem,
  not the solution — keeps proposals grounded in a real scenario.
- **Required problem + product surface.** The two fields that
  determine triagability are required; everything else (proposed
  solution, alternatives, who-benefits, extras) is optional.
- **Product-surface dropdown** mirrors the app's top-level sections
  (events / tournaments / groups / profile-billing / notifications /
  search / marketing). Labels routing happens via the issue form's
  built-in `labels:` line (`enhancement`) plus the dropdown choice
  for downstream filtering.
- **No screenshot field by default** — covered by "Anything else?".
  Most feature requests don't have screenshots to attach.

**[.github/CODEOWNERS](../../.github/CODEOWNERS).** Minimal
catch-all routing every path to `@cooler09`:

```
* @cooler09
```

With a header comment that:

1. Acknowledges this is a solo-maintained project so the catch-all
   is intentional.
2. Documents the **narrowing strategy** for when additional regular
   contributors land (domain experts on `packages/domain/`, infra
   folks on `supabase/migrations/`). The point is to make the
   ownership boundary clear at the file rather than leaving the
   next maintainer to guess whether the catch-all is permanent or
   placeholder.

This wires GitHub's "automatic code-review assignment" surface
without pretending the project has finer ownership boundaries than
it actually does.

## Pattern notes

- **Audits drift quietly when out-of-band work lands.** The
  bug-report template + `config.yml` were already in the tree but
  the audit's status table and "Still open" list still said
  "❌ missing" / "only PR template shipped". Bundle 38 is partly a
  reconciliation: the actual state of the repo + a Bundle 38 entry
  that calls out the prior landing as out-of-band. Same shape as
  Bundle 34's "no tests exist" reconciliation. Worth checking the
  tree state before assuming an audit row is current.
- **CODEOWNERS for solo projects is a wiring/intent decision, not
  ownership.** The original audit's "Defer CODEOWNERS until there's
  a real owner map" advice would leave the GitHub review-assignment
  surface unwired indefinitely. A catch-all with a documented
  narrowing strategy is the better minimum — costs nothing to
  maintain, costs nothing to narrow later, and the header makes the
  intent legible.
- **Issue-form schema beats markdown.** GitHub's YAML form schema
  enforces required fields and produces structured input that's
  easier to triage than a markdown checklist that everyone can
  ignore. Keep new templates in this format.
