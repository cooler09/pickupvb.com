## What shipped

**[docs/onboarding.md](../onboarding.md)** — a thin overlay, not a
replacement for the existing setup docs. README already covers
prerequisites + install + local Supabase, and
[setup-dev-environment.md](../setup-dev-environment.md) covers
provisioning the `dev.pickupvb.com` staging environment from
scratch. The onboarding doc fills the gap between those two:

- **15-minute TL;DR** — clone → install → `pnpm supabase:start` →
  migrate + gen types → `pnpm dev` → verify quad. Single bash block
  so it can be copy-pasted.
- **Reading order, prioritised.** AGENTS.md first (the single most
  important file), then README, then the relevant per-package
  README. A "read when you hit it" table maps topic → doc for
  endpoints, domain rules, migrations, prod inspection, Stripe,
  staging, journal, audits.
- **Five-bullet mental model.** Hexagonal layering, typed
  `DomainError` subclasses, page composition under `_components/`,
  anonymous-auth claim guard, `revalidatePath()` after mutating
  actions. The bullets a new contributor needs in their head before
  they can review code.
- **First-PR walkthrough.** Branch off `develop`, match surrounding
  style, run the verify quad (`pnpm typecheck && pnpm lint &&
pnpm test && pnpm build`), add tests for domain/application work,
  follow the migration preamble standard, open the PR. Explicitly
  notes the agent will not commit or push.
- **Troubleshooting table.** Day-1 stuck states: Docker not running,
  `pnpm db:migrate` partway, missing Supabase types, `exactOptional`
  JSX traps, server-action 404s from raw `formData.get`, missing
  `revalidatePath`. Each row routes to the canonical fix doc.

## Pattern notes

- **Overlay, don't duplicate.** The temptation with onboarding docs
  is to restate the README, the integrations doc, and the runbook
  inline so the new contributor never has to leave the page. That
  creates a fourth source of truth that goes stale first. The
  onboarding doc is short by design and links out aggressively.
- **The verify quad is the gravitational centre.** Half of AGENTS.md
  rules are enforced by typecheck/lint/test/build. Putting the quad
  inside the TL;DR block, inside the first-PR walkthrough, and
  inside the "tests pass locally but CI fails" troubleshooting row
  is repetition that pays for itself.
- **Reading order matters more than completeness.** A new
  contributor who reads AGENTS.md + README + the domain README in
  that order has 80% of what they need. The "read when you hit it"
  table covers the remaining 20% on demand. Telling someone to
  "read the docs" without ordering them is a non-instruction.
