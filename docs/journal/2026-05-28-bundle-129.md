# Bundle 129 — M3 alignment tokens (2026-05-28)

## Context

Follows the [m3-alignment audit](../audits/m3-alignment.md) landed
earlier the same day, which evaluated adopting Material Design 3 in
response to repeated mobile-UX rework. Recommendation B + C: adopt M3
as a **design system** (tokens + principles) layered on Tailwind v4,
with Radix UI for the handful of widgets that justify a headless
primitive. Explicitly rejected a `@mui/material` swap (Emotion vs.
Tailwind collision, RSC regression, bundle weight, brand drift).

Bundle 129 is the first of the audit's 10-bundle sequence — the
**tokens** bundle, which the audit calls out as the prerequisite for
everything else and the only zero-component-change bundle in the plan.

## Decisions

### Build-time palette generation, ship pure CSS

[`scripts/gen-palette.ts`](../../scripts/gen-palette.ts) seeds an M3
tonal palette from the existing brand colors using
`@material/material-color-utilities` (Google's reference
implementation), then prints CSS variables that get pasted into
[`globals.css`](../../apps/web/src/app/globals.css). The package is a
devDependency only — zero runtime JavaScript ships.

Rejected:

- **Runtime palette generation** (compute tones on first render) —
  forces the M3 utilities into a client component, blocks SSR, and adds
  ~10 KB to every page for a value that never changes between deploys.
- **Build-time codegen via PostCSS plugin** — adds Tailwind / PostCSS
  build-graph dependency for a one-shot seed-color change that happens
  roughly never. The script approach makes regeneration a deliberate
  developer action and keeps the build pipeline minimal.
- **Hand-roll the M3 tone math** — the HCT color space + Google's tone
  algorithm is non-trivial and would diverge from the spec over time.
  Use the reference package.

### Preserve the legacy `--tw-color-*` block; expose M3 in parallel

The audit's plan called out that this bundle must change **zero
component visuals**. To honor that, the legacy brand-token block
(`--tw-color-background`, `--tw-color-primary`, `--tw-color-surface`,
etc.) is left exactly as before. The M3 role tokens
(`--md-sys-color-primary`, `-on-surface`, `-surface-container-*`, …)
land in a sibling block, and Tailwind 4's `@theme inline` exposes them
under a `md-` prefix so they're reachable as `bg-md-primary`,
`text-md-on-surface-variant`, `border-md-outline`, etc. without
shadowing any existing utility.

Rejected:

- **Re-alias `--tw-color-primary` → `var(--md-sys-color-primary)`** —
  would shift the visible primary teal from `#439093` to the M3 tone-40
  derivative `#0D696C` on every existing button, link, and badge
  app-wide as a side effect of this bundle. Even though the derived
  value is principled, doing this in a "tokens-only" bundle would
  violate the "zero visual change" contract and bury a visible
  regression in a foundation-laying PR. Call sites migrate
  opportunistically in later bundles by switching from `bg-primary` →
  `bg-md-primary` at the same time the surrounding component gets its
  state-layer and shape pass.
- **Drop legacy tokens immediately** — same reasoning, with the
  additional cost of forcing every component to migrate in one PR.

### Tailwind 4 token naming: `md-` color prefix, `shape-` radius prefix, `elevation-` shadow prefix, M3 type-role names verbatim

Trade-off: a longer name (`bg-md-primary-container` vs. `bg-primary`)
in exchange for collision-free coexistence with the legacy palette.
Worth it during the migration window; can be shortened in a future
bundle if the legacy palette is fully retired.

For shape, the `shape-` prefix avoids colliding with Tailwind's
default `rounded-sm` / `rounded-md` / `rounded-lg`, which are still
used in dozens of components. `rounded-shape-md` reads slightly
awkwardly but is unambiguous.

For type, the M3 role names (`text-display-lg`, `text-headline-md`,
`text-title-sm`, `text-body-lg`, `text-label-md`) carry semantic
meaning the Tailwind defaults don't — keeping them verbatim makes
audit findings translatable to spec citations.

For elevation, `shadow-elevation-1` through `-5` matches the M3 spec
exactly and reads clearly at call sites.

### Global `prefers-reduced-motion` reset

Added a global `@media (prefers-reduced-motion: reduce)` block that
defangs all CSS animations + transitions + smooth-scroll to ~0 ms.
Per-component motion that's functionally meaningful (e.g. the
`.match-flash` ring on bracket realtime updates) can opt back in with a
deliberate `@media (prefers-reduced-motion: no-preference)` block — the
existing `match-flash` rule keeps its reduced-motion fallback for now,
the new global rule just adds a belt-and-suspenders default for
everything else.

### `viewportFit: 'cover'` lands now, even though no component consumes safe-area yet

The `pt-safe`/`pb-safe`/`pl-safe`/`pr-safe` utilities only resolve to
non-zero values on iOS notch / Android gesture-bar devices when the
viewport meta has `viewport-fit=cover`. Next 16 wants this via
`export const viewport: Viewport`. Shipping the meta change in the
tokens bundle (rather than waiting for the eventual BottomNav / FAB
bundle that consumes it) keeps the utility a no-op on unsupported
devices today and a working utility tomorrow.

### `tsx` as devDep instead of `node --import tsx`

The palette script is a one-shot — `pnpm tsx scripts/gen-palette.ts`
is the simplest invocation. Adds 2 transitive packages but only to
devDependencies.

## Patterns observed

- **Tailwind 4's `@theme inline` is the right surface for design-system
  tokens** — it lets the value resolve at use-time (so `data-theme`
  swaps work) without runtime JS, and the same `--<bucket>-<name>`
  convention works for colors, sizes, radii, shadows, and font
  metrics. The `--text-<role>--line-height` and
  `--text-<role>--letter-spacing` sibling properties for compound
  font tokens are well-suited to the M3 type scale (each role bundles
  size + leading + tracking).
- **`@utility` shorthand for safe-area is preferable to `@layer
utilities`** — Tailwind 4's `@utility` is variant-aware, so
  `md:pb-safe` works automatically.
- **Separate the "vocabulary" half of a finding from the "call sites
  use it" half in the audit log.** This bundle ships the vocabulary
  for six findings; the per-finding header is "🟡 Tokens shipped"
  rather than "✅ Closed" so the audit accurately reflects state.

## Follow-ups deferred

- **Bundle 2 — touch targets.** Sweep every icon-only button to apply
  a new `tap-target` utility (`min-h-12 min-w-12`). Mechanical edit
  across ~20 files. Establishes 48 dp minimum across the app and adds
  a lint rule to prevent regression.
- **Bundle 3 — state layers + button vocabulary.** Refactor
  `primaryButtonClass()` to apply the M3 state-layer overlay using
  the `--md-sys-state-*-opacity` tokens that landed in this bundle;
  introduce `secondaryButtonClass`, `tonalButtonClass`,
  `textButtonClass` sharing the convention.
- **Bundle 4 — Radix Toast.** First widget swap. Drops in
  `@radix-ui/react-toast` styled with the M3 motion + color tokens.
- Eventual call-site migration sweep where `bg-primary` → `bg-md-primary`
  and the legacy `--tw-color-*` block is finally retired. Likely a
  separate bundle after the per-component passes finish (Bundles 5–9).
- **Lint rule** forbidding new `text-{n}xl` / new ad-hoc `shadow-*`
  / new ad-hoc `rounded-*` values once Bundles 2 + 3 + 7 land. Deferred
  to avoid blocking the migration window.
