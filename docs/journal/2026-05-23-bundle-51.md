change satisfies findings in more than one audit file, and the
remediation log in each file needs to record the closure.

## Pattern notes

- **Cross-audit linkage** is now a recurring pattern: Bundle 49 closed
  an architecture-audit P3 cluster, and the same code change satisfied
  a documentation-audit P2 that had been waiting on the same precondition.
  Each affected audit file gets its own remediation-log entry citing the
  bundle where the work actually shipped; don't try to consolidate
  cross-audit closures into a single edit.
- **`@throws` vs. prose JSDoc** — Bundle 49 used prose ("Throws
  `InvariantViolation` for …") which reads fine but doesn't render as a
  structured tag in TypeScript hover tooltips. The audit's explicit
  call for `@throws {Class}` annotations is more than style — VS Code
  surfaces the tag specifically, so it shows up at the call site, which
  is exactly where the information is needed. Worth using `@throws`
  consistently going forward; consider promoting this to AGENTS.md's
  Domain-errors section if a future bundle touches it.
- **Bookkeeping-with-code is fine** — Bundle 51 is small (two files
  touched) but the code change is real, not just chasing audit rows.
  The earlier "bookkeeping-only" Bundle 51 plan from the conversation
  summary was rejected because the audit's actual ask hadn't been
  satisfied yet; the bodies-without-tags Bundle 49 added closed the
  architecture P3 but not the documentation P2. Read what the audit
  asks for, not just whether something tangentially related shipped.
