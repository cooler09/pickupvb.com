# 2026-05-24 — Bundle 19: Architecture audit cleanup + teams page slug fix

## Context

Bundle 18's scoping pass surfaced two architecture-audit P2 findings
that were already resolved in the repository but still appeared "open"
in the prose at the top of [docs/audits/architecture.md](../audits/architecture.md):

1. "Server-action files missing `revalidatePath` after mutation" — six
   files flagged. Each was verified during Bundle 18 scoping and found
   to already use the correct pattern (read-only, delegated, or
   Stripe-redirect with documented webhook deferral).
2. "`profile/billing/actions.ts` throws bare `Error()`" — all 11 sites
   across `actions.ts` (4) + `pro/actions.ts` (7) actually throw
   `InvariantViolation` / `UnauthorizedError`. The remediation log
   already had a 2026-05-22 entry covering this but the inline finding
   wasn't updated.

Bundle 18 also worked around (rather than fixed) the teams page bug
where `team.slug` is referenced (`returnPath`, `ShareLink`) but isn't
in the SELECT projection. The breadcrumb URL temporarily used
`params.id` to dodge it. This bundle closes both gaps.

## Decisions

- **Cleanup over re-audit.** The findings weren't wrong when written —
  they were resolved later the same day. Refreshing the document keeps
  the next agent from re-investigating ghosts. Recorded as "Resolved
  2026-05-22" (the date the underlying fix shipped), not "2026-05-24"
  (today), so the timeline reads correctly.
- **Add `slug` to the SELECT rather than refactor the lookup.** The
  teams page already uses `.eq('slug', params.id)`, so `params.id` is
  semantically the slug; the bug is just that `slug` was omitted from
  the projected columns. Single-character fix to the column list
  un-breaks every existing `team.slug` reference (`returnPath`,
  `ShareLink`, our new breadcrumb URL).
- **Flip the breadcrumb back to `team.slug`.** With `slug` selected,
  using `team.slug` keeps the breadcrumb consistent with the rest of
  the page's URL construction (and with the events / groups /
  players pages that all use the typed row field, not `params.id`).
