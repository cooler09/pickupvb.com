## Changes

### 1. Teams suite — `ensureSearchableDisplayName` helper

[apps/web/tests/e2e/teams.authed.spec.ts](../../apps/web/tests/e2e/teams.authed.spec.ts)

Three teams tests (invite-accept, decline, broadcast) intermittently failed
because the UserPicker `ilike` search on `profiles_public.display_name` did
not reliably match the seeded attendee-b account (display_name was an
email-prefix that the ilike query was not finding).

Added an idempotent helper that visits `/profile` as attendee-b and ensures
the display_name starts with a known unique prefix (only writes if needed,
so it doesn't churn the DB across runs). All three call sites now resolve
the display_name through the helper before opening the picker.

Result: `teams.authed.spec.ts:147 | :274 | :389` all pass deterministically.

### 2. Profile edit display_name flake

[apps/web/tests/e2e/profile-edit.authed.spec.ts](../../apps/web/tests/e2e/profile-edit.authed.spec.ts)

The "edit display_name, save, reload, verify persisted" test waited only
on `networkidle` after save, which does not actually wait for the React
server-action round-trip to complete. Replacing that with a wait on the
in-page "Profile updated" success alert exposed a deeper problem: the
three `'profile form'` tests all submit the **same** `<form>` and
`updateProfile()` writes every field from the payload. Running them in
parallel under 2 workers caused a lost-update race — while the
display_name test was mid-save, the home_city test would submit with its
stale `defaultValue` snapshot of `display_name` and revert the write.

Fixed with `test.describe.configure({ mode: 'serial' })` on the profile
form describe block. The cross-field write semantics of `updateProfile()`
mean these tests cannot be parallelized.

### 3. New: events browse public filter coverage

[apps/web/tests/e2e/events-browse.public.spec.ts](../../apps/web/tests/e2e/events-browse.public.spec.ts)

Test plan §14.1 ("Event Browse and Filter") had no dedicated public-filter
test. The `/events` page is server-rendered from URL searchParams via a
`pick()` allow-list against `SURFACES` and `SKILLS`, so it's testable
without auth or mutations.

Five tests:

1. `/events` loads without auth + filter form is visible.
2. `?surface=indoor` → "Remove filter Indoor" chip is visible.
3. `?skillBand=intermediate` → "Remove filter Intermediate" chip is visible.
4. `?surface=indoor&skillBand=intermediate` → both chips + "Clear all" link.
5. Invalid values (`surface=NotARealSurface&skillBand=ZZ`) are silently
   dropped by `pick()` — page still loads, zero chips rendered.

Selector strategy: target the chip's `aria-label="Remove filter <label>"`
on the `Link` to avoid false matches with the `<option value="indoor">`
elements inside the filter `<select>`.

Card-counting was intentionally avoided — dev data is live and varies
across runs.

## Patterns observed

- **React server actions + `networkidle` is not a contract.** When a
  Playwright test mutates via a form, wait on a UI success indicator
  (alert, toast, redirected URL), not on `networkidle`. The server-action
  round-trip can complete after `networkidle` reports stable.
- **Forms that write every field can't be parallelized.** When a single
  form payload writes every column (not just the user-edited ones),
  every test that uses that form needs to be serial — otherwise concurrent
  tests stomp each other's writes via their stale `defaultValue`
  snapshots. Use `test.describe.configure({ mode: 'serial' })` on the
  describe block when the underlying action has wide write semantics.
- **`pick()` allow-list is case-sensitive.** The `/events` page accepts
  only lowercase surface/skill values; uppercase or invalid values are
  dropped silently. URL-driven tests must use the literal enum values
  from `event-filter-form.tsx` (SURFACES, SKILLS).
- **Chip selectors should target `aria-label`, not visible text.**
  Filter-strip chips share label text with `<option>` entries in the
  filter form, so `getByText(/indoor/i)` matches both. The chip's
  `aria-label="Remove filter X"` is unique.
- **Idempotent test-data helpers avoid DB churn.** When a test needs the
  test user to have a particular display_name (or any specific row state),
  check first and skip the write when already in the desired state.

### Deferred (with rationale)

- **Community rate-limit test** (`community.authed.spec.ts:127`,
  `RateLimitError('You can submit at most 5 listings per 24 hours.')`).
  Triggering the limit would create 5 throwaway listings and lock
  attendee-a out of community posting for 24h, breaking CI re-runs.
  Needs a dedicated rate-limit test profile/account before it can be
  enabled.
- **Admin claim-approval flow** (`admin.authed.spec.ts:170`). Requires
  setting up a city+day-matched listing/event fixture spanning attendee-a,
  attendee-b, and admin accounts — complex multi-actor fixture not worth
  building until claim flow lands in the test plan as a priority surface.

### Patterns surfaced

- **Always probe `/profile`-style fast endpoints before scanning index
  pages.** A 10-iteration `goto + networkidle` walk against dev easily
  blows a 90s test timeout. The `/profile`-based `findOwnedGroupUrl`
  helper is single-page-load and reusable.
- **Coverage-pointer comments beat live `test.fixme` for duplicates.**
  When a fixme exists because the same test was implemented in a sibling
  spec, replace the fixme with a comment that names the spec/test. This
  prevents the next audit from re-flagging "fixme present" without
  reopening the question of whether it should exist.

**Schema gotchas surfaced while writing this:**

- `tournament_brackets` flipped to per-division in
  [20260605000300_bracket_per_division.sql](../../supabase/migrations/20260605000300_bracket_per_division.sql);
  the old `event_id unique` constraint is gone and `division_id` is now
  NOT NULL. Any future bracket-seeding code must insert one bracket per
  division, not one per event.
- `events.short_code` lookups normalise to **upper case** in
  [packages/infrastructure/src/supabase-event-repository.ts:1155](../../packages/infrastructure/src/supabase-event-repository.ts#L1155).
  Stored codes must be uppercase or the `/e/<code>` redirect returns 404.
- `bracket_seeds` has `unique(bracket_id, seed)` — seeds are scoped per
  bracket (per division), so the same seed numbers can be reused across
  divisions without collision.
