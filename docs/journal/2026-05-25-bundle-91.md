## Changes

### 1. Teams suite — `ensureSearchableDisplayName` helper

[apps/web/tests/e2e/teams.authed.spec.ts](../../apps/web/tests/e2e/teams.authed.spec.ts)

Three teams tests (invite-accept, decline, broadcast) intermittently failed
because the UserPicker `ilike` search on `profiles_public.display_name` did
not reliably match the seeded attendee-b account (display_name was an
email-prefix that the ilike query was not finding).

Added an idempotent helper that visits `/profile` as attendee-b and ensures
the display_name starts with a known unique prefix (only writes if needed,
so it doesn't churn the DB across runs). All three call sites now resolve
the display_name through the helper before opening the picker.

Result: `teams.authed.spec.ts:147 | :274 | :389` all pass deterministically.

### 2. Profile edit display_name flake

[apps/web/tests/e2e/profile-edit.authed.spec.ts](../../apps/web/tests/e2e/profile-edit.authed.spec.ts)

The "edit display_name, save, reload, verify persisted" test waited only
on `networkidle` after save, which does not actually wait for the React
server-action round-trip to complete. When two workers raced (or a prior
failed run left stale data), the reload picked up a value that didn't
match the just-filled `Date.now()` value.

Fixed by waiting on the in-page "Profile updated" success alert
(rendered by [profile-form.tsx](../../apps/web/src/app/profile/profile-form.tsx)
line 304) before reloading, and applied the same wait to the cleanup save.

### 3. New: events browse public filter coverage

[apps/web/tests/e2e/events-browse.public.spec.ts](../../apps/web/tests/e2e/events-browse.public.spec.ts)

Test plan §14.1 ("Event Browse and Filter") had no dedicated public-filter
test. The `/events` page is server-rendered from URL searchParams via a
`pick()` allow-list against `SURFACES` and `SKILLS`, so it's testable
without auth or mutations.

Five tests:

1. `/events` loads without auth + filter form is visible.
2. `?surface=indoor` → "Remove filter Indoor" chip is visible.
3. `?skillBand=intermediate` → "Remove filter Intermediate" chip is visible.
4. `?surface=indoor&skillBand=intermediate` → both chips + "Clear all" link.
5. Invalid values (`surface=NotARealSurface&skillBand=ZZ`) are silently
   dropped by `pick()` — page still loads, zero chips rendered.

Selector strategy: target the chip's `aria-label="Remove filter <label>"`
on the `Link` to avoid false matches with the `<option value="indoor">`
elements inside the filter `<select>`.

Card-counting was intentionally avoided — dev data is live and varies
across runs.

## Patterns observed

- **React server actions + `networkidle` is not a contract.** When a
  Playwright test mutates via a form, wait on a UI success indicator
  (alert, toast, redirected URL), not on `networkidle`. The server-action
  round-trip can complete after `networkidle` reports stable.
- **`pick()` allow-list is case-sensitive.** The `/events` page accepts
  only lowercase surface/skill values; uppercase or invalid values are
  dropped silently. URL-driven tests must use the literal enum values
  from `event-filter-form.tsx` (SURFACES, SKILLS).
- **Chip selectors should target `aria-label`, not visible text.**
  Filter-strip chips share label text with `<option>` entries in the
  filter form, so `getByText(/indoor/i)` matches both. The chip's
  `aria-label="Remove filter X"` is unique.
- **Idempotent test-data helpers avoid DB churn.** When a test needs the
  test user to have a particular display_name (or any specific row state),
  check first and skip the write when already in the desired state.
