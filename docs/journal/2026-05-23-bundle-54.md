# 2026-05-23 — Bundle 54: SEO P3 closures + www → apex permanent redirect

## Context

Continuing the SEO audit cleanup that Bundles 18, 20, and 21 started. Two
P3 items had been deferred at "discussion-level" status: the `og:type`
choice on event pages, and slug-based event URLs. Both needed a recorded
decision so they'd stop resurfacing in audit scans. Separately, the SEO
audit's Open questions list flagged the `www` → apex redirect status code
as unverified — worth a `curl` before re-auditing.

## What shipped

### 1. `www → apex` redirect: 307 → 308 (real fix)

`curl -I https://www.pickupvb.com/events` returned `HTTP/2 307` with
`location: https://pickupvb.com/events`. That's Vercel's default
www-redirect behaviour, and it's wrong for SEO: 307 is _temporary_, so
search engines treat the apex as a different URL, don't consolidate link
equity, and don't update SERP canonicals.

Fix lives in [apps/web/next.config.mjs](../../apps/web/next.config.mjs):
a `redirects()` rule with `permanent: true` matching
`host: www.pickupvb.com`. Next emits **308 Permanent (method-preserving)**
when `permanent: true`. Because the rule lives in the framework config,
it shadows Vercel's default redirect — no dashboard change needed, and
the behaviour is reviewable in source.

I considered 301 (the older permanent status) but 308 is the modern
correct choice: it preserves the request method on redirect (so a POST
to `www` won't get silently converted to a GET) and is treated identically
to 301 by every major search engine.

### 2. P3 `og:type = 'website'` on event pages → ✅ Wontfix

Flipped the finding header in [docs/audits/seo.md](../audits/seo.md) to
Closed (Wontfix) with the rationale: `'event'` is not a standard
OpenGraph type, and `'website'` is the documented fallback for any URL
that isn't `article` / `video` / `music`. The authoritative rich-results
signal for events is the existing `SportsEvent` JSON-LD block in
[apps/web/src/app/events/\[id\]/\_components/event-jsonld.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/event-jsonld.tsx),
which Google's parser reads for `name`, `startDate`/`endDate`,
`eventStatus`, `location`, `organizer`, `offers`, `attendeeCapacity`.
OG `og:type` only governs social-share previews (Facebook/LinkedIn/Slack),
where `'website'` is correct.

### 3. P3 Slug-based event URLs → 🟡 Deferred (with rationale)

Documented in the Still-open section with the explicit cost: add a
`slug` column to `events`, accept `/events/[id-or-slug]` in the route
handler, and 301 old UUID URLs to slugs. Not worth the migration
without an observed problem. UUID URLs aren't SEO-penalized — they're
just less memorable. Leaving the finding visible (🟡, not ✅) so it can
be revisited if user feedback or analytics changes the calculus.

## Patterns surfaced

- **Default Vercel www-redirect ships as 307**, not 308 — at least on
  this project. Worth a `curl -I https://www.<domain>/...` check on any
  Next-on-Vercel deploy before assuming the redirect is SEO-correct.
  Cheapest fix is a `redirects()` rule with `permanent: true` in
  `next.config.mjs` — keeps the behaviour in source instead of a
  dashboard setting.
- **Wontfix is a valid closure state** for items that are technically
  flaggable but where the recommended change would be wrong. Recording
  the rationale (here: "OG `'event'` is non-standard; JSON-LD is the
  real signal") prevents the same finding from re-appearing in the next
  audit pass.
