# Bundle 126 — Pool play: per-pool courts (2026-05-27)

## Context

Bundle 124 shipped a bracket-wide `courtLabels` list + greedy slot
solver. Multi-pool tournaments often run on physically separate sets
of courts — Pool A on the east wall, Pool B on the west — and want the
schedule to reflect that. With the previous model every pool drew from
the same flat court list, so two pools sharing the bracket couldn't be
told "you run on different courts."

This bundle adds **per-pool court overrides** so hosts can:

- Give each pool a dedicated court list (disjoint sets → pools run
  fully in parallel, total slot count drops).
- Mix shared and pool-specific courts (the solver only refuses to
  double-book a court inside the same slot).
- Opt a pool out of court scheduling entirely by mapping it to `[]`.

## Decision

- **`BracketConfig.courtsByPool: Readonly<Record<string,
ReadonlyArray<string>>>`** (default `{}`). Keys are pool labels
  (`'A'`, `'B'`, …); values are court lists used in place of the
  bracket-wide `courtLabels` for matches in that pool. Stored on the
  existing JSON config column — no migration. Pools missing from the
  map fall back to `courtLabels`; explicitly-empty entries skip
  scheduling for that pool.
- **`assignCourtsAndSlots` reworked** to track _which courts_ are in
  use per slot (not just `slot.size`). Each match's allowed courts
  come from `courtsByPool[m.pool] ?? courtLabels`; the solver picks
  the lowest slot whose used-courts set doesn't already contain a
  free option from the allowed list **and** has no team conflict.
  Backwards-compatible when `courtsByPool` is empty — the per-court
  set is functionally equivalent to the old "next free index" logic.
- **`generatePoolPlay` and `Bracket.reorderPoolMatches`** thread the
  new map through. The "has any courts configured?" gate now also
  considers non-empty per-pool lists.
- **Web form: `pool_courts_<LABEL>` fields.** The format picker has
  a "Use different courts per pool" checkbox that reveals one
  comma-separated input per pool letter. The server action collects
  any `pool_courts_*` form fields and assembles `courtsByPool`.
- **Five new domain tests** ([packages/domain/src/brackets/bracket.test.ts](../../packages/domain/src/brackets/bracket.test.ts)):
  defaults, accept-on-create, per-pool replacement, fallback to
  bracket-wide list, skip-on-empty, disjoint courts schedule in
  parallel (3 slots instead of 6), shared courts respect court-level
  uniqueness within a slot. Suite at 179 tests.

## Rejected alternatives

- **Per-pool config as a separate aggregate / table.** Way too heavy
  for a free-text label list. JSON on the existing config column is
  the right shape.
- **Validating that `courtsByPool` keys exist (i.e. `< poolCount`).**
  Soft-accept unknown keys instead. The host might pre-fill more
  pools than the current event has, and there's no harm — the solver
  simply never sees those keys.
- **Multi-select court chips per pool in the UI.** Comma-separated
  text matches the bracket-wide field's UX and stays plain HTML.
  Upgrade to chips when courts become first-class entities.

## Patterns surfaced

- **JSON-column config is the right home for "add an optional field"
  changes.** No migration; `{ ...DEFAULT_BRACKET_CONFIG, ...row.config }`
  in the repo loader gives new defaults to old rows for free.
- **Solver capacity that started as a count (`slot.size`) often needs
  to grow into a set when the resource gains identity.** Once courts
  could be allowed-or-not per match, "free court count" stopped being
  meaningful and "specific free courts" took over. Worth noticing
  early before tests over-specify the count semantics.
- **`formData.entries()` over a `name`-prefix scan** is the cleanest
  pattern for "N optional inputs of unknown count" without sending a
  hidden index. UI controls which prefixes get submitted.

## Verify

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` — all green.
Domain tests 179 (up from 174); application 17; web 50.

## Follow-ups

- A way to mark a pool as "no courts" in the UI (the action supports
  it via empty values, but the current form treats blank as "fall
  back," not "opt out"). Add an explicit "skip" toggle if hosts ask.
- Court availability over time (Court 1 free from 9-noon then needed
  for league play) — out of scope; would require a different schedule
  model entirely.
- Promote courts to a real entity once we want them shared across
  events (booking calendars, etc.). Today they're per-bracket free
  text and that's enough.
