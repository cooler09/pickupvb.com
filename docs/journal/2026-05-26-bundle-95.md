# 2026-05-26 — Bundle 95: e2e cheap-wins (unblock 5 fixmes)

## Goal

First slice of the e2e skip-triage backlog. The skipped Playwright
catalogue had a "cheap wins" cluster that needed no new infra: five
`test.fixme(...)` entries that only needed (a) the
`createFreeOpenPlayEvent` recipe already proven in
[apps/web/tests/e2e/event-host.authed.spec.ts](../../apps/web/tests/e2e/event-host.authed.spec.ts)'s
`beforeAll`, or (b) the persistent `E2ETFA` short-code fixture from
the dev tournament seed. This bundle implements all five and extracts
the create recipe into a shared helper so the next batch of skips
(team-signup variants, RSVP-as-team) can call it too.

Out of scope (deferred): anything needing Stripe Connect (paid event
create, ticket checkout, tip flow), broadcast/notification fixmes,
the magic-link auth flow, and Pro-only tournament create.

## Context

`apps/web/tests/e2e/event-host.authed.spec.ts` had the only working
event-creation recipe in the suite — packed inline in a 70-line
`beforeAll`. It encoded several non-obvious things (DateTimePicker
trigger selector vs hidden ISO input; address-disclosure collapse on
`#addressLine` fill; `?created=1` flash on success redirect; the
right `getByRole('button', /create event/i)` selector). Every other
spec that wanted to create an event was marked `test.fixme(...)`
rather than reimplement it.

## Changes

### 1. New shared helper

[apps/web/tests/e2e/\_helpers/event-create.ts](../../apps/web/tests/e2e/_helpers/event-create.ts)

- `pickFutureDateTime(page, name, hhmm)` — moves from event-host's
  inline helper into the shared module.
- `createFreeOpenPlayEvent(page, { title, hostGroupId?, ... })` —
  returns `{ url, id }`, throws with the visible form errors on
  failure so callers can surface them instead of silently skipping.
- `cancelEvent(page, eventUrl)` — best-effort two-step cancel via
  `/edit` for `afterAll`/`finally` cleanup.

### 2. Refactor `event-host.authed.spec.ts` `beforeAll`

The 70-line inline body now calls `createFreeOpenPlayEvent` +
`cancelEvent`. Behavior is unchanged — same selectors, same
diagnostic messages on failure, same `beforeAllError` surfacing.

### 3. `meta-seo.public.spec.ts` — two new tests

- **Short URL redirect** (`/e/E2ETFA`): uses
  `page.request.get(target, { maxRedirects: 0 })` to assert the raw
  308 + `Location: /events/<uuid>`. Skips gracefully if the seed
  isn't applied (production).
- **og:image content-type**: visits a real event detail page, reads
  the `og:image` meta, fetches it via `page.request.get`, asserts
  `200` + `Content-Type: image/*`. Skips if no events / no og:image.

The old "external social card validator" fixme is left in place — that
one really does need an external service.

### 4. `events.authed.spec.ts` + `event-create-extended.authed.spec.ts`

Both had a "create a free open-play event end-to-end" fixme. Now both
call the shared helper and clean up via `cancelEvent` in `finally`.

### 5. `event-host.authed.spec.ts` — sponsor panel test

Pro-only. Opens a `STORAGE_PATHS.proHost` context (mirrors the
billing-stripe.authed pattern), creates a disposable event as
pro-host, navigates to `/events/<id>/edit`, asserts the
`Sponsor slot (Pro)` heading from
[sponsor-panel.tsx](../../apps/web/src/app/events/[id]/edit/sponsor-panel.tsx)
is visible. Cleanup in `finally` runs regardless of assertion outcome.
Skips when the pro-host storage state is missing.

### 6. `groups-manage.authed.spec.ts` — host event as group

Opens `/events/new`, reads `#hostGroupId` option values; if the only
option is `''` ("Yourself"), the test user doesn't own/admin a
hostable group on this environment — skip per README group #7.
Otherwise creates an event with `hostGroupId` set to the first
group, then visits `/groups/<id>` and asserts the event title appears
under the "Upcoming events" heading. Cleanup via `cancelEvent`.

## Patterns surfaced

- `test.fixme(title)` with no body is the right "TODO test" pattern
  (the `(title, fn)` overload). Already documented in
  `/memories/repo/e2e-tests.md`; the bundle confirmed it works fine
  alongside real tests in the same describe.
- `page.request.get(url, { maxRedirects: 0 })` is the cleanest way
  to assert HTTP redirect status + Location without following.
  Promote this pattern if more redirect specs land.
