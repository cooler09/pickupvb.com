# 2026-05-24 — Bundle 79: Web-vitals → product-analytics bridge

## Context

Bundle 78 closed the marketable-surface P2. The next-cheapest item on
the analytics audit was P2 #8: web-vitals (LCP / CLS / INP / FCP /
TTFB) are captured by `@vercel/speed-insights` today but never reach
PostHog, so we can't correlate "slow LCP" with the conversion events
Bundle 76 wired (`checkout_started` / `checkout_completed`). Bridging
the metrics into the same vendor as the funnel events unlocks
"does slow-page → bail-on-checkout?" — and is also a down-payment on
P3 #12 (drop Speed Insights once PostHog has parity numbers).

## Decisions

- **Server beacon, not a client-side PostHog SDK.** PostHog only
  lives in the infrastructure adapter (`posthog-node`) — there is no
  browser SDK shipped. Keeping all capture behind the server-side
  port means the PII guardrail test in `analytics-port.test.ts`
  stays the single source of truth for what reaches the vendor. The
  beacon hop is `useReportWebVitals` → `navigator.sendBeacon` →
  `/api/web-vitals` → `analytics.capture(...)`.
- **`useReportWebVitals` from `next/web-vitals`, no `web-vitals` dep.**
  Next already ships the hook; pulling in the upstream package just
  for the same callback would be redundant.
- **`navigator.sendBeacon` with `fetch keepalive` fallback.** LCP
  and CLS often finalize on page unload, where a regular `fetch()`
  would be cancelled. `sendBeacon` is the standard primitive that
  survives. Fallback path uses `fetch` with `keepalive: true` for
  browsers (rare) that lack `sendBeacon`.
- **Mask route templates client-side.** `usePathname()` returns the
  resolved URL like `/events/abc-123`. PostHog rolling up by raw URL
  would explode into thousands of unique strings. A small masker
  collapses UUID-shaped and numeric segments to `[id]` so vitals
  bucket by template — matches the shape Next's own route map prints.
- **Anonymous capture by default.** The route resolves the viewer
  via `getViewer()` and only attaches an actor id when the user is
  signed in and NOT anonymous. Web vitals on a logged-out marketing
  page should still capture, just without a `distinctId`.
- **Zod-validate the payload allowlist.** The browser can POST
  arbitrary JSON; the route enforces an exact shape (`metric` enum,
  numeric `value` bounded `[0, 1e6]`, `route` matching `^\/[^?#]*$`,
  etc.) before anything reaches the analytics port. Bad payloads
  fail-quiet with a 204 — the endpoint should never look like a
  useful probe surface.
- **Don't drop Speed Insights yet.** P3 #12 retires `@vercel/speed-insights`
  once we've validated PostHog has comparable numbers. Running both
  for a parity window is intentional.
- **Filter automated browsers.** Mirror the existing `AnalyticsClient`
  guard (`navigator.webdriver`) so Playwright runs don't pollute the
  vitals.

## Patterns surfaced

- **`useReportWebVitals` + `sendBeacon` is the right shape for any
  unload-sensitive client telemetry.** No new dependency, survives
  navigation, fail-quiet by construction. Same pattern would work
  for "abandonment" capture (visibilitychange → beacon) if we ever
  need it.
- **Mask dynamic segments client-side before sending.** Cheap, keeps
  PostHog (and any other downstream) groupable, and avoids needing
  a per-page known-route registry.
- **Server-side analytics port + browser beacon endpoint is a clean
  alternative to a client-side vendor SDK.** Keeps the PII guardrail
  centralized, keeps third-party JS off the page (faster INP), and
  lets the consent banner (P2 #5) gate one endpoint instead of a
  vendor's auto-capture surface.

## Follow-ups deferred

- **P3 #12 — drop `@vercel/speed-insights`.** Wait a parity window

  when the time comes.
- **PostHog dashboards / insights for web vitals.** Out-of-band; no
  code change required. Wire a "vitals by route" insight and pair
  with the conversion funnel.
- **Server-side `web_vitals` for SSR-measured metrics.** Browsers
  give the canonical numbers; SSR-measured TTFB is in Vercel
  request logs already.
- **Consent banner gating (P2 #5).** When the banner ships, the
  beacon `fetch`/`sendBeacon` should be gated on the analytics
  toggle — one cookie check at the top of the hook callback.
