# Bundle 112 — Bracket: "Jump to latest match" affordance

## Why

A 24-team double-elim bracket renders 40+ cards across winners,
losers, and grand-final columns. On a phone the page is a long
vertical scroll; on the projector the host wants the live match
front and centre, not "scroll down past the round-1 outcomes
to find what's playing right now." The realtime refresher
already keeps the data fresh, but the cursor doesn't move —
the spectator has to hunt.

Goal for this bundle: a one-tap shortcut to the most relevant
match, with a visual ring on that card so it's obvious where
you landed. Reuse the same affordance on the host page so a
host running a tournament from their phone can re-orient
after a result entry.

## What changed

### `pickLatestMatchId` heuristic in `board-view.tsx`

**NEW** export from
[apps/web/src/app/events/[id]/bracket/\_components/board-view.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/board-view.tsx).
Pure function over `ReadonlyArray<Match>`; returns a string
match id (or `null` when the bracket has no eligible matches).
Priority:

1. **Live** — `status === 'in_progress'`, or any match with
   sets recorded that isn't completed. Tie-break by deepest
   round, highest matchNumber (the further into the bracket,
   the more consequential the game).
2. **Most recently completed** — same tie-break. Last finished
   match wins.
3. **Next up** — lowest-numbered pending match with both teams
   known. Useful right after the host generates a bracket but
   before any sets are entered.

Domain `Match` has no `updatedAt` column, so "latest" is
inferred from `status` + round/matchNumber rather than wall
time. That's fine — round depth is a better proxy for
"interesting" than recency anyway.

### `BoardView` accepts `highlightMatchId`

When set, the section renders a "Jump to latest →" anchor in
the header strip (next to the "In progress" / "Reset bracket"
controls), and the matching card gets a `ring-primary ring-2`
on its wrapper. The wrapper carries `id={`match-${m.id}`}` and
`scroll-mt-24` so anchor navigation lands the card below the
sticky header instead of flush against the viewport top. CSS
`scroll-smooth` on the surrounding `<section>` gives the
glide.

The same anchor wrapping is duplicated in `PoolsView` since it
renders its own `MatchCard` map outside `renderMatch`. Pool
matches participate in both the highlight ring and the anchor
target.

### Both bracket pages pass `highlightMatchId`

- [apps/web/src/app/events/[id]/bracket/page.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/page.tsx)
  — host workspace.
- [apps/web/src/app/events/[id]/bracket/watch/page.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/watch/page.tsx)
  — spectator view.

Both import `pickLatestMatchId` from `board-view` and pass the
result. `null` is fine — `BoardView` just doesn't render the
button or the ring.

## Patterns observed

- **Heuristic ranking belongs next to its consumer.**
  `pickLatestMatchId` is exported from `board-view` rather than
  hoisted to the domain layer because the ranking is a UX
  preference ("what should the spectator see first?"), not a
  business invariant. Domain doesn't need to know what "latest"
  means; that's a presentation concern. If a second consumer
  appears (e.g. an OG-image generator for share previews) the
  helper graduates — until then it lives where it's used.
- **`scroll-mt-*` is the cheap fix for fixed-header overlap.**
  Plain `<a href="#match-xxx">` would scroll the target flush to
  the viewport top, which is unreadable under any sticky chrome.
  `scroll-mt-24` adds 6rem of inset just to the anchor-target
  element, no JS, no layout shift.
- **Lint surprise:** `min-w-[220px]` now triggers a Tailwind
  "can be written as `min-w-55`" warning when the className is
  inside a template literal. The original `className="min-w-[220px]"`
  string-literal was silent. Once you wrap the class list to
  add a conditional ring, the same arbitrary value gets
  flagged. Worth knowing for the next time a previously-quiet
  arbitrary value lights up after a tiny refactor.

## Follow-ups deferred

- **Auto-scroll on realtime update.** Right now the spectator
  has to tap "Jump to latest" each time a new result lands.
  The `BracketRealtimeRefresher` could optionally re-anchor to
  the new latest match (or, less aggressively, flash the ring
  to draw the eye). Needs care for users who've manually
  scrolled away to look at a different match.
- **`?focus=match-xxx` deep-link.** Pair with the share-link
  bundle (111): a spectator wanting to send "this exact match"
  could share a URL that auto-scrolls and rings on load.
- **Better "live" detection.** Today an in-progress match is
  one with sets recorded but no winner. A bracket-side
  `started_at` would let us flag "started, no sets yet" as
  live too — useful for the "warmup just finished" window.
