# 2026-05-23 — Bundle 43: Combobox ARIA on address + user pickers

## Context

Two of the accessibility audit's remaining P2s targeted the same WAI-ARIA
combobox pattern on two typeahead controls — the address autocomplete on
event/community forms and the people-picker used for adding co-hosts,
friends, and team members. The audit's open-questions section had even
floated extracting a shared `Combobox` primitive, but with only two
consumers and one of them (`AddressAutocomplete`) already most of the way
there, the right move was to finish the pattern in place on both files
and revisit extraction the next time a third consumer appears.

## What shipped

**[user-picker.tsx](../../apps/web/src/components/user-picker.tsx) — full migration.**

The picker was missing every ARIA hook the pattern needs and relied on a
120 ms `setTimeout` after `onBlur` to close the dropdown — fragile,
swallowed keyboard activation, and broke for AT that synthesises focus
events. Changes:

- Added `role="combobox"`, `aria-expanded={open}`, `aria-controls={listboxId}`,
  `aria-autocomplete="list"` on the search input.
- Added `aria-activedescendant` via the spread pattern so it only renders
  when an option is highlighted (`exactOptionalPropertyTypes`-safe).
- Added an `activeIdx` state and an `onKeyDown` handler covering
  ArrowDown / ArrowUp / Enter / Escape. ArrowDown opens the list when
  closed-but-loaded; Enter commits the active option; Escape closes
  without committing.
- Replaced the blur timeout with a `containerRef` + document `mousedown`
  effect — mirrors the `AddressAutocomplete` and `DateTimePicker`
  pattern already in the tree.
- Promoted each option `<button>` to `role="option" id={optionId(idx)}
aria-selected={idx === activeIdx}`; the wrapping `<li>` gets
  `role="presentation"` so the listbox children are pure options.
- Moved the Searching… / No matches / count text into an
  `aria-live="polite"` sr-only `<p>` so screen readers announce result
  arrivals without polluting the listbox.

**[address-autocomplete.tsx](../../apps/web/src/components/address-autocomplete.tsx) — top-up.**

Most of the combobox shape was already in place (the audit was written
before that landed). Added the two missing pieces:

- `aria-activedescendant` on the input, again via the spread pattern,
  pointing at `address-suggestion-${idx}` when an option is active.
- An `aria-live="polite"` sr-only status region carrying the same
  Searching… / No matches / count text as the user picker — parity for
  AT users moving between the two controls on the same form.
- Each `<li role="option">` gets a stable id matching the active descendant.

## Pattern notes

- **Finish in place before extracting a shared primitive.** With only
  two consumers, a `<Combobox>` primitive would have meant designing an
  API around two known shapes and then forcing both into it. Doing the
  full pattern in `UserPicker` first surfaced the real seams — the
  `optionId(idx)` helper, the listbox-vs-status split, the
  spread-pattern `aria-activedescendant` — without committing to an
  API. If a third consumer shows up (a team-picker, an event-search
  typeahead, etc.) the extraction is now a refactor over three real
  implementations rather than a speculative design.
- **`aria-live` status belongs outside the listbox.** ARIA spec says
  listbox children should be options or groups. Stuffing
  "Searching…" / "No matches" as `<li>`s inside the listbox both
  pollutes the option count screen readers announce and prevents the
  status from being a live region. Moving them to a sibling `<p
aria-live="polite">` fixes both at once and keeps the visual layout
  almost identical (sr-only, so sighted users still see the inline
  placeholders inside the dropdown for the no-matches case — kept as
  a `role="presentation"` `<li>` so the visual treatment doesn't
  regress).
- **Spread pattern for `aria-activedescendant`.** With
  `exactOptionalPropertyTypes: true`, `aria-activedescendant={cond ?
id : undefined}` is a type error. The
  `{...(cond ? { 'aria-activedescendant': id } : {})}` shape is the
  repo-standard workaround and stays out of the DOM entirely when the
  condition is false, which is what AT expects (the attribute is
  meaningful only when an option is active).
- **`mousedown` on options beats input blur.** Even with the blur
  timeout gone, picking still uses `onMouseDown` (with
  `preventDefault`) rather than `onClick`. Without that, the input's
  focus loss would close the dropdown before the click landed. The
  document `mousedown` outside-click handler doesn't trigger here
  because the click target is inside `containerRef`.
