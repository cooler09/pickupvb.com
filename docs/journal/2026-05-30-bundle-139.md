# M3 adoption reality-check + value-preserving shape migration (2026-05-30)

## Context

User asked to "review the M3 alignment and see what items we still need to
implement" and to "reevaluate improvements to the strategy." A re-audit of
[docs/audits/m3-alignment.md](../audits/m3-alignment.md) against the actual
call sites surfaced the headline finding: the 10-bundle arc (129–138)
shipped every **primitive and token**, but **adoption stalled.** The app is
still ~95% on legacy ad-hoc styling. Measured counts in `apps/web/src`
(2026-05-30): 401 raw palette colors, 77 `text-Nxl` + 1181 `text-lg/sm/xs`,
132 ad-hoc hovers, 567 raw `rounded-*`, 53 `shadow-*`, 192 bare `<input>` —
against single-digit M3 adoption (12 `md-` roles, 39 type-roles, 12
`state-layer`, 7 `rounded-shape-*`, 3 `<TextField>`, FAB on 1 page).

The per-finding 🟡 headers conflated "primitive shipped" with "adopted
across app," hiding the gap behind a status that reads ~80% done.

## Decisions

- **Reframed the audit, didn't just keep migrating.** Added an
  [Adoption status](../audits/m3-alignment.md#adoption-status-2026-05-30)
  section that separates "primitive shipped" from "adopted," diagnoses
  _why_ opportunistic migration stalled (the compat aliases render
  identically → zero visual pressure to migrate; no lint guard → counts
  grow; 🟡 masks the split), and records a go-forward strategy. Chose this
  over silently shipping more migration bundles because the next agent
  needs to know the program is a _primitives_ success and an _adoption_
  backlog, not "80% done."
- **Value-preserving subset only for the shape codemod.** Chose to migrate
  only the _exact-pixel_ buckets over a full role-aware restyle. Tailwind
  v4 defaults make `rounded-lg/xl/2xl` (8/12/16 px) identical to
  `rounded-shape-sm/md/lg` — a `perl` sweep is genuinely zero-visual-change.
  Rejected codemodding `rounded-md` (406 sites): Tailwind's 6 px has **no**
  M3 token (`shape-sm` = 8, `shape-xs` = 4), and the right target is
  role-dependent (button → `sm`, input/card → `md`) — a blind sed both
  changes pixels and guesses roles. That's a feature-class judgment task,
  the same one the user declined for color.
- **No elevation codemod.** Rejected `shadow-sm → shadow-elevation-1` etc.:
  M3 elevation is a two-layer key+ambient shadow, visually distinct from
  Tailwind's single-layer presets, so a sweep is a deliberate restyle of
  every shadow, not a value-preserving move. Needs a visual-review bundle.
- **Ratchet behind migration, not ahead of it.** Chose to `error`-forbid
  only the now-eliminated `rounded-lg/xl/2xl`. A rule on a still-legacy
  category either breaks the build (`error` on 400+ live sites) or floods
  lint with ~900 `warn`s that bury the 3 real pre-existing warnings. So
  each finding earns its ratchet the moment its count hits zero — the rule
  _follows_ the migration. Rejected an `eslint-plugin`-style baseline file
  (none in the repo; not worth introducing for one ratchet).
- **Put the shape ratchet in `apps/web`'s own config, not
  `packages/config/eslint.base.mjs`.** apps/web has a standalone Next.js
  flat config that does **not** extend the base — the base only covers the
  pure library packages.

## Patterns observed

- **zsh doesn't word-split unquoted `$(...)`.** The first codemod attempt
  passed a newline-joined file list as `$files` to `perl`; zsh handed it to
  perl as one giant argv (`File name too long`), so the multi-file edit
  silently no-op'd while a separate single-file edit worked. Use
  `rg -l0 … | xargs -0` for multi-file sweeps in this repo's shell. Worth
  remembering for any future codemod bundle.
- **"Value-preserving codemod" is a per-class property, not a per-finding
  one.** Of 567 `rounded-*`, only 162 (lg/xl/2xl) are exact-pixel matches;
  the 406 `rounded-md` and all 53 shadows are not. Always break a
  "mechanical migration" down by class/pixel before promising it's safe.

  bundle; not a codemod. Extend the shape ratchet to `rounded-md` once it
  lands.
