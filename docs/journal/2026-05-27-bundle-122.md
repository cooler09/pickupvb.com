# Bundle 122 — Pool play configuration: bestOf + fixed-games schedule (Phase 1 of ADR 0018) (2026-05-27)

## Context

A host running a same-day pool-play tournament asked for more control
over the `pool_play_playoff` format: match length (best of 1 vs. 3),
a "games per team" cap so a 6-team pool doesn't run all 15 matches,
a designated work/ref team per match, and "no team in two places at
once" so the schedule never asks a team to play and ref on different
courts simultaneously.

[ADR 0018](../adr/0018-pool-play-configuration.md) records the full
design — four `BracketConfig` additions, a match-level `workTeamId`
and `court`, and a slot solver. This bundle ships **Phase 1 only**:
the match-length and schedule-density knobs that don't touch any
table shape. Work-team and courts/slots are Phase 2 / Phase 3 and
land later; the ADR captures both so the data shape stays consistent
across phases.

## Decision

- **`BracketConfig` gains `poolSchedule: 'round_robin' | 'fixed_games'`
  and `poolGamesPerTeam: number | null`.** Defaults preserve current
  behavior (`round_robin`, `null`). Stored as JSON on `brackets.config`
  — no migration needed.
- **`bestOf` validation tightens from "positive odd" to the explicit
  set `{1, 3, 5}`** via a new `ALLOWED_BEST_OF` export from
  [packages/domain/src/brackets/bracket.ts](../../packages/domain/src/brackets/bracket.ts).
  Rejects 7+ so the picker can't quietly diverge from the aggregate.
- **`generateRoundRobin` accepts an optional `maxRounds` cap** —
  truncates the circle-method rotation at N rounds, so each team
  plays exactly N opponents (no repeats). `generatePoolPlay` now
  takes an `options: { schedule, gamesPerTeam }` argument and routes
  `fixed_games` through the truncated path. Domain rejects
  `gamesPerTeam ≥ smallest pool size` so the host picks RR instead
  when they actually want a full schedule.
- **Format picker grows two new controls:** a "Match length" radio
  group ({1, 3, 5}) and, inside the pool-play fieldset, a "Schedule"
  radio (`round_robin` vs `fixed_games`) plus a "Games per team"
  number input that appears only in fixed-games mode. UI mirrors
  the domain guard so the submit button disables when
  `gamesPerTeam >= teamsPerPool`.
- **`createBracketFromForm` reads the new fields** and populates
  `BracketConfig` accordingly. `bestOf` is read for every format
  (not just pool play); the schedule fields are gated to
  `pool_play_playoff` and survive non-pool-play formats as hidden
  no-op inputs.

## Tests

New file [packages/domain/src/brackets/bracket.test.ts](../../packages/domain/src/brackets/bracket.test.ts):
21 cases covering `Bracket.create` validation (bestOf ∈ {1,3,5},
`fixed_games` requires positive `gamesPerTeam`), `generateRoundRobin`
truncation (cap honored, oversize cap clamped to full RR, per-team
opponent count), and `generatePoolPlay` schedule modes (full RR vs
fixed-games match counts, "no team appears twice in the same pool
round" property, and the "gamesPerTeam ≥ pool size" rejection).
Verify chain (`pnpm typecheck && pnpm lint && pnpm test && pnpm
build`) passes; domain test count: 152.

## Patterns surfaced

- **Additive `BracketConfig` extensions are cheap thanks to the
  JSON column.** `DEFAULT_BRACKET_CONFIG` + `{...DEFAULT, ...row.config}`
  in [packages/infrastructure/src/supabase-bracket-repository.ts](../../packages/infrastructure/src/supabase-bracket-repository.ts)
  meant old rows kept working with no backfill. Future Phase 2/3
  additions (`requireWorkTeam`, `courtLabels`) follow the same shape.
- **Mirroring domain validation in the picker is the friction-reducer
  that paid off.** The host sees the "gamesPerTeam must be less than
  smallest pool size" red text inline instead of submitting and
  bouncing off a `ValidationError` flash.

## Follow-ups deferred

- **Phase 1b — reorder UI.** Per the open-questions discussion the
  generator picks opponents and the host gets a drag-to-reorder view
  before the bracket transitions to `active`. Likely gated on
  `status === 'setup' && matches.length > 0` rather than a new
  `BracketStatus`.
- **Phase 2 — work/ref team.** `Match.workTeamId`; pool generator
  fills it with the idle team in the same pool's rotation, null when
  no idle team exists. Migration on `bracket_matches`.
- **Phase 3 — courts + slot solver.** `BracketConfig.courtLabels`
  (free-text array), `Match.court` and `Match.slot`, greedy
  graph-coloring solver. Conflict reported as `InvariantViolation`
  so [api-helpers.ts](../../apps/web/src/lib/api-helpers.ts) maps it.
