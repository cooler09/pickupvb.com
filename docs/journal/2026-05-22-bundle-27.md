# 2026-05-22 — Bundle 27: CSP enforcement

## Context

Bundle 15 (2026-05-24) added the full Content-Security-Policy header
behind `Content-Security-Policy-Report-Only` to soak the allowlist
without risking production breakage. The directives cover Cloudflare
Turnstile (script + iframe), Supabase REST + Realtime (https + wss),
OSM tiles, and the inline-script / inline-style escape hatches needed
by JSON-LD and Tailwind. Sentry traffic is already same-origin via
the `tunnelRoute: '/monitoring'` config, so no `*.ingest.sentry.io`
entry was needed. See the
[Bundle 15 journal](2026-05-24-bundle-15.md) for the policy
inventory.

The soak window produced no real violations against the existing
allowlist, so the follow-up tracked as **P2 #3a** in
[docs/audits/security.md](../audits/security.md) is now safe to ship.

## What shipped

One-line swap in [apps/web/next.config.mjs](../../apps/web/next.config.mjs):

```diff
-          { key: 'Content-Security-Policy-Report-Only', value: csp },
+          { key: 'Content-Security-Policy', value: csp },
```

Inline policy-rationale comment refreshed to describe enforcement mode
and re-point the nonce follow-up at the new **P2 #3b** entry. Policy
content unchanged.

## Tradeoffs accepted

- **`'unsafe-inline'` still on `script-src` and `style-src`.** JSON-LD
  emits `<script type="application/ld+json">` from
  [layout.tsx](../../apps/web/src/app/layout.tsx) and
  [event-jsonld.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/event-jsonld.tsx),
  and Tailwind utility classes ship as inline style attributes. Both
  can be hardened with nonces, but that requires threading a per-
  request nonce through Next middleware and rewriting every inline
  emitter to consume it. Out of scope for this bundle; tracked as
  **P2 #3b**.
- **No CSP violation reporter wired up.** Real-world violations now
  surface as blocked-resource errors in the browser console + Sentry
  (since failed `fetch` / `script` loads bubble up through the SDK).
  A dedicated `report-to` / `report-uri` endpoint would aggregate them
  centrally — left as a future enhancement.

## Alternatives rejected

- **Keep Report-Only indefinitely.** Report-Only adds zero security
  value beyond the console; the whole point of CSP is for the browser
  to refuse to load disallowed resources. Indefinite soak defeats
  the purpose.
- **Ship enforcement with the nonce hardening in the same bundle.**
  Nonce threading touches middleware + every JSON-LD call site +
  potentially the Tailwind output pipeline. Worth its own bundle so
  this one stays auditable as "single header rename".

## Follow-ups deferred

- **P2 #3b** — nonce-based hardening of `'unsafe-inline'` on
  `script-src` and `style-src`.
- **P3 #8** — audit-log coverage gaps.
- **P3 #11** — preemptive upload hardening.
