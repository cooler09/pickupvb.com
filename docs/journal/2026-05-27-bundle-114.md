# 2026-05-27 — Bundle 114: Bracket spectator OG image

## Why

Bundle 111 shipped one-click copy of the spectator URL. As soon as people
start sharing those links in group chats and on social, the unfurled
preview matters — and right now the bracket-watch route inherits no OG
metadata of its own. It would fall back to the site-level OG image (or
nothing) rather than something that says "live bracket." We want the
preview to reinforce the value prop the link delivers.

## What changed

- New [opengraph-image.tsx](../../apps/web/src/app/events/[id]/bracket/watch/opengraph-image.tsx)
  under the watch route. Reuses `brandOgImage` from
  [lib/og-image.tsx](../../apps/web/src/lib/og-image.tsx) so brand
  treatment (palette, "P" tile + wordmark, CTA pill) stays consistent
  with the existing event / team / player / group cards. Eyebrow is
  `Live bracket`; meta line composes `<status> · N teams · <format>`
  (e.g. `In progress · 8 teams · Single elimination`). CTA overridden to
  `Watch live at pickupvb.com` to differentiate from the generic event
  card's "Join free" pitch.
- `generateMetadata` added to
  [bracket/watch/page.tsx](../../apps/web/src/app/events/[id]/bracket/watch/page.tsx)
  so unfurlers also get a proper `<title>`, description, canonical URL,
  and `openGraph` / `twitter` blocks — matching the shape already in
  use on the parent event page.
- Defensive fallbacks at both layers (the page's `generateMetadata` and
  the OG handler) return a generic "Live bracket — PickupVB" card if the
  event lookup fails, so a 404 or a transient handler error never breaks
  the share preview.

## Patterns observed

- **Reuse `brandOgImage`, don't author new JSX cards.** The helper
  already nails the Satori inline-style constraints, the cache headers,
  and the typography rhythm. New OG routes should be a 20-line data fetch
  - one call to `brandOgImage({ eyebrow, title, meta, cta? })`.
- **Inline a small enum→label map when only one consumer needs it.**
  `lib/enum-labels.ts` `FORMAT_LABEL` is for team-format (4s/6s); the
  bracket format enum (`single_elimination`, `double_elimination`,
  `round_robin`, `pool_play_playoff`) is a different domain. Bundle 109
  moved bracket format labels into `format-picker-form.tsx`; importing
  from a `'use client'` component into an OG image route would drag the
  client boundary the wrong way. A 4-line `Record<BracketFormat, string>`
  inline in the OG file is cheaper than re-extracting a shared module
  for a single second consumer.
- **OG image routes can re-fetch the same data the page does.** They run
  on demand, are cached for an hour via `OG_CACHE_CONTROL`, and `Promise.all`
  of `findByDivisionId` + `listRegisteredTeams` is the same pair the page
  already calls. No need to introduce a slim read model just for previews.

## Follow-ups deferred

- **Per-division OG image.** Today we render `divisions[0]`. A multi-
  division tournament shared from `?division=B` should reflect the B
  division's team count and status. Would need to thread `searchParams`
  into the OG route or move to a query-string-aware variant.
- **Winner name when bracket is `completed`.** Eyebrow could read
  "Champion: Team Foo" instead of "Final results" — needs to walk the
  bracket to the final match's winner side.
- **Liveness hint mid-tournament.** Showing "Final about to start" or
  "Round of 8" gives the share preview real-time pull. Requires a small
  helper to summarize the current round from the matches list.
- **Custom font in `ImageResponse`.** `brandOgImage` currently uses
  Satori's default system stack. Loading IBM Plex (or whichever brand
  font we settle on) via `ImageResponse({ fonts })` would tighten the
  visual identity across every OG card at once — worth doing as a
  cross-cutting bundle rather than per-route.
- **IntersectionObserver "don't yank me" guard on the autoscroll
  behaviour from bundle 113** is still open.
