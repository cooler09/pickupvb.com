# Bundle 56 — 2026-05-23 — CONTRIBUTING.md (Documentation P1)

## Context

The Documentation audit had one P1 left: "Missing CONTRIBUTING and LICENSE".
The LICENSE half closed 2026-05-17 (MIT). The CONTRIBUTING half was gated
on an open question that had been sitting unanswered for six days:
**"Is this an open-source / open-contribution project, or a personal /
closed repo?"** The audit body explicitly noted that the contents of
CONTRIBUTING.md depended on the answer — a permissive doc for open
contributions vs. a one-line "this is personal, PRs are ad-hoc" note.

The gate is answerable now. Shipping MIT in Bundle ~17 implicitly chose
"permissive / forkable," but the day-to-day reality is that I run this
project alone and there's no review SLA. So the right framing is
"personal project, PRs welcome but ad-hoc" — open in license terms,
ad-hoc in process. That answers the gating question and unblocks the
file.

## What shipped

### Root `CONTRIBUTING.md` (new)

[CONTRIBUTING.md](../../CONTRIBUTING.md) — ~120 LOC across nine
sections:

1. **Personal-project framing.** Up front: this is mine, PRs are
   ad-hoc, no SLA. Removes the misleading "thanks for your
   contribution!" / OSS-corporate vibe.
2. **Code of Conduct** as a short paragraph instead of a separate
   file (the standalone CoC is still on the P3 list — calling it out
   inline here keeps the bar reasonable without manufacturing a doc

   check `docs/audits/` + `docs/journal/` for context, expect that
   the hosted secrets won't work locally.

   six-line quickstart so the file isn't useless without a second tab
   open.
5. **Conventions: see AGENTS.md.** Deliberately does not duplicate
   the typed-error table, page-composition rules, or layering
   constraints — those live in [AGENTS.md](../../AGENTS.md). Calls
   out the three things that actually trip people up: hexagonal
   layering, typed `DomainError` (not `Error('NOT_FOUND')`),
   `exactOptionalPropertyTypes`, and `_components/` co-location.
6. **Verify before pushing** — the four-command quad, codified as
   a pre-push gate.
7. **Pull requests** — branch naming, commit messages (lowercase
   imperative, matching the actual history), PR description
   expectations (link to audit findings + journal entries if
   applicable), and the "same rules the AI agents follow" footer
   tying back to AGENTS.md's no-`--no-verify` / no-force-push rules.
8. **Migrations** — points at the preamble standard and the
   regen-types step, with a CI note that prod migrations apply on
   deploy.
9. **What probably can't get merged** — explicit list (framework
   imports in `domain` / `application`, undocumented `force-dynamic`,
   string error codes, drive-by refactors). Cross-references the
   "Patterns surfaced by audits" section in AGENTS.md.
10. **Security advisory channel** + MIT license note.

## Pattern notes

### Gated findings can be closed once the gate is satisfied

The CONTRIBUTING P1 sat open for six days because nobody noticed
the gate question (open-vs-closed) had been implicitly answered the
moment MIT shipped. Worth a sweep next audit: any finding tagged
"depends on X" should re-check whether X has been decided since.

### "Thin pointer" is the right design when conventions already live elsewhere

The natural CONTRIBUTING.md template is verbose — setup + style guide

- commit conventions + testing + release process. We already have
  AGENTS.md (conventions), README.md (setup), docs/runbook.md
  (release/rollback), docs/testing.md (test strategy). Duplicating any
  of them into CONTRIBUTING.md guarantees drift. The shipped file is
  deliberately a pointer doc: it tells contributors **what to do**
  (verify quad before PR; issue-first for non-trivial work) and
  **where to read more** (AGENTS.md for the architectural rules).

This is the same shape as docs/onboarding.md (Bundle 40) — thin
overlay on the existing docs rather than a parallel canon.
