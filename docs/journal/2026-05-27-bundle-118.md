# Bundle 118 — Division-centric registration: multi-division free agents, host opt-out, cross-event guard (2026-05-27)

## Context

Bundle 117 (the registration-workflow re-audit) was triggered by the
product reframing "the event is a container; each division owns its
teams + free agents." The re-audit logged six new findings; this bundle
closes three of them in one migration:

- **R1 (P1)** — `event_free_agents` PK `(event_id, user_id)` blocked a
  player from joining multiple divisions' free-agent pools for the same
  event, even though `division_id` had been NOT NULL since Bundle 68.
- **R2 (P1)** — No host toggle for free-agent enrollment. Every
  division that existed accepted FA signups; there was no way to run a
  Pro/Open division "captains only" while the Rec division stayed open.
- **R6 (P3, architectural)** — `event_teams.event_id`,
  `event_team_registrations.event_id`, `event_free_agents.event_id`,
  and `event_attendees.event_id` are redundant with `division_id` once
  divisions carry their parent `event_id`. Nothing on the schema side
  enforced that the two agree; an app bug could persist a row whose
  `event_id` belonged to a different event than its `division_id`.

R3 (per-division `team_registration_mode`) and R4 (walk-ins as
first-class registrations) are deferred — R3 needs ADR 0009 superseding
ADR 0008 §2, R4 needs a product decision on `captain_id` nullability.

## Decisions

- **One migration, three findings.** All three are read/write contracts
  that touch the same four tables. Shipping them as separate migrations
  would force a CI/CD ordering between an RLS rebuild, a PK widen, and
  a trigger install on overlapping surfaces. One file keeps the data
  plane consistent in a single deploy.
- **R2 default = `true`.** Existing hosts get current behaviour with
  no migration backfill; the toggle is strictly opt-out. New divisions
  default to accepting free agents through `Division.create()`'s
  `?? true`, and the column carries the same default at the DB level.
- **R2 enforced in the domain, not just RLS.** `VolleyballEvent.joinAsFreeAgent`
  throws `InvariantViolation` when the target division has
  `allowFreeAgents=false`. RLS is the second line; the aggregate keeps
  invariants framework-free and lets the application layer surface a
  typed `'fa_disabled'` reason to the panel.
- **R6 via trigger, not column-drop.** Two options were on the table:
  - **A. Drop the redundant `event_id` columns** on the four tables
    and rebuild every reader/writer to derive `event_id` via a join on
    `event_divisions`. Cleanest end-state but a wide column-removal
    sweep across the infra adapter, RLS policies, views, and
    bracket-reader queries. Half of those readers don't care about the
    consistency invariant — they're just convenient denormalisations.
  - **B. Install a BEFORE INSERT/UPDATE trigger** that asserts the
    parent `event_divisions` row's `event_id` matches. **Chosen.**
    Cheap belt-and-braces; closes the audit finding's literal intent
    ("nothing enforces that the two agree") without touching a single
    reader. The column-removal sweep is still on the table as a later
    bundle if the columns prove to drift in practice.
- **UI scope.** The schema unblocks multi-division-per-user FA signup,
  but the existing free-agent panel still posts one division at a
  time. A picker-list UI is deferred — the immediate user-visible win
  is R2 (host can hide the FA form per division) and the
  `TournamentRegisterPanel` collapse when no division accepts FAs.

## Changes

- **New migration**
  [20260710000000_division_centric_registration.sql](../../supabase/migrations/20260710000000_division_centric_registration.sql)
  — R1 widens `event_free_agents` PK to
  `(event_id, user_id, division_id)`; R2 adds
  `event_divisions.allow_free_agents boolean not null default true` and
  rebuilds the `event_free_agents_insert` RLS policy to add
  `exists (select 1 from public.event_divisions d where d.id =
division_id and d.allow_free_agents = true)`; R6 installs
  `assert_division_event_consistency()` and BEFORE INSERT/UPDATE
  triggers on `event_teams`, `event_team_registrations`,
  `event_free_agents`, and `event_attendees`.
- **Types stub** — [packages/supabase/src/database.types.ts](../../packages/supabase/src/database.types.ts)
  hand-patched (Docker unavailable locally) to add

- **Domain** —
  [`Division`](../../packages/domain/src/events/division.ts) gains
  `allowFreeAgents` prop, ctor argument, and a `?? true` default in
  `create()`. [`VolleyballEvent.joinAsFreeAgent`](../../packages/domain/src/events/volleyball-event.ts)

  [`CreateEventHandler`](../../packages/application/src/commands/create-event.handler.ts)

  [`JoinEventHandler`](../../packages/application/src/commands/join-event.handler.ts)

- **Infrastructure** —
  [`SupabaseEventRepository`](../../packages/infrastructure/src/supabase-event-repository.ts)

  the three division mappers translate `allow_free_agents ↔ allowFreeAgents`.
  [`EventRepository.DivisionLite`](../../packages/domain/src/events/event-repository.ts)
  carries `allowFreeAgents`.
- **Types** —
  [`DivisionInputSchema`](../../packages/types/src/events.ts) adds
  `allowFreeAgents: z.boolean().optional()`.
- **Web UI — create event** —
  [`DivisionsRepeater`](../../apps/web/src/app/events/new/_components/divisions-repeater.tsx)

  [`division-actions.ts`](../../apps/web/src/app/events/[id]/division-actions.ts)

- **Web UI — attendee surfaces** —
  [`event-signup-area.tsx`](../../apps/web/src/app/events/[id]/_components/event-signup-area.tsx)

## Follow-ups deferred

- **Multi-division-per-user free-agent UI.** Schema now allows the same
  user in multiple divisions' FA pools per event; the panel still posts
  one division at a time. Needs a checkbox-list signup form + handler
  loop. Low priority — the audit's pain point was the PK collision,
  not the UI.
- **R3 (per-division `team_registration_mode`).** Bundle C. Requires
  ADR 0009 superseding ADR 0008 §2, a migration to move the column
  from `events` to `event_divisions` with backfill, an RLS rewrite on
  `event_team_registrations_insert` to read the division's mode, an
  `events_view` rebuild, and lifting the `TeamRegistrationModeSelect`
  picker from the event-level form into the per-division repeater.
- **R4 (walk-ins).** Bundle D. Blocked on product decision: does a
  walk-in registration need `captain_id` (and therefore a
  `profiles`/`auth.users` row) at all, or can `captain_display_name` +
  `captain_phone` stand alone? Migration sketch: nullable `captain_id`
  - `captain_display_name text` + `captain_phone text` + `source text
not null default 'captain' check (source in ('captain','host','walk_in'))`
  - `check (captain_id is not null or captain_display_name is not null)`.
- **R6 column-removal sweep.** The trigger satisfies the audit's
  intent; dropping the redundant `event_id` columns from the four
  tables is still available as a later bundle if drift surfaces.

## Notes

- Docker not running locally → `packages/supabase/src/database.types.ts`
  hand-patched. Production migrations are applied automatically by
  CI/CD on deploy per AGENTS.md.
- The R6 trigger fires on every INSERT/UPDATE to the four tables; the
  lookup is a single PK-indexed read on `event_divisions` and should
  not move the needle on write latency. If it does, the column-removal
  sweep becomes the right answer.
