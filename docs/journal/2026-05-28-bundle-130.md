# 2026-05-28 — Bundle 130 (M3 Touch Targets)

Second installment of the M3 adoption plan from
[docs/audits/m3-alignment.md](../audits/m3-alignment.md). Bundle 129
shipped the vocabulary (tokens). This bundle closes the first **P1**
finding by sweeping every icon-only button to a shared `tap-target`
utility.

## Context

Audit P1 #3 documented that despite [accessibility.md](../audits/accessibility.md)
having previously bumped the mobile-menu hamburger and notification bell
to 44 × 44, drift had crept back across icon-only buttons elsewhere:
toast close `×`, modal close `×`, pagination prev/next, co-host remove
`✕`, bracket seeding move arrows, board move-match arrows, walk-in
player remove. All sat between 24 px and 36 px tall — below both M3's
48 dp minimum and the 44 px target the prior nav-only fix landed on.

The audit specified the fix: introduce a `tap-target` utility and apply
it everywhere. This is the highest-leverage mobile-UX bundle in the
sequence because it touches every page that has a list-row action and
every page that uses the toast viewport (i.e. all of them).

## Decisions

- **Single `@utility tap-target` in `globals.css`.** Tailwind 4's
  `@utility` shorthand registers it as a real utility class
  (`tap-target`, `hover:tap-target`, etc.). The body inlines `3rem`
  rather than `calc(var(--spacing) * 12)` because we don't depend on
  `--spacing` being defined anywhere else and the literal is one
  cognitive hop less to read at the call site.
- **`min-height` / `min-width`, not `height` / `width`.** A fixed-size
  button locks the layout when content (text + icon, a badge, etc.)
  legitimately needs more space. `min-*` floors the hit area at 48 px
  but still lets the button grow.
- **Visual change is intentionally near-zero.** Where a previous
  component combined a small visual chrome (`-mt-1 -mr-1 px-1.5` on the
  toast close) with a small click target, we kept the chrome offsets and
  let `tap-target` provide the floor — the icon stays where the eye
  expects it, the hit area grows outward symmetrically.
- **What we did NOT touch:**
  - `NavDropdown` trigger — has a visible text label that already
    dominates the hit area; the dropdown chevron isn't truly
    icon-only.
  - Share menu in `share-link.tsx` — text label + icon together
    already exceed 48 px width.
  - Filter chips in `active-filter-chips.tsx` — M3 Chip spec is
    32 dp, not 48 dp; chips are a separate component category and
    get their own primitive in a later bundle.
- **Lint rule deferred.** The audit suggested a custom rule that warns
  on `<button>` elements containing only an SVG without `tap-target`.
  Worth doing once the call-site pattern is consistent across the
  whole tree, but the up-front detection cost (AST walks across every
  JSX tag) is high for this small a bundle. Revisit when more icon-only
  surfaces ship (FAB, BottomNav).

## Patterns observed

- Several call sites already had a private "make this a 44 px square"
  recipe (`flex h-11 w-11 items-center justify-center`). The `tap-target`
  utility is now the canonical version — when reviewing future PRs,
  flag the long-form as a smell.
- The toast-close button is doing two jobs at once: it's both a hit
  target and a corner-flush visual element. The pattern that survived
  this sweep — negative margin to absorb the floor's overflow back
  into the parent layout (`-mt-1 -mr-1`, `-m-2`) — is worth knowing
  about. Use it wherever a `tap-target` would otherwise push surrounding
  text out of alignment.
