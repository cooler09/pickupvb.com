# Bundle 7 — Tournament tabs → single-flow picker

_Date: 2026-05-24_

## Context

Bundle 6 ([journal](2026-05-24-bundle-6.md)) ratified the team-paradigm
doctrine in [ADR 0008](../adr/0008-team-registration-paradigm.md) and
cleared the registration-workflow audit's recommended-sequencing step 1.
The next item the audit called out (and the only remaining UX P2 on the
registration surface) was the `TournamentRegistrationTabs` two-tab
split: "Register team" and "Free agent" sat on sibling tabs, forcing
the user to know which they were before they could look at either.

ADR 0008 §6 sketches the eventual division → mode → roster → pay
wizard, but flagged the full wizard as **Phase 2** because Bundles 1
and 5 had already pushed division selection _into_ each individual
panel (`TournamentSignupPanel`, `FreeAgentSignupPanel`,
`AdHocTeamSignupPanel`). With the per-panel flows already
division-first, the immediate UX bug was just the tab metaphor itself
— and the smaller change of replacing tabs with a guided picker
unblocks the audit P2 without a model rewrite.

## Scope

1. New client component
   [`TournamentRegisterPanel`](../../apps/web/src/app/events/%5Bid%5D/_components/tournament-register-panel.tsx)
   replaces `TournamentRegistrationTabs`. It accepts the existing team
   and free-agent panels as `ReactNode` children — so the wrapper
   becomes a `'use client'` boundary while the panels themselves stay
   server components and keep importing server actions directly.
2. Renders a `role="radiogroup"` "How are you signing up?" segmented
   control above the two panels; the unselected branch is hidden via
   `hidden={mode !== ...}` so the DOM still ships both for
   instant-toggle but only the active one is interactive / visible.
3. When `team_registration_mode === null` (free-agent-only event), the
   wrapper short-circuits to `<section id="signup">{freeAgentPanel}</section>`
   — no picker rendered, no team branch in the DOM.
4. Default mode is chosen at the page boundary:
   `defaultMode={event.isFreeAgent ? 'free-agent' : 'team'}`.
5. Deleted
   `apps/web/src/app/events/[id]/_components/tournament-registration-tabs.tsx`.
6. Verified the stale `PaidTicketPanel` dual-CTA UX P2 — the panel
   already branches on `paymentsOffPlatform`
   ([paid-ticket-panel.tsx#L75-L99](../../apps/web/src/app/events/%5Bid%5D/_components/paid-ticket-panel.tsx#L75-L99))
   and only ever shows one CTA. Audit description was out of date;
   marked closed in the same bundle without code change.
7. Audit + index updates in
   [docs/audits/registration-workflow.md](../audits/registration-workflow.md)
   and [docs/audits/README.md](../audits/README.md).

## Decisions

- **Segmented radiogroup over a modal wizard.** ADR 0008 §6's
  division → mode → roster → pay wizard is the right destination, but
  the panels are already division-first internally. A modal would
  duplicate division selection and require lifting the
  team/ad-hoc/free-agent forms out of their server components. The
  segmented picker is a one-step nudge that fixes the discoverability
  bug without rewriting any of the working flows. Wizard collapse
  remains tracked in the audit and ADR §6.
- **Wrapper takes `ReactNode` children, not props.** Two alternatives
  considered: (a) pass shape-typed props and let the wrapper render
  the inner forms itself, or (b) accept the rendered panels as
  `ReactNode`. Option (a) would force the wrapper to become a server
  component (because it would import server actions) or force the
  inner panels to become client components (losing their server-action
  imports). Option (b) preserves the boundary: the page (server)
  renders both panels eagerly, hands them to the client wrapper as
  children, and the wrapper just toggles visibility. The DOM weight
  is identical to the old tab implementation.
- **Default to free-agent panel on `isFreeAgent` events.** Considered
  a smarter default based on whether the viewer is captain of any
  registered team, but `user?.id` may be undefined and the heuristic
  adds edge cases without a clear win. `event.isFreeAgent` is the same
  signal the existing host-side UI uses, so it stays consistent.
- **Keep the `#signup` anchor on the outer `<section>`** so existing
  deep-links from email and share cards still scroll to the picker.
- **Did not lift the division selector out of the panels.** ADR 0008
  §6 sketches this as a Phase-2 win, but the panels enforce the
  `divisionId` requirement at the form boundary today and the side-step
  ports validate it server-side. Lifting it would require a new
  client-side state store and isn't needed to close the audit P2.

## Patterns observed

- **Server-component children inside a client wrapper.** This is the
  third place in the codebase where a `'use client'` wrapper accepts
  server-rendered panels as `ReactNode` (the others are the events
  list filter chrome and the host dashboard tabs). Worth promoting to
  AGENTS.md "Patterns surfaced by audits" if it shows up again — the
  React docs cover it but it's easy to forget when reaching for
  `'use client'` on a small interaction.
- **Stale audit findings are a real category.** The `PaidTicketPanel`
  dual-CTA P2 was authored before the `paymentsOffPlatform` branch
  landed; nothing closed it because no remediation bundle touched the
  file. A quick "verify before scoping" pass on each open finding is
  cheaper than scoping a fix. Worth treating audit-doc verification
  as the first step of any UX-bundle scoping going forward.

  0008 §5 deferred; still open on the audit.
