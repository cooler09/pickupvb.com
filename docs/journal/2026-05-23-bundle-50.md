# Bundle 50 — Accessibility P3 cluster closeout (2026-05-23)

## Context

After Bundle 49 brought the architecture audit down to its single
deferred P2, the next-cleanest closeout target was the accessibility
audit's three remaining P3 findings:

1. Placeholder-as-label in `datetime-picker.tsx` and
   `address-autocomplete.tsx`.
2. Icon-only buttons sized `h-4 w-4` / `h-5 w-5` in `alert.tsx` and
   `mobile-menu.tsx`.
3. Heading-level sweep — routine recheck.

All three were grouped under one bullet in the audit's "Still open"
list, so closing them in one pass collapses the audit row to "every
finding resolved."

## What shipped

### Placeholder-as-label — one real fix

Audited every `DateTimePicker` callsite for a sibling `<label htmlFor>`:

- `community/new/community-listing-form.tsx` — `startsAt` ✅ + `endsAt` ✅.
- `community/[slug]/edit/community-listing-edit-form.tsx` — `startsAt` ✅ + `endsAt` ✅.
- `events/new/new-event-form.tsx` — `startsAt` ✅ + `endsAt` ✅.
- `events/[id]/edit/edit-event-form.tsx` — `startsAt` ✅ + `endsAt` ✅.
- `event-advanced-details-panel.tsx` — `registrationClosesAt` ❌ (label
  rendered without `htmlFor`).

Added `htmlFor="registrationClosesAt"` to the lone offender. SR users
focusing the field now hear "Registration closes at" instead of just
the picker's placeholder text.

For `AddressAutocomplete`, the audit text was stale: Bundle 43's
combobox ARIA pass added `aria-label="Search for an address or venue"`
to the input, so the placeholder is no longer doing label duty. No
code change needed; verified in the remediation log so the next agent
doesn't re-grep.

### Icon-only hit-areas — both findings verified-stale

- [alert.tsx](../../apps/web/src/components/alert.tsx) — the `h-4 w-4`
  SVG at L66 is the **decorative variant icon** (`aria-hidden`), not a
  close button. The current alert component has no close affordance at
  all (toasts have one, alerts don't). The audit must have been
  written against a draft that bundled the patterns together.
- [mobile-menu.tsx](../../apps/web/src/components/mobile-menu.tsx) —
  the hamburger trigger is `h-11 w-11` (44×44), satisfying WCAG 2.5.5.
  Bumped to that size in Bundle 2's tap-target P2; the audit text
  predates that change.

Both noted in the remediation log row so the next pass doesn't repeat
the work.

### Heading-level sweep — clean

Ran `grep -rn '<h[1-6]' apps/web/src/app --include='page.tsx'` and

| Level     | Count |
| --------- | ----- |
| `h1`      | 74    |
| `h2`      | 153   |

No level-skipping. Two `page.tsx` files have no local `h1`
(`groups/[id]/page.tsx` and `events/[id]/page.tsx`) — both emit their
`h1` from a co-located `_components/` child
([group-header.tsx](../../apps/web/src/app/groups/%5Bid%5D/_components/group-header.tsx#L53),
[event-hero.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/event-hero.tsx#L107)),
which is the page-diet pattern the architecture audit's Bundles 23-24
established. No action needed.

## Patterns / follow-ups

- **A P3 cluster with three items, two stale.** The audit text was
  written 2026-05-17; bundles 2, 43, and 44 (covering tap targets,
  combobox ARIA, focus-ring contrast respectively) closed the
  underlying issues without ever crossing the P3 line. Always do the
  cheap re-verification grep before opening an editor — common enough
  now that "audit text outpaced the code" is the recurring journal
  motif this week (compare Bundle 48's TODO scan, Bundle 49's hrefs
  cleanup).
- **The accessibility audit has no more remediation findings.** The
  four "open questions" at the bottom of the audit are design calls
  rather than fixable items — combobox-primitive consolidation needs
  an architecture decision; the AT testing / accessibility-statement /
  contrast-token questions need ownership outside a single bundle.
  When one is picked up, treat it as a new audit topic rather than a
  re-open of the existing one.
- **Heading-level sweep tooling.** The two-grep approach (level
  histogram + per-file h1 presence) was enough to verify the entire
  app in under a minute. Worth keeping in mind for future a11y passes
  on new templates.
