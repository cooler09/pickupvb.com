# 2026-05-28 — Bundle 134 (Dialog + BottomSheet on Radix)

Sixth installment of the M3 adoption plan from
[docs/audits/m3-alignment.md](../audits/m3-alignment.md). Bundle 129
shipped tokens, Bundle 130 swept touch targets, Bundle 131 introduced
the state-layer utility + button vocabulary, Bundle 132 migrated the
toast system to Radix, Bundle 133 shipped BottomNav + FAB; this
bundle migrates the dialog primitive to `@radix-ui/react-dialog`,
adds M3 affordances (icon, action ordering), and ships a bottom-sheet
presentation for mobile.

## Context

Audit P2 #9 called out that the Bundle 128 `<FormModal>` is a solid
native `<dialog>` shell but missing the M3 dialog structure: no icon
slot, no spec'd action ordering, no full-screen-on-compact variant.
Audit P2 #14 called out the related mobile UX miss: centering a
`max-w-md` card on every viewport loses ~30% of vertical space to
margins on mobile and lifts the form above the thumb zone — M3
prescribes a **bottom sheet** for modal forms on compact screens.

These are the same primitive on different viewports, so they bundle
naturally. The audit's recommended 10-bundle sequence pairs them as
"Bundle 6 — Dialog + BottomSheet."

Migrating off native `<dialog>` is also overdue: the Bundle 128
implementation needed two `useEffect` bridges — one to drive
`el.showModal()` from React state (`<dialog>` doesn't accept a
controlled `open` prop without losing the backdrop + focus trap),
and one to listen for browser-initiated `close` events so the next
`open()` call worked. Radix collapses both into a single
`useState` + `onOpenChange` callback.

## Decisions

### 1. Preserve the public API exactly

The three call sites
([host-ad-hoc-teams-panel.tsx](../../apps/web/src/app/events/[id]/_components/host-ad-hoc-teams-panel.tsx),
[no-bracket-view.tsx](../../apps/web/src/app/events/[id]/bracket/_components/no-bracket-view.tsx),
[setup-view.tsx](../../apps/web/src/app/events/[id]/bracket/_components/setup-view.tsx))
were carefully written and tested in Bundle 128. This bundle is a
**primitive swap**, not a call-site migration. The visible diff at
every call site is zero. Same `<FormModal trigger title description
size>` shape, same `children` node-or-render-prop, same
`CloseOnSettled` + `ModalFooter` exports. M3 affordances added
strictly as optional props.

### 2. Additive M3 affordances, not enforced

- **`icon?: ReactNode`** — optional M3 dialog icon above the title.
  When present, title + description center per M3 spec; when absent,
  the existing left-aligned layout stays.
- **`presentation?: 'dialog' | 'sheet' | 'auto'`** — defaults to
  `'dialog'`, preserving the Bundle 128 centered card on every
  viewport. `'sheet'` and `'auto'` are opt-in per call site.
- **`<ModalActions>`** — new export with named
  `destructive` / `dismissive` / `confirming` slots that enforce
  M3's `[destructive]   …spacer…   [dismissive] [confirming]`
  ordering. `<ModalFooter>` stays exported as the unstyled escape
  hatch already in use.

This shape keeps the bundle scope tight (1 primitive, 1 CSS file,
3 call sites untouched) and leaves call-site adoption of the new
affordances as future smaller PRs.

### 3. Single `<Content>` for `presentation='auto'`

The auto variant flips between bottom sheet (below `sm`) and
centered dialog (`sm` and up). Tempting to render two conditional
`<Content>`s, but that:

- Remounts the focus trap on viewport rotation.
- Doubles the React tree weight for every modal in the app.
- Forces every consumer that opens a modal mid-animation to handle
  the swap.

Instead the composition is `className="md-sheet-motion sm:md-dialog-motion
fixed inset-x-0 bottom-0 … sm:inset-auto sm:top-1/2 sm:left-1/2 …"`
— the same DOM node restyles itself at `sm:`, the same focus trap
follows, and the M3 motion keyframes the CSS chooses also flip via
the responsive variant. Verified the Tailwind responsive prefix
covers both class names without escape (single `@utility`-free
strings).

### 4. `<span style={{ display: 'contents' }}>` wraps the trigger

Radix's `Dialog.Trigger asChild` requires a single forwardRef child.
The legacy public API hands `(open) => ReactNode` to call sites and
expects them to wire `open()` onto whatever element they choose
(`<button>`, `<Link>`, styled `<div>`). Two ways to bridge:

1. Force callers to use `Trigger asChild` themselves — breaks the
   public API.
2. Render the trigger output adjacent to `Portal` and let the caller
   keep wiring `open()` onto their element directly — Radix's
   trigger semantics aren't actually needed since the caller's
   element drives `setIsOpen(true)`.

Picked option 2. The `display: contents` wrapper exists purely to
give us a single React element to render the trigger render-prop's
arbitrary output into without disrupting flex/grid layout at the
call site.

### 5. Motion family with toast

Dialog + sheet use the same `emphasized-decelerate` / `emphasized-accelerate`
pair at the same `medium2` / `short4` durations the Bundle 132 toast
uses. Reads as "this is the same app talking to you" across all
transient surfaces. Centered dialog adds a 4 px lift + 2% scale-up
on enter (M3 dialog standard); sheet uses pure `translateY(100%) →
0` (M3 sheet standard).

### 6. No `vaul` yet

Audit mentions `vaul` as a swipe-to-dismiss option for the sheet.
Radix Dialog alone covers the visual + a11y story for now. Touch-drag
dismiss is the kind of affordance that needs real usage data to
decide whether the close button is awkward enough to warrant — added
to deferred follow-ups instead.

## Patterns observed

- **The Radix bridge pattern (codified in AGENTS.md Bundle 132 for
  Toast) cleanly generalises to Dialog.** Same shape: preserve the
  call-site API, bridge `data-state` to M3 motion via CSS keyframes,
  compose `tap-target` + `state-layer` on the close button. Worth
  reusing verbatim for Bundle 8 (Dropdown Menu).
- **Optional-prop M3 affordances** are the right migration tactic
  when the primitive has multiple call sites with hand-tuned
  markup. Risks zero regressions; lets call-site adoption be
  per-form judgement calls.
- **Tailwind responsive variants compose cleanly with Radix
  attribute selectors.** `md-sheet-motion sm:md-dialog-motion` works
  because each class is bound to `[data-state='open'|'closed']`
  independently — the responsive variant just decides which keyframe
  sets paint at each breakpoint. Single DOM node, two motion
  families, zero React conditionals.

## Follow-ups deferred

- **Migrate existing `ModalFooter` call sites to `<ModalActions>`**
  when next touching those forms. No churn-only PR — the existing
  layouts already match M3 ordering by hand.
- **Pick a first `presentation='auto'` adoption site.** Likely the
  walk-in team form on `host-ad-hoc-teams-panel.tsx` (largest modal,
  biggest mobile-real-estate win). Defer until product greenlights.
- **`vaul`-style swipe-down-to-dismiss** on the sheet variant if
  user testing flags the close button as awkward on mobile.
- **Audit other native `<dialog>` users** ([report-bug-button.tsx],
  [confirm-submit-button.tsx]) for whether they should migrate onto
  Radix as well or stay native — smaller one-off cases may not
  justify the dep weight.
- **`onCloseAutoFocus` handling** for sheets that contain async
  forms (Radix returns focus to the trigger by default; this is
  correct, just worth documenting once a real case surfaces).
