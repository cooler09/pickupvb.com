# Bundle 71 — 2026-05-23 — Document Google OAuth + anon sign-in setup

## Context

Two onboarding traps surfaced back-to-back while a new dev was setting
up the stack:

1. The guest RSVP / guest ticket-checkout / anonymous-tip flows started
   throwing `"Anonymous sign-ins are disabled"` after a clean
   `supabase start`. The Supabase CLI defaults
   `enable_anonymous_sign_ins = false`, and our `[auth]` stanza in
   `supabase/config.toml` had never set it explicitly — we'd only been
   relying on the dashboard toggle on hosted projects.
2. The "Continue with Google" button on `/login`
   (`apps/web/src/app/login/_components/google-button.tsx`) was wired
   to `signInWithOAuth({ provider: 'google' })` and the callback route
   existed (`apps/web/src/app/auth/callback/route.ts`), but the
   provider itself was undocumented — no Google Cloud setup steps, no
   `[auth.external.google]` block in `config.toml`, no env vars in
   `.env.example`. New devs hit a generic "provider not enabled" error
   with no breadcrumb back to the fix.

Both are pure documentation / config plumbing — the app code was
already correct.

## Decision

- Make `enable_anonymous_sign_ins = true` explicit in `config.toml`
  with a comment pointing at the three files that depend on it. Source
  of truth lives in-repo so the next clone doesn't break.
- Add the `[auth.external.google]` stanza wired to env-ref placeholders
  (`SUPABASE_AUTH_GOOGLE_CLIENT_ID`, `SUPABASE_AUTH_GOOGLE_SECRET`).
  The CLI auto-loads `supabase/.env` (already gitignored), so devs
  drop the credentials there and `supabase start` picks them up. No
  shell-export ritual required.
- Mirror the env vars in `.env.example` with a comment block that
  links to Google Cloud Console and spells out the callback URIs
  (Supabase's `/auth/v1/callback`, **not** the app's `/auth/callback`
  — this trips everyone up at least once).
- Add two short subsections to `README.md` under "Getting started":
  "Google OAuth provider (optional)" and "Anonymous sign-ins". Both
  call out that `config.toml` is local-only and the hosted toggle
  lives in the Supabase dashboard, because that's the second trap —
  flipping it locally and forgetting to flip it in staging/prod.

Rejected: routing the OAuth client through a separate
`packages/config` module. The CLI consumes the values directly via
the `env(...)` syntax — adding an indirection layer would just hide
the actual contract.

## Changes

- `supabase/config.toml` —
  - Added `enable_anonymous_sign_ins = true` to `[auth]` with a
    pointer to the three actions that call `signInAnonymously()`.
  - Added `[auth.external.google]` stanza with env-ref placeholders
    and a comment noting hosted environments configure via dashboard.
- `.env.example` — added `SUPABASE_AUTH_GOOGLE_CLIENT_ID` and
  `SUPABASE_AUTH_GOOGLE_SECRET` under a Google OAuth block that
  documents the Cloud Console setup and the local vs hosted split.
- `README.md` — new "Google OAuth provider (optional)" and
  "Anonymous sign-ins" subsections under "Getting started", placed
  immediately after the Supabase key-copy step so they're encountered
  before `pnpm dev`.

## Verification

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` — all four
pass (no code change, only config + docs).

- Add a hosted-environment runbook entry under `docs/` that lists
