# 2026-05-22 — Bundle 28: real `test` scripts in the last 5 placeholder packages

## Context

The organization audit's P1 #2 was "test scripts are no-ops; CI is green
by accident." Bundles 22 (test bootstrap) and 23 (events/[id] page
diet) brought Vitest online for `domain`, `application`, and `web` —
those three packages have real `vitest run` scripts and real test
suites. The remaining 5 packages (`config`, `infrastructure`,
`notifications`, `supabase`, `types`) still shipped placeholder
`test: "echo no-tests"` (or `"echo no-op"`) scripts. Net effect:
dropping a `*.test.ts` into any of those packages would do nothing
under `pnpm test`, and CI would happily report green.

## What shipped

One-line `package.json` edit in each of the 5 packages:

```diff
-    "test": "echo no-tests",
+    "test": "vitest run --passWithNoTests",
```

(`config` was `echo no-op`; same swap.)

`--passWithNoTests` keeps packages without any test files exiting 0,
so CI stays green today. The moment a `*.test.ts` lands anywhere
under `src/`, Vitest picks it up via the default include glob
(`**/*.{test,spec}.?(c|m)[jt]s?(x)`) and a failure fails `pnpm test`.

No new devDeps: Vitest is already installed at the workspace root
and resolves via pnpm's hoisted node_modules. No per-package
`vitest.config.ts` either — defaults handle a Node-environment unit-
test glob fine. Packages that need richer config later can add one
without touching this scaffolding.

## Verification

```
pnpm --filter @pickupvb/infrastructure test
# → "No test files found, exiting with code 0"

pnpm typecheck && pnpm lint && pnpm test && pnpm build
# → all four ✅
```

## Tradeoffs accepted

- **`--passWithNoTests`** silently passes when there are no tests.
  That's the right default for packages like `types` (pure type
  declarations — nothing to unit-test) and `config` (lint/tsconfig
  presets). It does mean a future contributor who deletes the last
  test in `notifications` won't get a CI failure for the deletion;
  acceptable trade for not blocking trivial scaffolding now.
- **No per-package `vitest.config.ts`** added in this bundle.
  `domain` / `application` / `web` have their own configs because
  they want explicit include globs / reporters. The 5 packages
  here can copy that pattern when they grow tests; no need to
  pre-create empty configs.

## Alternatives rejected

- **Add real test files alongside the script swap.** The audit P1
  is specifically about the _script_, not coverage. Writing
  meaningful adapter tests for `SupabaseEventRepository` etc. is a
  real effort (needs a Supabase test-double strategy) and belongs
  in its own bundle so the audit closure stays auditable.
- **Replace placeholder packages' `test` script with `exit 0`
  explicitly.** Same as today's echo — still green-by-accident.
  Defeats the audit fix.
- **Drop the placeholder scripts entirely and let Turborepo skip
  the task.** Would work, but explicit `vitest run --passWithNoTests`
  makes the intent obvious and means a contributor running
  `pnpm --filter X test` gets a Vitest output rather than a
  "missing script" error.
