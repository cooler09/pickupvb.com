# Bundle 46 — `co-host-actions.ts` flash-param redirects (2026-05-23)

## Context

Carried over from the 2026-05-17 architecture audit, where the
**Server-action error handling** pattern was documented in
[AGENTS.md](../../AGENTS.md) and applied to `rsvp-actions.ts`, but
[co-host-actions.ts](../../apps/web/src/app/events/%5Bid%5D/co-host-actions.ts)
was left for a follow-up sweep. Its three handlers — `addEventCoHost`,
`removeEventCoHost`, `addCoHostFromForm` — were invoked from plain
`<form action={fn.bind(...)}>` elements in
[hosts-section.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/hosts-section.tsx),
yet any `DomainError` thrown by
`handlers.addEventCoHost.execute` / `handlers.removeEventCoHost.execute`
bubbled to the React error boundary and replaced the event page with the
generic error UI. The remaining audit follow-up explicitly called this
out as the last unaligned action file on the event page.

## What shipped

- **[apps/web/src/lib/server-redirects.ts](../../apps/web/src/lib/server-redirects.ts):**
  extended the `redirectEventNotice` key union to include `'cohost'` (joining
  `'rsvp' | 'tip' | 'fa'`) so co-host actions share the same flash-param
  helper as the rest of the event page.
- **[apps/web/src/app/events/[id]/co-host-actions.ts](../../apps/web/src/app/events/%5Bid%5D/co-host-actions.ts):**
  wrapped the two handler calls in `try/catch` and added a small
  `mapErrorAndFlash(eventId, err)` helper that branches on
  `UnauthorizedError` / `NotFoundError` / `ConflictError` /
  `ValidationError` and falls through to a generic `DomainError` arm
  (passing `err.message` as the `cohost_msg` flash). Anything that isn't
  a `DomainError` is re-thrown so the React boundary still catches real
  bugs. Success path is unchanged — `revalidatePath(returnPath)` at the
  end. `addCoHostFromForm` didn't need changes because it delegates to
  `addEventCoHost`.
- **[apps/web/src/app/events/[id]/\_components/event-flash-banners.tsx](../../apps/web/src/app/events/%5Bid%5D/_components/event-flash-banners.tsx):**
  added five new `cohost` arms (`unauthorized`, `notfound`, `conflict`,
  `invalid`, `error`) using the existing `Alert` component for variant
  styling. `error` falls back to a generic message if `cohostMsg` is
  absent.
- **[apps/web/src/app/events/[id]/page.tsx](../../apps/web/src/app/events/%5Bid%5D/page.tsx):**
  passed `cohost` and `cohost_msg` from `searchParams` through to
  `EventFlashBanners`.

## Pattern notes

- **The flash-param pattern stays cheap because it composes with
  `redirectEventNotice`.** Adding a new flash key is two lines (union
  expansion + JSX arm) once the helper exists — no per-action redirect
  URL construction, no missed `redirect()` calls. Worth keeping the
  union narrow rather than letting it sprawl: each addition forces a
  conscious decision about which page renders the alert.
- **`mapErrorAndFlash` keeps the catch block from drifting.** Each typed
  `DomainError` subclass gets a specific flash code, then the
  `instanceof DomainError` fallback handles anything else throwing from
  the application layer (e.g. a future `InvariantViolation`) without
  silently turning it into a 500. Non-`DomainError` throws still bubble,
  which is the right behaviour for genuine bugs (NPEs, infrastructure
  outages) — those should hit the React error boundary, not flash.
- **Closing this follow-up unblocks the "Patterns surfaced by audits"
  section in AGENTS.md** — every reference file it cites now actually
  matches the pattern, so the next agent who reads it sees consistent
  examples in both `rsvp-actions.ts` and `co-host-actions.ts`.
