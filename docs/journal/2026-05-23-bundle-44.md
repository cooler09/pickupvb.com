# 2026-05-23 — Bundle 44: Toast focus-ring contrast — last accessibility P2

## Context

After Bundle 43 closed the combobox-pattern P2s, only one P2 was left in
the accessibility audit: the toast close button's focus ring inherited
its color from the toast foreground (`focus:ring-current`) which on
info/warning variants didn't reliably hit the 3:1 contrast threshold
that WCAG 2.4.11 (Focus Appearance, AA in WCAG 2.2) requires against the
adjacent toast surface. With this bundle, every P1 and P2 in the audit
is resolved — what remains is the P3 backlog (placeholder-as-label, a
few icon-only hit-areas, a heading sweep) and the open questions about
end-to-end AT testing and an accessibility-statement page.

## What shipped

Single-file change: [toast.tsx](../../apps/web/src/components/toast.tsx).

- Added a `VARIANT_RING_CLASSES: Record<ToastVariant, string>` map
  alongside the existing `VARIANT_CLASSES` map. Each entry pairs a ring
  color with a matching `ring-offset-<variant-bg>` so the ring reads as
  a solid 2 px outline against the toast surface rather than bleeding
  into the page behind it.
  - **error** → `ring-red-700` / `ring-offset-red-50`, dark
    `ring-red-200` / `ring-offset-red-950`.
  - **success** → `ring-emerald-700` / `ring-offset-emerald-50`, dark
    `ring-emerald-200` / `ring-offset-emerald-950`.
  - **warning** → `ring-amber-800` / `ring-offset-amber-50`, dark
    `ring-amber-200` / `ring-offset-amber-950`. (Amber-800 instead of
    amber-700 for the extra step against the warmer surface.)
  - **info** → `ring-primary` / `ring-offset-surface`. The info variant
    uses the brand primary on the brand surface, so the existing
    primary-on-surface contrast token already passes — the bundle reuses
    it rather than introducing a parallel token.
- Switched the close button from `focus:ring-*` to `focus-visible:ring-*`
  to match the rest of the repo's focus-visible standard (landed in the
  2026-05-17 ring sweep). Mouse clicks no longer paint a ring;
  keyboard-tab navigation still gets the high-contrast outline.

## Pattern notes

- **`Record<Variant, string>` map is the right shape for per-variant
  Tailwind classes.** Keeping `VARIANT_RING_CLASSES` parallel to the
  existing `VARIANT_CLASSES` makes the intent obvious at the call site
  (`${VARIANT_RING_CLASSES[t.variant]}`) and means adding a new variant
  is two map entries instead of hunting through a `clsx` ladder. The
  template-literal concat in the JSX is fine here because the variant
  is the discriminant — the value can't be missing.
- **`ring-offset-<bg>` is the part people forget.** A high-contrast
  ring with no offset (or with `ring-offset-transparent`, as before) is
  often _less_ visible than a single 2 px ring because the ring runs
  flush against the toast border. Pinning the offset to the variant's
  background gives the ring breathing room and makes it read as
  intentional UI rather than a stray outline.
- **`focus-visible` not `focus`.** This was the standard the 2026-05-17
  ring sweep established for inputs; close buttons missed that pass
  because they used the older `focus:ring-current` idiom. Catching it
  here keeps the codebase consistent — no mouse-click rings anywhere.
