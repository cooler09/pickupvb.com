# 2026-05-24 — Bundle 84: Host-owned sponsor slot v1 (Pro-only core)

## Context

After Bundle 83 closed monetization P1 #2 (buyer-paid processing fee),
the next sequenced item from the monetization audit was P2 #4:
**host-owned sponsor slot**. The key product decision was already made
in the audit and user follow-up: PickupVB should not become a third-party
ad seller; instead hosts add their own local sponsor to their own event.

Given the same-day constraints, Bundle 84 focused on the v1 core that
establishes the product surface and trust posture:

- one sponsor slot per event,
- authored only by managers of that event,
- gated as a Pro capability,
- rendered below the fold on event detail,
- with explicit sponsor labeling and `rel="sponsored noopener nofollow"`.

À-la-carte charging for free hosts was deferred as a follow-up bundle so
we could ship the behavior and evaluate host usage first.

## Decisions

- **Pro-only for v1 authoring.** This aligns with the monetization
  direction "Pro = host operating system" and avoids introducing a new
  one-off checkout flow in the first sponsor bundle.
- **RLS handles manage-permission; app layer handles Pro entitlement.**
  RLS checks "can manage this event" (host, primary-group admin, co-host).
  `hasProBenefits(user.id)` gates writes in server actions. Keeping these
  concerns separate preserves flexibility if we introduce free-tier
  à-la-carte later.
- **One slot per event, intentionally small surface.** Single sponsor,
  single logo, short blurb, optional discount code, optional external
  link. This keeps the section community-oriented instead of ad-like.
- **URL safety by schema + action validation.** Migration constrains
  `link_url`/`logo_url` to `https://`; server actions also validate
  supplied URLs so invalid values fail with clear flash messages.
- **Read model cache coherence by tag + path.** Sponsor writes call both
  `revalidatePath('/events/[id]/edit')` and `updateTag('event:[id]')`
  so edit-page and event-page renders stay in sync with the existing
  event detail caching strategy.

## Patterns surfaced

- **Entitlement vs authorization split scales better than RLS-only gating.**
  We intentionally did not encode "Pro" into SQL policies; policy remains
  manageability, while product entitlement lives in server actions.
- **Bundle-shaping by trust boundaries works.** We shipped the sponsor
  surface with strict guardrails first (single slot, explicit labeling,
  no scripts/animation), then deferred more monetization complexity.
