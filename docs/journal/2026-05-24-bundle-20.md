# 2026-05-24 — Bundle 20: SportsTeam + SportsOrganization JSON-LD

## Context

The SEO audit's last open P3 was "Add `SportsTeam` / `SportsOrganization`
JSON-LD on teams + groups detail pages." Bundle 18 had already shipped
shared `BreadcrumbList` JSON-LD across all four detail pages; this
bundle closes the matching entity-specific structured data on the two
routes that have schema.org analogues. Events already emit a rich
`SportsEvent` block; players have no clean schema.org type, so they
stay breadcrumb-only.

## Decisions

- **Co-located per-route components, not a shared abstraction.** The
  two schemas (`SportsTeam` vs. `SportsOrganization`) differ enough in
  fields — teams expose `numberOfPlayers`, groups expose `address` +
  `logo` — that a shared component would be mostly conditional. The
  existing `EventJsonLd` lives co-located under
  `events/[id]/_components/` for the same reason; matched that pattern.
- **`SportsTeam`: `numberOfPlayers = activeCount + extraMembers`.**
  Schema.org's `numberOfPlayers` counts the roster, not just signed-up
  app users — including the captain's off-site additions reflects the
  real team size.
- **`SportsOrganization`: no `numberOfEmployees`.** It's the only
  schema.org "member-count-ish" field on Organization, but its
  semantics are payroll, not community membership. Better to omit than
  to mis-signal.
- **Optional fields use the spread pattern.** `exactOptionalPropertyTypes`
  means `logo: avatarUrl ?? undefined` would type-error; both
  components use `...(avatarUrl ? { logo: avatarUrl } : {})` per the
  AGENTS.md convention.
- **`description` capped at 500 chars on groups.** Long-form group
  descriptions exist; Google truncates JSON-LD descriptions around
  there anyway. Keeps payload small.
