# 2026-05-24 — Bundle 87: Host analytics dashboard (Pro feature)

## Context

After Bundle 86 (saved templates), the next monetization-sequenced item
from [docs/audits/monetization.md](../audits/monetization.md) was
P1 #1 sub-item #2: **host analytics dashboard**.

Goal for this bundle: ship a practical, Pro-gated v1 with host-facing
metrics that justify subscription value independent of fee savings.

## Decisions

- **Chose `/profile/billing/analytics` as the route** over a standalone
  top-level profile tab because the metric set is monetization-adjacent
  and naturally grouped with earnings/payout surfaces.
- **Chose Pro gating at page level with in-page upsell** so non-Pro hosts
  can discover the feature and upgrade immediately without 404/redirect
  confusion.
- **Chose v1 metrics from existing tables** (`events`, `event_attendees`,
  `event_divisions`, `event_payment_audit`) to avoid adding migrations or
  delayed ETL work.
- **Deferred no-show rate** because there is no explicit check-in model;
  surfacing a guessed no-show metric would be misleading.

## Patterns observed

- **React purity lint in Next server components still matters.**
  `Date.now()` in render paths triggers `react-hooks/purity`; avoid
  render-time clock reads and derive stats without impure calls.
- **Monetization bundles are easier to ship safely when they piggyback on
  existing trusted tables and policies** rather than introducing new schema
  in the same iteration.
