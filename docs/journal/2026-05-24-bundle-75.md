# 2026-05-24 — Bundle 75: PostHog analytics adapter + first server-side captures

## Context

The repo had no first-party product analytics — only Vercel Analytics
(page views + Web Vitals) and Sentry (errors). That left us blind on the
questions that matter for both product iteration and ad/sponsor pitches:
how many events are published per metro per week, what fraction of
viewers RSVP, where the funnel leaks between event_view and
event_joined, and what the activation curve looks like for new hosts.

The user asked for an analytics audit + step-by-step implementation
("option C"). This bundle ships the minimum scaffolding to start
collecting first-party events without coupling the app to any one
vendor.

## Decisions

- **Hexagonal: domain owns the port, infrastructure picks the
  vendor.** `AnalyticsPort` lives in `packages/domain/src/shared/`
  alongside `result.ts` and `DomainError`. The event payload is a
  closed discriminated union (`AnalyticsEvent`) so handlers cannot
  emit untyped events. Swapping PostHog for Segment / Rudderstack /
  a homegrown event store later is a one-file change.
- **PostHog over Segment/Mixpanel.** Self-hostable, generous free
  tier, native session replay + feature flags, and the OSS SDK
  (`posthog-node`) has good Node 22 support. The audit lists the
  trade-offs (P3 #12 retires Vercel Analytics once PostHog covers
  page-view + web-vitals capture).
- **Hash actor ids with a server-side salt.** We never send the raw
  Supabase `user.id` to PostHog. The adapter sha256-hashes
  `salt + ':' + userId` before each `identify` / `capture`. The salt
  lives in `POSTHOG_DISTINCT_ID_SALT` (regenerated yearly = forced
  re-anonymization). This costs us cross-device join in PostHog but
  keeps the distinct-id surface non-reversible if PostHog is ever
  breached.
- **Fail-open everywhere.** Every adapter method wraps the SDK call
  in a try/catch and logs at `console.warn`. Analytics must never
  break a request — if PostHog is down, the user still creates the
  event / RSVPs.
- **Noop fallback resolved at boot.** When `POSTHOG_API_KEY` or the
  salt is missing, `analyticsFromEnv()` returns `NoopAnalytics`. Local
  dev and PR previews therefore have zero analytics traffic by
  default; only Production sets the env vars.
- **`flushAt: 1`, `flushInterval: 0`.** PostHog's default batching
  doesn't survive serverless function freeze — events queued but not
  flushed are dropped. Flushing per-capture loses some throughput but
  guarantees delivery in the Vercel runtime. Acceptable for our
  volume.
- **Two captures this bundle, not seven.** `event_published` (from
  the create-event server action) and `event_joined` (from both
  `joinEvent` and `joinEventAtPosition` in `rsvp-actions.ts`) are
  the two events that unlock the most analysis surface for the
  least integration risk. The other five (`event_left`,
  `checkout_started`, `checkout_completed`, `signup_completed`,
  `host_payout_setup_completed`) are scaffolded in the taxonomy
  and will land in follow-up bundles as each touchpoint is audited.

## Patterns surfaced

- **Hexagonal pays off again.** Adding analytics didn't touch
  `application/` at all — handlers stay framework-free, and the
  composition root is the only place that knows PostHog exists. New
  captures slot in at the server-action layer next to
  `revalidatePath()` calls, which is exactly where mutating
  business events already live.
- **`flushAt: 1` is the right default for Vercel serverless.** Any
  future SDK adapter (Segment, Rudderstack) needs the same setting
  — leaving batching enabled silently drops events between cold
  invocations.
- **Per-action mini-loaders.** Rather than threading event metadata
  through the join command result, `captureEventJoined()` does its
  own narrow `select host_id, location_city,
event_divisions(price_cents, sort_order)` query. This keeps the
  domain command's return shape unchanged and means future
  captures can pull whatever fields they need without churn at the
  port boundary.

## Follow-ups deferred

All tracked in `docs/audits/analytics.md`:

- **P1 #3 — UTM + referrer attribution.** Need a `/r/[shortId]`
  middleware that strips UTM params into a first-party cookie
  before passing through. Not in this bundle.
- **P1 #4 — PII guardrails for traits.** `AnalyticsTraits` is
  allowlisted, but there's no runtime assertion that nothing else
  ever reaches `identify(...)`. Add a Vitest in
  `packages/domain/` that exhaustively checks the union once the
  trait surface grows past the current four fields.
- **P2 #5 — Consent banner.** Bundle 75 is server-side only, so
  no browser consent is collected yet. Becomes blocking the moment
  we add a browser SDK (page views, session replay, feature flags).
- **P2 #6 — Domain-event outbox.** Capturing from the action layer
  is the pragmatic path for two events; long-term we want a
  durable outbox seeded by `EventPublished` / `SpotFilled`
  domain events so analytics ships even when the request crashes
  after the DB write.
- **P2 #7 — Marketable SQL views.** `/about/numbers` page with
  `metro_health_weekly` / `host_activity_monthly` /
  `position_demand_weekly` views is the public dataset deliverable
  for sponsors. Schema is sketched in the audit; not yet built.
- **P2 #8 — Web-vitals → PostHog bridge.** Currently goes to
  Vercel only.
- **P2 #9 — Cohort dashboard.** First-host-event activation curve
  by metro. Pure PostHog config, not code.
- **P3 #10–#12 — Salt rotation runbook, A/B framework, Vercel
  Analytics retirement.**
