# Bundle 127 — Bracket creator polish + site-wide CTA vocabulary (2026-05-27)

## Context

User started with "improve the UX on the bracket creator: move important
stuff up and emphasise CTAs." Shipped that, then asked "any other areas
on the site that can use UX updates?" — quick scan surfaced a forked
primary-CTA vocabulary, several muted-text empty states with no actual
button, and secondary-styled filter "Search" buttons.

This bundle ships both halves: the bracket creator polish first
(targeted), then the site-wide CTA-vocabulary sweep (cross-cutting).

## Decisions

### Bracket creator (half 1)

- **Promote primary CTAs from `px-3 py-1` to `px-4 py-2 font-semibold`**
  in [no-bracket-view.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/no-bracket-view.tsx),
  [setup-view.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/setup-view.tsx),
  and [format-picker-form.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/format-picker-form.tsx).
  These are the headline actions the host came to perform — they were
  the smallest buttons on the screen.
- **Sticky bottom action bar on the format picker** (`sticky bottom-2
z-10`) so "Create bracket" + the estimated-match-count hint stay
  visible while the host browses long format cards and pool options.
  Rejected: floating overlay (too heavy for a form). Rejected: moving
  the button to the top (loses the "informed decision after reading
  cards" affordance).
- **Top action card in SetupView** with "Generate bracket" hoisted
  above the seeding list. Rationale: seeding is rarely tweaked from
  the default randomized order, but the host always has to scroll
  past it to ship. Putting the primary action above the fold with a
  readiness summary (format + team count) inverts the priority.
- **Walk-in form collapsed into `<details>` with `open={!ready}`** —
  the escape hatch auto-opens when the host can't generate yet (i.e.
  when adding a walk-in is the unblocking action). Otherwise it stays
  out of the way. Applied to both `NoBracketView` and `SetupView`.
- **Readiness chip on `NoBracketView` header** ("8 teams · ready" /
  "1 team · need ≥ 2"). Pulls the gating constraint out of the
  scattered hint text below the disabled CTA and surfaces it as a
  status pill next to the heading.

### Site-wide CTA vocabulary (half 2)

- **Extracted [apps/web/src/components/primary-button.tsx](../../apps/web/src/components/primary-button.tsx)**
  — `primaryButtonClass(size?)` className helper + thin `<PrimaryButton>`
  wrapper for the `<button>` case. Two sizes:
  - `'sm'` (default): `px-3 py-1.5 text-sm` — list-row / header /
    in-line CTA.
  - `'md'`: `px-4 py-2 text-sm` — headline panel action.
- **Helper, not a wrapper component**, because consumers vary by
  element type (`<Link>` from next, `<a>` for external, `<button>`,
  our `<SubmitButton>` from form-status). A wrapper for each would
  force a discriminated union we don't need; a className spread is
  what every call site actually wants. Kept the `<PrimaryButton>`
  wrapper as a convenience for the simple `<button>` case.
- **Migrated 5 divergent sites** on the events surface — see audit
  status update for the list. Two of them were `text-xs` (Record
  winner, Generate playoff); bumping to `text-sm` was a free
  readability + tap-target win and stays consistent with the rest
  of the vocabulary.
- **Empty-state CTAs.** [/groups](../../apps/web/src/app/groups/page.tsx#L86)
  and [/teams](../../apps/web/src/app/teams/page.tsx#L126) empty
  states swapped a muted `<p>` for a centered card with a headline
  copy line, a `text-muted` nudge, and the actual create CTA. For
  `/groups`, used the existing `NewGroupButton` (self-hides for
  signed-out viewers) so the button only appears to people who can
  act on it; for `/teams`, linked directly to `/teams/new` (the page
  handles unauth redirect to `/login?next=/teams/new`). Same treatment
  on `my-teams-panel.tsx` "You don't captain any teams yet."
- **Filter-form "Search" buttons** on `/groups` + `/teams` promoted
  from `border-border-base hover:bg-fg/5` (secondary) to
  `primaryButtonClass()`. They were the primary action of the form
  but read as ghost buttons.

## Rejected alternatives

- **A full `<Button variant=primary|secondary|destructive>` design
  system component.** Overkill for the actual divergence — there are
  ~5 hand-rolled primary sites that need normalizing, not a full
  reset of the button vocabulary. The className helper is a smaller
  blast radius and lets the audit catch new drift the same way.
- **Adding empty-state CTAs to `/events`.** That page already has
  a `+ Host event` CTA in the header (from earlier UX work) and the
  empty state correctly differentiates "no events match your filters"
  from "no events at all" with a meaningful message. Left alone.
- **Site-wide tap-target bump (mobile).** Position-rsvp-panel mini
  buttons (`text-xs`) were called out in the quick scan but left for
  a focused mobile pass — touching every list-row button would
  reshuffle layouts and want a Playwright sweep.

## Patterns observed

- **CTA vocabulary forks silently.** Hand-rolled `bg-primary …` class
  strings drift over time as new components copy a nearby button
  instead of importing the established class. The
  `primaryButtonClass()` helper is the right shape — one source of
  truth, spreadable onto any element type, easy to grep for new
  hand-rolled offenders. Promoted into the bundle list of standard
  primitives implicitly via this entry; if the helper gets a sibling
  (secondary, destructive), reconsider promoting into AGENTS.md.
- **Empty states are conversion surfaces.** The "no X yet" moment is
  the highest-intent moment in the user journey — they searched, the
  search returned nothing, they're now waiting for an instruction.
  Muted gray text is the wrong answer; even when the CTA is already
  in the page header, repeating it inline lifts conversion.
- **Disclosure widgets (`<details>`) want readiness-aware defaults.**
  The pattern from the bracket walk-in (`open={!canGenerate}`) is
  reusable: collapse the secondary form when the host is on the happy
  path, auto-open it when the secondary form is the unblocking action.
