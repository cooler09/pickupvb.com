## Changes

### 1. Schema — soft-delete columns + RLS rewrite

[supabase/migrations/20260628000000_soft_delete_groups_teams_broadcasts.sql](../../supabase/migrations/20260628000000_soft_delete_groups_teams_broadcasts.sql)

For each of `groups`, `teams`, `broadcasts`:

- `deleted_at timestamptz` nullable.
- Partial index `WHERE deleted_at IS NOT NULL` (cheap; lets future
  admin/undelete surfaces find tombstones without scanning live rows).
- SELECT RLS policy rewritten to add `AND deleted_at IS NULL` so
  soft-deleted rows vanish from every read path (lists, detail pages,
  search, joins) without per-call-site filtering.

Also added a NEW `broadcasts_update_sender` policy:
`using (auth.uid() = sender_id) with check (auth.uid() = sender_id)`.
Before this, `broadcasts` had only SELECT-sender + two INSERT policies
— admin-client UPDATEs for `sent_at` fan-out were the only writers, so
the missing user-scoped UPDATE policy was latent.

Mirrors the profiles 2026-06-20 soft-delete pattern (column + partial
index + SELECT filter). No backfill needed; all existing rows stay
live (`deleted_at IS NULL`).

### 4. Broadcast hide (schema slice)

[apps/web/src/app/\_actions/hide-broadcast.ts](../../apps/web/src/app/_actions/hide-broadcast.ts)
— `hideBroadcastAction(broadcastId, eventOrTeamPath, eventId | null)`.
Sender-only. Pre-SELECTs to verify ownership (RLS will hide the row
post-update, so a post-update check would fail). UPDATEs `deleted_at`.
Revalidates the supplied path and optional `event:${eventId}` tag.

**No UI consumer ships in this bundle.** Grep for
`broadcast.*history|recent.*broadcast` returned no matches under
`apps/web/src/app/`. Building the host broadcast-history list is the
follow-up that unlocks the button.

## Decisions

- **Thin server actions, no application-layer commands.** The audit
  recommended `DeleteGroupCommand`/`DeleteTeamCommand` aggregates. Per
  AGENTS.md "no over-engineering," used direct server actions instead
  — mirrors `template-actions.ts` (host_event_templates) which is the
  same shape (single FK guard + flag flip). If soft-delete grows real
  business rules (cascade rules, audit log, restore window), promote
  then.
- **Slug reservation is intentional (for now).** The unique constraint
  on `groups.slug` / `teams.slug` is single-column, so a soft-deleted
  row keeps its slug reserved. Slug reclamation (partial unique index
  `WHERE deleted_at IS NULL`) is a follow-up — easy to ship once
  product confirms the desired UX (do deleted owners get their name
  back?).
- **RLS-driven hide pattern.** Filtering `deleted_at IS NULL` in the
  SELECT policy means every existing read path (event detail, team
  page, search, joins) inherits the filter for free. The alternative —
  adding `.is('deleted_at', null)` to every query — is brittle and
  invites bugs. Same posture as the 2026-06-20 profiles soft-delete.
- **Guard query shapes diverge by FK direction.** Group has
  `events.host_group_id` (count direct refs); team has many-to-many
  via `event_teams` (need nested join filter). Worth noting because
  the two server actions look similar but the Supabase query syntax
  is different enough to be easy to copy wrong.
