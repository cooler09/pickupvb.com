# 2026-05-24 — Bundle 86: Saved event templates (Pro host feature)

## Context

Monetization Bundle 85 closed the sponsor-slot follow-up (P2 #4). The
next sequenced monetization item was P1 #1 sub-item #1 from
[docs/audits/monetization.md](../audits/monetization.md): **saved event
templates** to increase Pro value for serial hosts below the fee-savings
break-even.

The goal for this bundle was a practical v1 in `/events/new`: hosts can
save a form snapshot as a named template, then re-apply it later and tweak
before publishing.

## Decisions

- **Chose host-scoped templates table over global/shared templates** because
  this is primarily a host workflow accelerator and avoids new sharing/ACL
  complexity in v1.
- **Chose Pro gating at save-time** (instead of apply-time) because applying
  should remain a read interaction; value capture is in authoring the
  reusable template.
- **Chose query-param apply flow on `/events/new`** so template selection
  works with server-rendered page data and keeps client logic simple.
- **Chose payload as form-value snapshot (`jsonb`)** to ship quickly and
  preserve flexibility while the event form evolves.

## Patterns observed

- **`exactOptionalPropertyTypes` keeps forcing safer prop wiring.** Passing
  optional values from page to form should use conditional spreads,
  especially for query-driven values.
- **Large form patches are safer as small context-targeted edits.** Attempting
  a monolithic patch on `new-event-form.tsx` was fragile; incremental hunks
  were faster and more reliable.
