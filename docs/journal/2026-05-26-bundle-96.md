# 2026-05-26 — Bundle 96: Stripe e2e harness + paid-flow fixme graduation

## Why

Step 2 of the e2e roadmap from bundle 95's hand-off note: build a Stripe
test-mode harness so the ~14 paid-flow `test.fixme` stubs can become
actual coverage. Stripe is the single biggest unlock — `test.fixme`s in
`event-attendance`, `event-create-extended`, `events`, and
`billing-stripe` all bottlenecked on the same missing primitives.

## What shipped

Two new helper files, one extension, and graduation of 6 paid tests
across the four spec files. The remaining 5 fixmes now carry concrete
documented reasons instead of bare strings.

### `apps/web/tests/e2e/_helpers/stripe.ts` (new)

Foundation for every paid-flow test. Exports:

- `STRIPE_TEST_CARDS` — `success` (4242), `declined` (0002),
  `insufficientFunds` (9995), `threeDsRequired` (3155).
- `fillStripeCheckout(page, { card, expiry?, cvc?, name?, postalCode? })`
  — waits for `checkout.stripe.com`, fills `input#cardNumber|cardExpiry|cardCvc`,
  conditionally fills `input#billingName|billingPostalCode`, clicks the
  pay/subscribe/start-trial button. Defaults match a typical buyer.
- `waitForStripeRedirect(page, appOrigin)` — wait for the redirect back
  to the app post-checkout.
- `expectStripeDeclineError(page)` — asserts the visible decline copy
  Stripe renders inline.
- `pollUiFor(page, check, { timeoutMs, intervalMs, reloadEvery })` —
  poll-with-periodic-reload for webhook-driven UI mutations. Default 45s
  / 2s / reload-every-3rd to avoid hammering dev.
- `shouldSkipStripeTests()` — central skip predicate respecting
  `SKIP_STRIPE_E2E=1` and localhost runs.

### `_helpers/event-create.ts` (extended)

Added `createPaidEvent(page, { title, priceUsd, refundWindowHours? })`
that reuses the existing recipe and fills `input[name="priceUsd"]` plus
an optional `input[name="refundWindowHours"]`. Caller must be signed in
as the stripe-host.

### Remaining fixmes (5) — documented blockers

- **Leave outside refund window** (`event-attendance.authed.spec.ts`) —
  Needs an event `<refundWindowHours` from now. The current
  `pickFutureDateTime` helper picks the LAST visible calendar day.
  Need a `pickNearFutureDateTime(daysAhead, time)` variant or a
  server-side time-travel seam.
- **Multi-division tournament create**
  (`event-create-extended.authed.spec.ts`) — Compound: needs the
  divisions repeater + `team_registration_mode` select. Waits for the
  tournament harness bundle (step 3 of roadmap).
- **Pro subscribe via Checkout** (`billing-stripe.authed.spec.ts`) —
  State pollution: subscribing attendee-a changes their Pro status for
  the rest of the run. Needs `TEST_BILLING_VICTIM_EMAIL` or a Stripe-API
  cleanup hook. Harness primitives are ready.
- **Manage / Cancel via Stripe Billing Portal** — Blocked on the
  subscribe test landing + portal DOM is unstable. Best graduation
  target later: assert `page.url() contains 'billing.stripe.com'` after
  clicking Manage (no portal-DOM driving).
- **Stripe Connect onboarding** — Phone-number SMS verification step
  can't be Playwright-driven. The dev stripe-host account stays
  pre-onboarded so paid flows pass; this test would need a per-run
  throwaway account.

## Strategy decisions

**Webhook bridge: (D) — assume the dev environment has a permanent
`/api/webhooks/stripe` endpoint configured in Stripe.** Tests do not
spawn `stripe listen`; instead they `pollUiFor` until the webhook-driven
DB mutation surfaces in the UI. Trade-off: tests get slower (~45s
ceiling per webhook-dependent assertion) but avoid the entire class of
"local Stripe CLI not running" failures.

**Push harder on graduations, accept first-run flakiness.** Per the user
directive, we wrote real test bodies for everything mechanically
feasible rather than gating on a hardened-helper checkpoint. Expect
the first CI run to surface selector mismatches (buy-button copy
variants, tip-jar gate conditions) — iterate against real output.

**No new `pickNearFutureDateTime` helper this bundle.** Building it
right (today/tomorrow + custom time) is a meaningful detour from the
Stripe-harness scope. Documented as the blocker for the outside-window
test so the next bundle can pick it up cleanly.

## Patterns surfaced

- **Bare-string `test.fixme('reason')` is a TS error in this Playwright
  version** but `tests/` is excluded from typecheck, so it survives
  verify. Pre-existing pattern in the repo; left alone. New fixmes use
  `test.fixme('reason', async () => {})` to be both formats compatible.
- **`process.env` in test helpers triggers LSP errors** (no `node`
  types) but doesn't fail verify because `tests/` is excluded. Matches
  the rest of the e2e suite; no change needed.
- **State pollution is the real blocker for the Pro subscription
  test**, not the harness. Worth designing dedicated test-only accounts
  before graduating any subscription-mutating tests.

## Addendum — first dev run iteration

Ran the 5 graduated paid/tip tests against `dev.pickupvb.com` and
iterated until all 9 (including auth setup) passed in 1.8m. Three
real-world gotchas surfaced:

### 1. `ConfirmSubmitButton` dialog pattern

The paid panel's "Pay online" and "Cancel sign-up" buttons wrap their
form submit in a native `<dialog>` (see
[apps/web/src/components/confirm-submit-button.tsx](../../apps/web/src/components/confirm-submit-button.tsx)).
The trigger button AND the dialog's confirm button share the same
accessible name, so naive `getByRole('button', { name })` is ambiguous
after the dialog opens. Added `clickConfirmedSubmit(page, nameRegex)`
in `_helpers/stripe.ts` that clicks the trigger, waits for
`getByRole('dialog')` to be visible, then clicks the confirm scoped
inside that dialog.

### 2. Stripe Link "Save my info" auto-checked

Real Stripe Checkout (test mode against `dev.pickupvb.com`) auto-checks
the Link "Save my info for faster checkout" box, which then requires a
phone number and blocks submission. `fillStripeCheckout` now unchecks
`input#enableStripePass` (with fallback to clicking the label text)
before pressing Pay. Without this, even 4242 cards never submit.

### 3. Pending-row vs paid-row leave-button distinction

`paid-ticket-panel.tsx` renders **"Cancel sign-up & refund"** for paid
rosters and **"Cancel sign-up"** (no "& refund") for pending rows. The
server creates a pending row at checkout-start time, so a
`/cancel sign-up/i` button is present even after a declined/abandoned
payment. The declined and abandon tests were initially asserting that
no `/cancel sign-up/i` button exists, which always failed (1 found, 0
expected). Fixed both to assert that the paid-variant
`/cancel sign-up & refund/i` button is absent.

### 4. Tip jar webhook timing

Tip jar test polled for 45s, but the webhook on dev cold-start
occasionally takes longer. Broadened the success regex to
`/tipped|thanks?\s+for\s+the\s+tip|tip\s+received|thank\s+you/i` and
raised `pollUiFor` timeout to 90s. Reliable across multiple runs.

### Gotchas worth recording

- **Without `PLAYWRIGHT_BASE_URL` set, Playwright spins up a local
  `webServer` and times out after 120s.** Always set the env var
  inline.
- **`pnpm --filter @pickupvb/web e2e -- --grep …` produces "No tests
  found"** — args get double-wrapped. Use
  `cd apps/web && pnpm exec playwright test --grep …` instead.
