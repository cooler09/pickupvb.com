# 2026-05-22 — Bundle 29: pre-commit hooks, dep-pin cleanup, `--webpack` documented

## Context

The organization audit's Bundle 28 closed P1 #2 (test scripts). The
remaining backlog was a cluster of P2 items, several of which were small
enough to bundle: pre-commit hooks (husky + lint-staged), inconsistent
dependency pinning, and the long-standing "why is `apps/web` forcing
`--webpack`?" question. User picked the multi-P2 option for this pass.

## What shipped

**(a) Pre-commit hooks — `husky` + `lint-staged`.**

- `pnpm add -D -w husky lint-staged` (v9.1.7 / v17.0.5).
- Root `package.json` gained `"prepare": "husky"` so the git hook is
  installed automatically on `pnpm install`.
- `pnpm exec husky init` created `.husky/pre-commit`; the default
  `pnpm test` body swapped for `pnpm exec lint-staged`.
- Root `package.json` `lint-staged` config: `prettier --write` over
  staged `*.{ts,tsx,js,jsx,mjs,cjs,json,md,css,yml,yaml}` files.

**(b) Dependency pinning normalized to caret form.**

- `@types/node`: `"25"` → `"^25.8.0"` in `application`, `infrastructure`,
  `notifications`, `supabase`.
- `typescript`: `"6"` → `"^6.0.3"` in `config`.
- All other packages already used caret; nothing else changed.

**(c) `--webpack` flag documented (not dropped).**

- First attempt: dropped `--webpack` from `apps/web/package.json` `dev`
  and `build`. Build failed:
  ```
  ⨯ This build is using Turbopack, with a `webpack` config and no `turbopack` config.
  ```
- Root cause: `next.config.mjs` has a `webpack(config)` callback that
  installs `config.resolve.extensionAlias = { '.js': ['.ts', '.tsx', '.js'], … }`
  so NodeNext-style `.js` import specifiers resolve to TS sources in the
  workspace packages. Turbopack ignores `webpack()` callbacks entirely,
  so dropping the flag breaks the first cross-package import that ends
  in `.js`.
- Reverted the flag and added a comment block above `webpack(config)`
  in `next.config.mjs` explaining the constraint and pointing back to
  the audit entry.

## Tradeoffs accepted

- **ESLint excluded from `lint-staged`.** ESLint v9 flat config discovery
  walks up from the cwd, not the file path; per-package
  `eslint.config.mjs` files don't resolve when lint-staged invokes
  `eslint` from the repo root over arbitrary cross-package paths. The
  attempted `eslint --fix` step produced the v9 "no config found" error
  even when targeting a known-good file. Options considered:
  - Add a root `eslint.config.mjs` that re-exports the shared base.
    Rejected — it would shadow `apps/web`'s Next-aware config (its
    flat config extends `next/core-web-vitals`, which the base doesn't).
  - Have lint-staged shell out to per-package `pnpm --filter X lint`.
    Rejected — needs a path-to-package mapping, brittle.
  - Drop ESLint from pre-commit, keep `pnpm lint` enforcement in CI.
    **Accepted.** CI still catches violations; pre-commit catches
    format drift, which is the more common nuisance.
- **Pre-commit hook is prettier-only, not the full verify quad.** A
  full `pnpm typecheck && pnpm lint && pnpm test` on every commit
  would punish iteration. CI is the right place for that.
- **`--webpack` stays.** The audit's preferred fix was "drop it";
  the audit's secondary fix was "add a comment explaining why" — we
  shipped the secondary. Full Turbopack migration is a bundle of its
  own (needs `turbopack.resolveExtensions` config equivalent + a sweep
  of every workspace-internal import specifier to make sure none rely
  on the webpack-only alias semantics).
- **Pinning convention not yet documented in AGENTS.md.** Caret is now
  the de facto convention but the audit's "document in AGENTS.md"
  recommendation is deferred to the next time someone edits that file.

## Alternatives rejected

- **`pre-push` hook running `pnpm typecheck && pnpm lint && pnpm test`.**
  Tempting but pushes are less frequent and CI gates merges anyway.
  Adds friction without commensurate value.
- **Switch to Biome for pre-commit format+lint.** Single-binary
  formatter+linter would sidestep the flat-config discovery issue,
  but swapping Prettier+ESLint is a much bigger decision than this
  bundle.

## Follow-ups deferred

- Full Turbopack migration for `apps/web` (P2 `--webpack` flag — only
  the documentation step landed; the actual flag removal is blocked
  on a `turbopack.resolveExtensions` equivalent for the workspace
  `.js` → `.ts` aliasing).
- Issue templates + CODEOWNERS (P2 — only PR template has shipped).
- Remote Turbo cache via Vercel (P2 — needs CI secret + `turbo.json`
  signature config).
- Pinning convention sentence in AGENTS.md.
