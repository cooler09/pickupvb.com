# Bundle 106 — Bracket: drag-to-reorder seeding

## Why

Continuing the bracket sweep. Today the seeding list is a static
`<ol>` — order is fixed by whatever the server returns; the host's
only reorder tools are the **Randomize** button (server-side shuffle)
or hand-editing the URL. Hosts who want a specific seed order (e.g.
"this is the #1 seed because they won last week") have to randomize
until lucky.

Plain HTML5 drag-and-drop is enough — no dnd-kit / react-dnd
dependency needed for ~16 items max per division. Add arrow buttons
alongside so touch + keyboard users get the same affordance.

## What changed

### Seeding list became a client island

- **NEW** [apps/web/src/app/events/[id]/bracket/\_components/seeding-list.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/seeding-list.tsx).
  `'use client'`. Local `useState<Team[]>` holds the current order;
  HTML5 `draggable` + `onDragStart`/`onDragOver`/`onDrop` handlers
  - ↑/↓ buttons drive reorders. Renders one hidden
    `name="team_id"` input per team in state order — the parent
    server-action form (`seedBracketFromForm`) keeps reading
    `formData.getAll('team_id')` unchanged.
- **REMOVED** the inline `SeedingList` function in
  [apps/web/src/app/events/[id]/bracket/\_components/setup-view.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/setup-view.tsx),
  imports the new client component, and **keys it by the joined
  team-id sequence** so a server-driven reorder (Randomize button,
  newly added walk-in team) re-mounts the component and resyncs
  state with fresh props.

### A/B affordances

- **Drag handle** (6-dot grip icon) on the left — `cursor-grab` /
  `cursor-grabbing`, visual feedback via `opacity-40` on the
  dragged row and a dashed primary border on the drop target.
- **↑ / ↓ buttons** on the right — disabled at the ends. Carry
  `aria-label`s ("Move {name} up/down") so screen readers
  announce the action with context.

The dataTransfer setup includes `setData('text/plain', t.teamId)`
because Firefox refuses to start a drag without it; effectAllowed
and dropEffect are both `'move'`.

## Patterns observed

- **Keyed client islands resync cleanly with server-driven prop
  changes.** Without the `key={teams.map(t => t.teamId).join(',')}`,
  hitting Randomize would shuffle the DB but leave the client
  showing stale local state. Forcing a remount on sequence change
  is one line and avoids a useEffect-sync dance. The trade-off:
  any pending drag is cancelled by a randomize — acceptable, since
  the host explicitly asked for a new order.
- **HTML5 drag-and-drop is fine for short lists.** ~16 max per
  division, all visible in one viewport, no nested or
  cross-container moves. Reaching for dnd-kit here would have
  added ~30KB gzipped and a `DndContext` provider for zero
  functional gain. The reusable bit (grip icon + arrow buttons +
  hidden inputs) is ~120 LOC of plain React.
- **Server action contract unchanged.** The reorder is local-only
  until submit; the action still reads `getAll('team_id')` and
  doesn't know whether the order came from drag, arrows, or
  randomize. Worth aiming for when adding client UX on top of a
  form — it keeps the action testable in isolation and means a
  no-JS browser still works (you just lose reordering).

## Follow-ups deferred

- **Keyboard drag.** Arrow buttons cover keyboard reorders, but a
  proper `aria-pressed` "pick up + place" flow with arrow keys
  (cf. dnd-kit's KeyboardSensor) would be more discoverable.
  Defer unless an accessibility audit flags it.
- **Touch drag refinement.** HTML5 drag-and-drop works on touch
  but is finicky on iOS without long-press. The ↑/↓ buttons are
  the recommended touch path; revisit if telemetry shows hosts
  reaching for arrows exclusively on mobile.
- **Inline seed-number edit.** Some hosts may want to type "5" to
  jump a team to seed 5. Probably overkill for ≤16 teams; revisit
  if division sizes grow.
- **Persist on each reorder (autosave).** Today reorders are
  ephemeral until **Save seeding** is clicked. Autosave would
  eliminate a click but also remove the natural batching that
  matches the rest of the form. Keeping the explicit save.
