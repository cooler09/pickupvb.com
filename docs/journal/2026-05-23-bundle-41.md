# 2026-05-23 — Bundle 41: FieldError accessibility sweep complete

## Context

Bundle 2 (2026-05-22) extracted the shared `FieldError` + `fieldA11y`
primitive into [field-error.tsx](../../apps/web/src/components/field-error.tsx)
and migrated two forms (`new-team-form`, `new-group-form`) as a
proof-of-pattern. The accessibility audit's P2 finding tracked the
remaining four forms — `new-event-form`, `edit-event-form`,
`community-listing-form`, `community-listing-edit-form` — as a
follow-up sweep. This bundle finishes the migration so every
`useFormState` form in the app emits `aria-invalid` +
`aria-describedby` on inputs that have a matching `<FieldError>`.

## What shipped

For each of the four forms:

1. Imported `{ FieldError, fieldA11y }` from
   `@/components/field-error`.
2. Deleted the local shadowing `FieldError` function declaration and
   the now-orphaned `errorClass` constant.
3. Spread `{...fieldA11y('<name>', state.fieldErrors)}` on every
   `<input>` / `<textarea>` / `<select>` that has a matching
   `<FieldError name="<name>">` sibling.

Files touched:

- [apps/web/src/app/events/new/new-event-form.tsx](../../apps/web/src/app/events/new/new-event-form.tsx)
  — the heaviest of the four (1115 LOC). Wired 14 inputs across
  basics, address, visibility, capacity, pricing, and the open-play
  / tournament / external sub-bodies. Both `surface` selects (open
  play body + external fields body) and the nested `SkillTierSelect`
  helper all get the spread.
- [apps/web/src/app/events/[id]/edit/edit-event-form.tsx](../../apps/web/src/app/events/[id]/edit/edit-event-form.tsx)
  — wired title, maxSpots, addressLine.
- [apps/web/src/app/community/new/community-listing-form.tsx](../../apps/web/src/app/community/new/community-listing-form.tsx)
  — wired title, description, externalUrl, externalHostName, and
  all 5 address fields.
- [apps/web/src/app/community/[slug]/edit/community-listing-edit-form.tsx](../../apps/web/src/app/community/[slug]/edit/community-listing-edit-form.tsx)
  — same field set as the new form.

`DateTimePicker`-backed `startsAt` / `endsAt` `<FieldError>` calls
were left alone — the picker exposes no input ref to receive ARIA
attributes, so wiring it requires component-level support tracked
under the existing "datetime picker `aria-expanded`, Escape, return
focus" P2.

The compound `positionRoster` `<FieldError>` in `new-event-form` was
also left without a per-input spread — it summarises a set of six
position inputs and there's no single boundary control to attach to.

## Pattern notes

- **Extract the primitive first, sweep second — in a separate
  bundle.** Bundle 2 only migrated two forms when it shipped the
  shared `FieldError`. That looked half-done at the time, but it
  was the right call: the primitive needed at least one real second
  consumer before its API was locked in (the `fieldA11y` helper
  shape, the `id` convention, the `role="alert"` on the rendered
  `<p>`). Bundle 41 confirmed the API survives contact with the
  more complex forms — nested sub-components passing `fieldErrors`
  down, dotted field names like `location.addressLine`, name
  mismatches like `priceCents`-error-on-`priceUsd`-input — without
  needing changes to the primitive.
- **Mechanical sweeps deserve their own bundle.** Mixing this with
  another audit topic would have made the diff hard to review.
  4 form files, 1 primitive consumed, no other behaviour changes —
  exactly the kind of change you want to land in isolation so the
  next person reading `git log` can tell at a glance what it does.
- **Some `<FieldError>` calls have no input to attach to.**
  Compound errors (`positionRoster` summarising six inputs) and
  component-encapsulated controls (`DateTimePicker`'s hidden input)
  are the two patterns. Leaving the `<FieldError>` text in place
  without wiring is correct — the audit asks for ARIA on inputs,
  not for wrappers around every error message.
