# Bundle 97 — e2e fixme triage follow-up to bundle 96

## Why

After bundle 96 graduated the 5 paid-flow + tip Stripe e2e tests, 18
`test.fixme` markers remained across `apps/web/tests/e2e/`. The user
asked: "can we continue with the other e2e tests that are skipped?"

This bundle triaged every remaining fixme and graduated the ones that
were genuinely achievable now — turning out to be **two pointer
comments** rather than two new tests, because the scenarios were
already covered elsewhere.

## What changed

1. **`navigation.public.spec.ts:71`** — the short-URL redirect fixme
   was converted to a pointer comment. The scenario is already
   covered by `meta-seo.public.spec.ts:178` ("GET /e/E2ETFA
   308-redirects to /events/<uuid>"), which asserts both the raw 308
   - `Location` header and the followed redirect using the persistent
     tournament seed (`E2ETFA`).

2. **`events.authed.spec.ts:149`** — the "Event full" fixme was
   converted to a pointer comment. Already covered by the capacity-1
   test in `event-attendance.authed.spec.ts` (graduated in bundle 96).

3. **`event-attendance.authed.spec.ts:339`** (leave outside refund
   window) — kept as fixme with a much-improved blocker explanation.
   Needs a `pickNearFutureDateTime(daysAhead, time)` helper because
   the existing `pickFutureDateTime` picks the LAST visible calendar
   day of the current month (1–~31 days out, right at the
   `MAX_REFUND_WINDOW_HOURS = 720` = 30-day boundary).

4. **Reverted** the experimental `pickFarFutureDateTime` helper added
   mid-triage — it's the wrong direction for this test (we need
   near-future, not far-future).

## What did NOT change (and why)

All 18 remaining fixmes have real, documented blockers:

- **Tournament mutations** (`tournament.authed.spec.ts`) — would
  pollute the persistent seed.
- **Stripe subscription / portal** (`billing-stripe.authed.spec.ts`)
  — state pollution (subscribing attendee-a leaves them Pro for the
  rest of the run); needs a dedicated `TEST_BILLING_VICTIM_EMAIL`.
- **Stripe Connect onboarding** — requires SMS verification, can't
  drive from Playwright.
- **Notifications** — require email-inbox access.
- **Community rate-limit** (6th submission/day) — would pollute
  attendee-a's daily quota for downstream tests.
- **Admin / extended event flows** — multi-step flows needing
  dedicated test users.

These should be addressed individually as their blockers are resolved,
not in a sweep.

## Lessons (recorded in `/memories/repo/e2e-tests.md`)

- **Before converting a fixme to a test, grep the description across
  ALL spec files** — two of three "achievable" fixmes turned out to
  be already covered elsewhere. The fix was a pointer comment, not a
  duplicate test.
- The `pickNearFutureDateTime` helper is now the explicit unblocker
  for the leave-outside-refund test. Documented in both the fixme
  comment and repo memory.

## Verify

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` — all green.
Short-URL test (the one we removed) confirmed redundant via a
`--grep "short URL redirect"` run that matched 2 tests passing on
dev. New version (after removal) confirmed no longer listed.
