# Bundle 107 — Bracket: tree-style visualization

## Why

Previous bracket layout rendered each round as a fixed-width column
of stacked match cards with no visual relationship between a match
and its two feeders. Functional, but the bracket didn't _look_ like
a bracket — readers had to mentally trace seed numbers to figure
out who plays whom in round 2.

Goal for this bundle: classic tree-style layout with `]` connector
glyphs between sibling pairs and matches in later rounds vertically
aligned with the midpoint of their feeders. No JS layout engine,
no dnd-kit-style coordinate math — pure flexbox + a couple of
absolute-positioned border spans.

## What changed

### New TreeBracket component

**NEW** [apps/web/src/app/events/[id]/bracket/\_components/tree-bracket.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/tree-bracket.tsx).
Server component (matches the rest of board-view.tsx). Takes the
filtered match list, a `renderMatch` callback, and an optional
`roundLabel` formatter.

Layout strategy:

1. **Outer flex-row** with a shared `min-height` driven by the
   first round's match count (`max(360, n * 96)px`). All round
   columns stretch to this height.
2. **Each round column** is `flex flex-col` with the matches
   wrapped in pairs (consecutive matches by `matchNumber`). The
   pair wrapper uses `justify-around` so matches in later rounds
   end up vertically aligned with the midpoint of their two
   feeders.
3. **Pair connector** — for each pair-of-two in a non-final round,
   an absolute-positioned `<span>` to the right with:
   `top: 25%; bottom: 25%; border-y border-r; -right-2; w-2`.
   Together with `gap-4` between round columns, this draws a `]`
   glyph that lands at the 25% / 75% midpoints of the two stacked
   matches and reaches halfway into the column gap.
4. **Incoming stub** — each non-first-round match draws a tiny
   `<span>` at `top: 1/2 -left-2 w-2 border-t` so the bracket
   line visibly enters the card from the right side of the
   previous column.

The two halves meet in the middle of the 16px gap. No JS
measurement, no Canvas, no SVG — works with SSR and React
Compiler memoization unchanged.

### BoardView swap

[apps/web/src/app/events/[id]/bracket/\_components/board-view.tsx](../../apps/web/src/app/events/%5Bid%5D/bracket/_components/board-view.tsx):
`renderRoundColumns` now delegates to `<TreeBracket>` instead of
its inline flat-column implementation. A `renderMatch` closure
captures the per-page props (eventId / divisionId / teamById /
bestOf / isHost / viewerId) so TreeBracket stays decoupled from
the page wiring. Removed the inline `groupByRound` helper —
TreeBracket has its own (sorted by `matchNumber` for stable pair
ordering, which the previous version didn't enforce).

Sections that now use the tree layout:

- Single-elimination — perfect 2:1 round structure, looks like
  the bracket the user has in their head.
- Double-elimination **winners** bracket — same.
- Double-elimination **losers** bracket — approximate; losers
  alternates feed/play rounds so some round-to-round ratios
  aren't 2:1. Connectors still render but won't always align
  exactly with the corresponding winners-bracket dropdown. See
  follow-ups.
- Double-elim **grand final** and pool-play **playoff** sections —
  both use TreeBracket too; small enough that the layout is
  trivially correct.

Pool-play **pools** view (round-robin within a pool) is unchanged
— a flat tile grid + standings table is the right shape for
that, no tree to draw.

## Patterns observed

- **Two CSS tricks were enough.** The whole tree shape comes from
  (a) `justify-around` on the round column so children spread to
  the midpoint of their feeders' pair, and (b) an absolute
  `<span>` per pair with inset top/bottom borders that forms the
  `]` glyph. Reaching for an SVG overlay or a layout library
  would have been ~10× the code for the same visual.
- **Connector pieces are reasoned about as "halves that meet in
  the gap."** Right side of pair extends `-right-2 w-2` (8px
  past column edge into the 16px gap). Left side of next round's
  match extends `-left-2 w-2` (8px the other direction). Total
  16px = `gap-4`. Easy to change uniformly by editing the gap +
  the two `w-2`s together.
- **MatchCard variable height is the worst case the design has to
  accept.** When a host expands the "Enter result" details, the
  card grows and its midpoint shifts down. The 25%/75% inset
  assumes equal heights, so an expanded card pulls its connector
  slightly off-center. The line still visibly reaches the card;
  documenting as known and moving on rather than instrumenting
  per-card heights with ResizeObserver.

## Follow-ups deferred

- **Losers-bracket layout polish.** Double-elim losers alternates
  feed and play rounds with non-2:1 ratios; the pair-grouping in
  TreeBracket assumes 2:1. Today it still reads as a tree, just
  with some pairs that don't have a true sibling. A proper fix
  would lay out losers as two parallel sub-trees with explicit
  feeder wiring from the winners bracket. Worth it when a host
  complains; out of scope for v1.
- **Connector ↔ expanded card alignment.** When a host opens
  "Enter result" the card grows downward and its midpoint
  shifts. Stamping the card with `min-h-[96px]` and using
  `flex-1` on the details body might keep the midpoint stable
  without a measurement step. Defer until anyone notices.
- **Highlight the bracket path of a selected team.** Click a
  team name → all matches that team plays are highlighted with
  a coloured ring. Quick win on top of TreeBracket; deferred.
- **Mobile horizontal scroll affordance.** The outer wrapper
  already does `overflow-x-auto`, but on touch devices a scroll
  hint (gradient fade on the right edge or a small chevron)
  would help discoverability. Cheap to add when revisiting.
- **Print stylesheet.** Hosts may want a printable bracket sheet
  for the gym wall. With the new tree layout, a print CSS that
  hides the controls and forces the bracket to fit a single
  landscape page would be a real-world win. Defer.
