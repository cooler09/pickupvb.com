# 2026-05-28 — Bundle 132 (Radix Toast)

Fourth installment of the M3 adoption plan from
[docs/audits/m3-alignment.md](../audits/m3-alignment.md). Bundle 129
shipped tokens, Bundle 130 swept touch targets, Bundle 131 introduced
the state-layer utility + button vocabulary, this bundle migrates the
toast system to `@radix-ui/react-toast` and brings it in line with the
M3 Snackbar spec.

## Context

Audit P2 #8 called out that
[toast.tsx](../../apps/web/src/components/toast.tsx) stacked unbounded
toasts in the top-right, exposed no action affordance, and used a
single hard-coded `durationMs` default. M3 Snackbar prescribes the
opposite on every axis: single visible snackbar with the rest queued,
optional **action slot** (this is how Snackbars do recovery —
"Couldn't save. **Retry**" instead of dumping the user at a flash-param
redirect page), bottom position on mobile / bottom-right on desktop,
and per-condition duration tokens (10 s for errors, 6 s when an action
is present, 5 s otherwise).

Rolling our own queue + action slot is a non-trivial amount of code
(focus management, swipe-to-dismiss, hotkey-to-dismiss,
`aria-live`-polite-vs-assertive, pause-on-hover). The audit's Plan C
prescribed Radix UI for exactly this class of widget — headless
primitives that bring the accessibility and behavior, leaving styling
to us. This bundle establishes the Radix convention in the codebase
and also documents it in [AGENTS.md](../../AGENTS.md) so subsequent
bundles (Dialog, DropdownMenu, Popover) reach for the same primitive
family.

## Decisions

- **Added `@radix-ui/react-toast` to `apps/web`** (production
  dependency, not devDep — the primitive ships in the client bundle).
  Followed the documented repo pattern: `pnpm --filter @pickupvb/web
add …` then a full `pnpm install` to reconcile peer-dep lockfile
  entries.
- **Preserved the entire `useToast()` public API.** `Toast`,
  `ToastVariant`, `ToastProvider`, and `useToast` are unchanged in
  shape; both existing call sites
  ([layout.tsx](../../apps/web/src/app/layout.tsx),
  [near-me-button.tsx](../../apps/web/src/app/events/near-me-button.tsx))
  needed zero edits. The new `ToastAction` interface is purely
  additive on the `Toast.action` optional field.
- **Single-visible queueing implemented at the context layer**, not in
  Radix. `toasts[0]` is rendered; everything else is held in state.
  `dismiss()` removes by id and the next call to `show()` while the
  queue is non-empty just appends. Radix's `<Toast.Root>` handles its
  own enter/exit lifecycle for the visible head; the queue around it
  is React state. This is simpler than letting Radix render N roots
  and trying to clip via CSS.
- **`type="foreground"` for errors / warnings, `"background"` for
  everything else.** This is the Radix knob that maps to
  `aria-live="assertive"` vs `polite`. Errors interrupt; success /
  info do not.
- **Duration policy moved into `defaultDurationMs(t)`** — returns
  `10_000` for errors, `6_000` when an action is present, `5_000`
  otherwise. Matches M3 Snackbar exactly. Callers can still override
  via `durationMs`; `0` is mapped to `Number.POSITIVE_INFINITY` for
  truly persistent toasts.
- **Position moved to bottom-center on mobile, bottom-right on
  `≥ sm`**, with `pb-safe` for iOS notch / home-indicator. Matches
  M3 Snackbar position rules. `pointer-events-none` on the viewport
  - `pointer-events-auto` on the root keeps the underlying page
    scrollable when a toast is visible.
- **Motion via CSS keyframes, not `tailwindcss-animate`.** Initial
  attempt used the `data-[state=open]:animate-in
slide-in-from-bottom-2` class set from
  `tailwindcss-animate`, but that package isn't installed and the
  existing M3 motion tokens already define the exact curves we want.
  Added one shared `.md-toast-motion` class to
  [globals.css](../../apps/web/src/app/globals.css) with three
  `@keyframes` (`md-toast-enter`, `md-toast-exit`,
  `md-toast-swipe-out`) and wired them to Radix's
  `[data-state]` / `[data-swipe]` attributes. Durations + easings
  resolve from `--md-sys-motion-duration-medium2` /
  `--md-sys-motion-duration-short3-4` and
  `--md-sys-motion-easing-emphasized-{accelerate,decelerate}` — the
  same tokens Bundle 129 shipped. Avoids a new dep, reuses the
  motion vocabulary.
- **Preserved the per-variant focus ring classes
  (`VARIANT_RING_CLASSES`)** from the original
  [accessibility audit Bundle 44](../audits/accessibility.md) fix.
  Both the new Action button and the Close button render their
  variant-correct ring color — WCAG 2.4.11 stays satisfied.
- **Preserved `FlashReader`.** The URL `?rsvp=...` flash-param
  consumer is unrelated to the M3 changes and any existing call sites
  in the app still need it; ripping it out is a separate bundle.

## Patterns observed

- The Radix `*.Root` / `*.Action` / `*.Close` / `*.Viewport`
  decomposition gives us **exactly the seams M3 specifies** — the
  action slot is a discrete primitive, the close affordance is a
  discrete primitive, the viewport is a discrete primitive. Styling
  per-variant just means passing different classNames; the
  behavior contract is identical.
- Wiring Radix's `[data-state]` / `[data-swipe]` to CSS keyframes via
  attribute selectors is **a one-line bridge** when you already have
  motion tokens. No JS animation library required. Worth remembering
  for Dialog / Popover / DropdownMenu in subsequent bundles — same
  pattern will compose.
- Putting the queue in React state (rather than letting Radix render
  multiple Roots) is the smaller, more testable surface. The
  `ToastContextValue.toasts` snapshot is now an assertable queue
  depth — a test can verify "second show() while one is visible
  appends instead of replaces" without touching the DOM.
- `tap-target` (Bundle 130) composes onto the Radix `*.Close`
  primitive cleanly — `<RadixToast.Close className='tap-target …'>`
  works because Radix forwards the className to the underlying
  `<button>`. Same expectation should hold for Radix Dialog close in
  Bundle 6.

## Follow-ups deferred

- **Action-button-driven recovery flows.** No call site uses
  `Toast.action` yet — it's wired and typed, ready for the first
  "couldn't save / retry" UX. Likely lands with the
  server-action-error-handling rework or the next round of optimistic
  UI work.
- **Swipe-to-dismiss visual polish.** The keyframe is wired; the
  in-flight swipe transform looks right on desktop with mouse-drag,
  but I haven't verified touch ergonomics on a real device. Open a
  follow-up if the swipe gesture feels off in QA.
- **Pause-on-hover tuning.** Radix pauses the auto-dismiss timer on
  pointer-enter and resumes on leave; we get this for free. Worth
  confirming during the next accessibility audit that this also
  satisfies WCAG 2.2.1 (Timing Adjustable) — likely yes since the
  toast remains dismissible via Close + Escape, but document it
  explicitly when we re-run that audit.
- **State-layer on the Close button.** The Close button is the one
  surface in the toast that doesn't carry the `state-layer` utility
  shipped in Bundle 131. Held off because the per-variant ring +
  variant-tinted hover already produces a coherent affordance and
  layering `state-layer` on top changed the chrome a little too much
  for what's an additive bundle. Pick up in the state-layer call-site
  sweep.
