# 2026-05-22 — Bundle 39: migration preamble standard

## Context

Bundle 38 closed the last open P2 on the organization audit (issue
templates + CODEOWNERS) and Bundle 37 closed the last open P2 on the
documentation audit (database-operations doc). The next-highest-signal
doc item is the first P3 from the documentation audit: **migration
preamble inconsistency**. Some migrations have rich preambles (e.g.
[20260513001100_anon_auth_pivot.sql](../../supabase/migrations/20260513001100_anon_auth_pivot.sql))
and many newer migrations follow a similar shape, but the convention
isn't written down anywhere — which means new migrations can drift
back to bare SQL without anyone catching it in review.

The audit's original fix said "Standardize a 4-line header (date /
title / context / impact) and apply going forward." That recipe was
too thin compared to what the good migrations actually do: the value
is in the **prose**, not in the four-line scaffold.

## What shipped

**[AGENTS.md → Migrations → Migration preamble](../../AGENTS.md)** —
new subsection codifying the de facto convention. Key points:

- **Banner rule** (`-- ====…`) top and bottom preferred for visual
  separation when scrolling through the migration body.
- **Title** — one-line imperative description.
- **ADR link** — **required** when the migration backs an ADR, so
  readers don't have to grep ADRs to find the why.
- **Context** block — why the change, what it builds on, non-obvious
  ordering constraints (backfill-before-NOT-NULL, dependency on a
  prior column landing, etc.).
- **Impact** block — what changes for callers, RLS posture shifts,
  view rebuilds, backfill semantics, and whether old code paths keep
  working until a follow-up migration.
- **Scale-to-fit:** the section names are scaffolding, not a checklist
  — trivial fixes can collapse to a sentence.
- **Three exemplars cited:** long hairy pivot
  ([anon_auth_pivot](../../supabase/migrations/20260513001100_anon_auth_pivot.sql)),
  ADR-driven additive
  ([event_divisions](../../supabase/migrations/20260605000100_event_divisions.sql)),
  one-paragraph bugfix
  ([fix_fill_default_division_id](../../supabase/migrations/20260605000600_fix_fill_default_division_id.sql)).
- **Backfilling old migrations is optional** — only do it when
  you're already touching the file in a follow-up PR. Never edit an
  applied migration solely to add a preamble.

## Pattern notes

- **Codify the floor, not the ceiling.** The audit recommended a
  strict 4-line schema. Looking at actual recent migrations, the
  value is in the prose breakdown of Context vs. Impact, and forcing
  a 4-line cap would have made the convention worse than the ad-hoc
  status quo. The rule of thumb: when codifying a convention, scan
  what the best existing examples actually do and write _that_ down.
- **Make the ADR link mandatory, not optional.** ADR-driven
  migrations without a link force the next reader to grep — high
  cost, zero benefit. This is the one hard rule in the new section.
- **Don't backfill historical artifacts purely for consistency.**
  Editing applied migrations risks confusion (which version did
  prod actually run?) for cosmetic gain. The convention applies
  going forward; old files stay as-is.
