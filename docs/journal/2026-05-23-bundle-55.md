# 2026-05-23 — Bundle 55: `RegisterTeamHandler` regression coverage

## Context

Bundle 52 reclassified two `RegisterTeamHandler` throws from
`UnauthorizedError` → `ValidationError` (the cross-event and
cross-division format mismatch). That fix shipped without unit tests
because the application package didn't have a test file for the team
handlers — only `join-event.handler.test.ts` existed. The follow-up
was logged so the reclassification couldn't quietly revert during a
future refactor.

This bundle ships those tests.

## What shipped

[packages/application/src/commands/team.handler.test.ts](../../packages/application/src/commands/team.handler.test.ts)
— 7 cases on `RegisterTeamHandler`, all using in-memory
`TeamRepository` + `EventRepository` doubles modeled on the existing
`InMemoryEventRepo` in `join-event.handler.test.ts`:

1. **Happy path** — captain registers a Sixes team to a Sixes division on
   a tournament. Asserts `attachTeamToDivision` is called with
   `(eventId, teamId, divisionId)` **and** `save()` is not — this locks
   in the Bundle 2 / Bundle 52 doctrine that the chosen `divisionId`
   lives only on the join row, not on the aggregate's `_teams` set.
2. **`NotFoundError`** when the team doesn't exist.
3. **`UnauthorizedError`** when the requester isn't the captain (the
   one branch that should stay an authorization error).
4. **`NotFoundError`** when the event doesn't exist.
5. **`ValidationError`** when team format ≠ event format (cross-event
   mismatch — the Bundle 52 reclassification).
6. **`NotFoundError`** when the chosen `divisionId` isn't on the event.
7. **`ValidationError`** when team format ≠ division format (cross-division
   mismatch — the other Bundle 52 reclassification). Event format is set
   equal to the team's format so the event-level check passes and the
   division-level branch is exercised in isolation. Two divisions are
   added (mismatched + matched) so the chosen `div-1` deterministically
   triggers the branch.

No production code changed.

## Verification

`pnpm typecheck && pnpm lint && pnpm test && pnpm build` — 15/15 × 3 + 8/8.

`@pickupvb/application` test suite went from 6 → 13 tests.

One drive-by error caught by the test run: I initially wrote
`Format.Fours` (the obvious doubles-court name) but the enum is
`{ Sixes, Quads, Triples, Doubles }`. The Division `assertFormatAllowedForSurface`
threw `InvariantViolation: Format 'undefined' is not allowed on surface 'indoor'.`
on the first run, which is exactly the kind of "enum member doesn't
exist" failure that an `as const` object can't catch at the type level
when accessed dynamically. Renamed to `Format.Quads` and tests went
green.

## Pattern notes

- **In-memory repository doubles via `Pick<EventRepository, ...>`** are
  the right scope for handler tests. `EventRepository` has many methods
  (`findMany`, `findByHostId`, payment sidecar accessors, etc.) that
  these handlers don't touch; `Pick` keeps the double minimal without
  forcing the test to implement the full interface or pull in
  `vi.mock()` ceremony. The existing `join-event.handler.test.ts`
  established this pattern; Bundle 55 just applied it to a second
  handler.
- **Assert both side effects: what was called AND what was NOT called.**
  The happy-path test checks `events.attached.length === 1` AND
  `events.saved.length === 0`. The "save is not called" assertion is
  what guards the Bundle 2 design — the aggregate's in-memory mutation
  from `event.registerTeam(...)` is intentionally discarded so the
  next `findById` rehydrates `_teams` from the DB. A regression that
  added `events.save(event)` after the aggregate mutation would
  re-introduce the original NOT NULL violation on `event_teams.division_id`.
- **`Format` is an `as const` value-and-type, not a true TS `enum`.** This
  means dotted access to a non-existent member type-checks as `undefined`
  at runtime instead of failing at compile time. Tests catch it
  immediately; type-only access doesn't. Worth a one-line lookup
  (`grep "Format = "`) before fabricating member names from intuition.
