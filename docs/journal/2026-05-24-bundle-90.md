# Bundle 90 — Hero Images

**Date:** 2026-05-24
**Scope:** Events, groups, and public profiles — wide banner image upload and display.

## Why

The platform had no file upload infrastructure at all. Avatar/logo fields on groups and profiles were plain URL text inputs. Hero images were chosen as the first upload surface because:

- Every event, group, and profile page has "wasted" space above the fold that a real photo makes significantly more compelling.
- `og:image` is currently driven by a generated brand card. A host-uploaded photo produces richer social share previews with no extra work.
- Building the upload primitive once unblocks avatar uploads, sponsor logos, and any future media feature.

See `docs/audits/hero-images.md` for the full proposal and trade-off analysis.

## Changes

### Migration (`supabase/migrations/20260625000000_hero_images.sql`)

- `ALTER TABLE events ADD COLUMN hero_image_url text`
- `ALTER TABLE groups ADD COLUMN hero_image_url text`
- `ALTER TABLE profiles ADD COLUMN hero_image_url text`
- `CREATE OR REPLACE VIEW profiles_public` — adds `hero_image_url` to the public projection so anon queries on the player profile page can read it without touching the base table.
- New Supabase Storage bucket `hero-images` (public read).
- Storage RLS policies: public SELECT, authenticated INSERT/UPDATE/DELETE scoped to `(storage.foldername(name))[1] = auth.uid()::text` (path prefix is the uploading user's id).

### `packages/supabase/src/database.types.ts`

## Decisions

**Display-time crop only.** No crop UI at upload time. `object-cover` handles aspect ratio at render. Keeps this bundle scoped — a crop widget is a separate bundle if ever needed.

**Immediate-save pattern.** The upload widget saves to DB right after the Storage upload completes, independent of the main form's Save button. This avoids lost-upload states if a user uploads a photo then navigates away without saving the form.

**Cache-buster on the returned URL.** Supabase Storage CDN caches aggressively. After a `upsert: true` upload to the same path, appending `?t={Date.now()}` forces browsers and the Next.js image CDN to fetch the new object immediately.

**`profiles_public` view updated in the same migration.** Since the player profile page uses an anon client against the view (not the base table), `hero_image_url` had to be added to the view projection in the same deploy as the column addition — otherwise the player page would silently return null for the field until the view was updated.

**Free for all tiers.** No Pro gate. Richer content benefits the whole platform regardless of host tier.

## Follow-ups

- Avatar URL fields on groups (new-group and edit-group forms) are still plain text inputs. Now that upload infrastructure exists, migrating them to a file picker is a natural next step.
- The event `opengraph-image.tsx` still generates a brand card. A follow-up can use `hero_image_url` as the og:image when set (requires fetching it from the DB in the OG image handler).
- Storage cleanup: when a hero image is removed (null written to DB), the old Storage object is not deleted. A cron or webhook cleanup job would prevent orphaned objects accumulating.
