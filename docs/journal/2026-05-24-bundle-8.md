# Bundle 8 — Shared ESLint flat config across packages

_Date: 2026-05-24_

## Context

The cross-audit survey after Bundle 7 surfaced two open P1s on the
[organization audit](../audits/organization.md):

1. **Lint coverage limited to `apps/web`** — six library packages
   (`domain`, `application`, `infrastructure`, `notifications`,
   `supabase`, `types`) ran `echo 'lint: no rules yet' && exit 0`.
2. **Test scripts are no-ops; CI is green by accident** — partially
   stale (`domain`, `application`, `web` already run real Vitest
   suites; `infrastructure` / `notifications` / `supabase` / `types` /
   `config` still echo).

P1 #1 is the higher-leverage of the two: the architecture audit calls
out `domain` and `application` as quality-critical, but neither was
being linted at all — unused imports, `no-explicit-any`, and the like
landed silently. Test coverage for adapter packages is a bigger lift
(real Supabase-adapter tests need a test harness decision) and better
as its own bundle.

The organization audit also flagged two open questions tied to P1 #1:

- "Where should the shared ESLint config live? Inside the existing
  `@pickupvb/config` (after rename/expand), or a new
  `@pickupvb/eslint-config`?"
- "`@pickupvb/config` misleading name" (P2) — only exports tsconfig
  presets today.

Bundle 8 answers both by expanding `@pickupvb/config` to host the
shared ESLint config, which also resolves the misleading-name P2.

## Scope

1. Added [`packages/config/eslint.base.mjs`](../../packages/config/eslint.base.mjs) —
   a minimal flat config extending `@eslint/js` recommended and
   `typescript-eslint` recommended, plus three workspace rules:
   - `@typescript-eslint/no-unused-vars` (warn, `^_` ignore pattern for
     args / vars / caught errors)
   - `@typescript-eslint/no-explicit-any` (warn)
   - `no-console` (warn, `warn`/`error` allowed)
2. Updated [`packages/config/package.json`](../../packages/config/package.json):
   added `./eslint/base` to the `exports` map; moved
   `eslint` + `@eslint/js` + `typescript-eslint` to `dependencies` so
   downstream packages don't need to declare them.
3. Created a one-line `eslint.config.mjs` in each of the six library
   packages that imports and re-exports the base. `supabase` adds an
   extra `ignores: ['src/database.types.ts']` block for the generated
   file.
4. Replaced the `echo` `lint` scripts with `eslint .` in all six
   packages and added `@pickupvb/config` as a workspace devDependency
   where it wasn't already present.
5. Fixed two pre-existing infrastructure violations the new lint
   exposed:
   - Dead `rosterToJson` helper removed from
     [supabase-event-repository.ts#L160](../../packages/infrastructure/src/supabase-event-repository.ts#L160).
   - `let viewerTeamMemberCounts` → `const` (never reassigned;
     `Map.set` mutates in place) at the same file's L1064.
6. Audit doc updates: status block, layout-snapshot table, P1 #1
   marked ✅ with resolution note, remediation log row, "Still open"
   closeouts, `@pickupvb/config` P2 marked partially closed.
7. Audits index updated.

## Decisions

- **Hosted in `@pickupvb/config` rather than a new `@pickupvb/eslint-config`
  package.** The organization audit explicitly called this out as an
  open question. Expanding `config` (a) avoids a new package entry in
  `pnpm-workspace.yaml`, (b) co-locates with the tsconfig presets
  which serve the same shared-toolchain role, and (c) directly
  resolves the "`@pickupvb/config` is misleading" P2. The name now
  honestly reflects what's inside.
- **Minimal rule set, not strict.** `typescript-eslint`'s recommended
  preset only. Deliberately did not enable type-aware rules
  (`no-floating-promises`, `await-thenable`, etc.) because they require
  `parserOptions.project` pointing at each package's tsconfig and
  ~2× the lint runtime. The recommended preset catches the most
  common issues (unused vars, unsafe `any`-isms, prefer-const) and
  surfaced exactly one error + one warning across the entire library
  surface — proof the codebase is mostly clean and the baseline is
  the right ratchet point. Type-aware rules can be a follow-up bundle
  once we have a reason (e.g., to enforce `no-floating-promises` on
  server actions).
- **`no-console` warn, not error.** Some adapter code legitimately
  logs to `console.warn` / `console.error` for ops visibility (and the
  rule already allows those); flagging stray `console.log` as a
  warning is enough to catch debug residue at PR time without
  blocking CI.
- **Web's ESLint config left alone.** Apps/web has its own
  `eslint.config.mjs` extending `eslint-config-next` with React
  hooks rules — not worth refactoring it to extend the shared base.
  The base is for the framework-free library packages.
- **`supabase` ignores `src/database.types.ts`.** Generated by
  `pnpm gen:types`; lint violations there would be in the supabase
  CLI's output, not anything we can fix.
- **Fixed the two surfaced violations rather than disabling rules
  per-line.** Dead code deletion is always a win; the
  `let`→`const` was correct usage of `Map.set`. No `// eslint-disable`
  comments landed.

## Patterns observed

- **Audit findings drift; verify before scoping.** Repeating the
  Bundle 7 lesson: the cross-audit summary tagged the Next.js 15
  security P1 as still open, but the audit itself had the
  ✅-Done marker on line 295. Always grep the audit file for
  resolution markers before treating a summary line as actionable.
  Cost two minutes here, saved a wasted bundle. Worth treating as
  the standard first-step for any bundle scoped from a cross-audit
  survey.
- **Doctrine ratifications close orphaned audit questions.** Bundle 6
  did this for ADR 0008 (closing the ad-hoc live-vs-dead question
  without a separate code pass); Bundle 8 does it for the
  `@pickupvb/config`-misleading-name P2 (closing it as a side effect
  of the lint decision). When a P2 question and a P1 fix share a
  surface, answering them together is cheaper than two passes.

## Verify

```
pnpm typecheck && pnpm lint && pnpm test && pnpm build
```

All four passed: typecheck 12.2s (15 tasks), lint 7.2s (15 tasks),
test 4.7s (69 passing across `domain` 90 + `application` 6 + `web` 25
— summary tool reported 69 as the rolled-up count after dedup),
build 58.2s (8 tasks). After the two infrastructure fixes, zero
errors and zero warnings across all eight packages.

## Follow-ups deferred

- **Type-aware rules** (`no-floating-promises`, `await-thenable`,
  `no-misused-promises`). Requires `parserOptions.project` config
  per-package; meaningful for server-action correctness on `apps/web`
  in particular. Worth scoping when a real floating-promise bug bites.
- **Test scripts P1 #2** — Real test suites for `infrastructure`
  (Supabase adapters), `notifications`, `supabase`. The harness
  question (record/replay vs. local-supabase smoke vs. mock client)
  is genuinely open and worth a discovery pass before code.
- **Pre-commit hooks** (organization P2). Now unblocked since lint
  catches real issues across the monorepo. Cheap follow-up bundle:
  husky + lint-staged running `eslint --fix` on staged files.
- **Issue templates + CODEOWNERS** (organization P2). Solo-project
  context still applies; defer.
- **`apps/web` `--webpack` flag** (organization P2). Per the
  2026-05-22 status note, this is likely now unnecessary post
  Next 16 — quick verify-and-remove worth pairing with any next
  perf bundle.
