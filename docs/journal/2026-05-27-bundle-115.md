# Bundle 115 — Bracket follow-ups sweep

## Why

Closing out the menu surfaced at the end of [bundle 114](2026-05-27-bundle-114.md):
seven small bracket follow-ups grouped into one bundle so the watch
page, format picker, and OG cards reach feature-parity with the rest
of the events surface.

## What changed

1. **Min-teams validation on the server.** `CreateBracketHandler` now
   loads registered teams and throws `ValidationError` with code
   `invalid` if the count is below `minTeamsForFormat(format)` (2 for
   single-elim, 3 for double-elim / round-robin, 4 for pool-play). The
   client picker disables formats below the threshold already; this
   closes the last loophole (direct POST / racing registrations) at the
   application boundary.
   - [packages/domain/src/brackets/enums.ts](../../packages/domain/src/brackets/enums.ts)
     exports `minTeamsForFormat`.
   - [packages/application/src/commands/bracket.handler.ts](../../packages/application/src/commands/bracket.handler.ts).

2. **Format thumbnails in the picker.** Each card in
   [format-picker-form.tsx](../../apps/web/src/app/events/[id]/bracket/_components/format-picker-form.tsx)
   now has a 64×32 inline SVG sketch on the left — single-elim tree,
   double-elim two-tree-feeding-final, K4 graph for round-robin, two
   pool rectangles plus a mini playoff for pool-play. Pure decorative
   (`aria-hidden`); the dl on the right still carries the real info.

3. **`?focus=match-xxx` deep link.** Both the host workspace
   ([page.tsx](../../apps/web/src/app/events/[id]/bracket/page.tsx))
   and the spectator view
   ([watch/page.tsx](../../apps/web/src/app/events/[id]/bracket/watch/page.tsx))
   read a `focus` query and (a) pass it to `BoardView` as
   `highlightMatchId`, (b) pass it to `LatestMatchTracker` as
   `initialFocusId`. The tracker now scrolls and flashes a target on
   first mount when present.

4. **Per-division share URLs.** When the event has >1 division, the
   "Share" link and the "Open public spectator view" link both pin the
   currently selected division via `?division=`, so a host sharing the
   "B Division" workspace produces a URL that lands the recipient on
   the same division.

5. **"Don't yank me" autoscroll guard** (deferred from bundle 113).
   [latest-match-tracker.tsx](../../apps/web/src/app/events/[id]/bracket/_components/latest-match-tracker.tsx)
   no longer scrolls automatically when _any other_ match card is
   already meaningfully on screen — checked synchronously via
   `getBoundingClientRect` across `[id^="match-"]` nodes (>25% of
   element height visible). The flash highlight still fires so the
   viewer notices the update without losing their place.

6. **Per-division OG image.** A new
   [og/route.ts](../../apps/web/src/app/events/[id]/bracket/watch/og/route.ts)
   route handler renders the OG card with the requested division, and
   `generateMetadata` in
   [watch/page.tsx](../../apps/web/src/app/events/[id]/bracket/watch/page.tsx)
   now reads `searchParams.division` and points `openGraph.images` at
   it. The file-convention
   [opengraph-image.tsx](../../apps/web/src/app/events/[id]/bracket/watch/opengraph-image.tsx)
   stays as the crawler fallback; both call the shared
   [\_og.tsx](../../apps/web/src/app/events/[id]/bracket/watch/_og.tsx)
   renderer.

7. **Winner name in OG when bracket is `completed`** (deferred from
   bundle 114). `pickChampion` in the shared OG helper walks matches
   to find the final winner (final-side completed match first; else
   any completed terminal); when found, the eyebrow becomes
   `Champion: {team}`. Round-robin still falls back to "Final results"
   until standings render — see follow-ups.

## Patterns observed

- **Underscore-prefixed files are colocated-but-non-routable** in the
  App Router. Used `_og.tsx` alongside the route segment to share
  render logic between the file-convention handler and the query-aware
  route handler without spawning a new module under `lib/`. Mirrors
  the `_components/` and `_loaders/` convention this repo already
  leans on.
- **`getBoundingClientRect` is the right primitive** when you need a
  visibility answer _right now_ inside an effect, not a stream of
  events over time. `IntersectionObserver` is the wrong shape — it's
  async and you'd have to track entries you don't otherwise care
  about. The synchronous read pairs cleanly with the existing
  scroll/flash decision in `LatestMatchTracker`.
- **`ImageResponse` extends `Response`**, so a route handler can
  return it directly without the typical `new Response(body, init)`
  ceremony. Keeps the handler at five real lines.
- **Two OG entry points, one renderer.** The file-convention
  `opengraph-image.tsx` can't read query strings; the route handler
  can. Have both — file convention for crawlers that ignore meta
  tags, route handler for everyone else via `openGraph.images`.

## Follow-ups deferred

- **Per-match "Copy link" UI.** The `?focus=` deep link is currently
  URL-craftable; a small copy-link control on `MatchCard` would close
  the loop. Skipped to keep the bundle tight.
- **IBM Plex in OG cards.** Satori still falls through to the system
  default. Loading the brand font would tighten visual consistency
  with the rest of the marketing surface.
- **Round-robin champion via standings.** `pickChampion` only handles
  bracket-style finals; round-robin "completed" status still renders
  "Final results" without a team name. Needs a standings-aware path.
- **Winner cup glyph** next to the champion eyebrow.
- **Per-division share for the host workspace too** (currently only
  the spectator view's share link pins division — host workspace
  copy works but the link already lives on the same path so it's
  effectively free; double-check during the next host UX pass).
- **Format thumbnail accessibility.** If we ever want them to convey
  information beyond decoration (e.g. for screen-reader users
  choosing a format), they'll need `<title>`/`<desc>` and an
  `aria-label` on the wrapper.
