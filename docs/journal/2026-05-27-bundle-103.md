# Bundle 103 — Live score tracker (first host tool)

## Why

The host-tools landing at `/tools` has been a static "Coming soon" grid
since launch. The user kicked off the host-tools tier with two
questions: should these be Pro, and can we start with a live score
tracker that covers both pickup ("disposable scoreboard on the gym TV")
and tournament ("save the result of each game") use cases.

Decision: **base host tools stay free, persistence becomes the Pro
hook**. Reasoning written to `/memories/repo/host-tools.md`. The
short version:

- The monetization plan already says "free for casual users is
  non-negotiable" and the existing wedges (ticket fees, Pro CSV /
  unlimited paid events, tips) are orthogonal to utilities.
- Every shared `/tools/scoreboard/AB12` link is a viral surface that
  brings non-pickupvb people onto the platform. Gating it loses the
  wedge entirely.
- Phase 6 ("Tournament hosting tier") in the monetization plan
  already anticipates a Pro layer; it should sit on top of the free
  utility rather than replace it. Free tools, paid persistence /
  event linkage / multi-court dashboards.

"Host knows best" was the second design constraint. No auto-locking
state transitions: the scoreboard shows a "set point" badge when the
target + win-by is satisfied, but the host taps **Win set** to commit.
Same idea for match-won. Makes the tool genuinely sport-agnostic
(volleyball, pickleball, ping pong, dodgeball — whatever the host is
running).

## What changed

### 1. Realtime protocol — no backend, no DB

The hard architectural call was sync. Three options, picked the third:

1. WebRTC peer-to-peer — privacy-perfect, zero cost, but NAT
   traversal is fiddly and overkill for "two devices in the same
   gym."
2. Persist every increment to a `scoreboard_events` table — wasteful
   for the disposable case, drags in RLS, auth, retention. Save it
   for the Pro persistence layer.
3. **Supabase Realtime `broadcast` channel** — pure pub/sub on
   `scoreboard:{code}`. No DB rows. No auth. No RLS. The channel
   evaporates when the last subscriber leaves. ✅

Conflict resolution is last-write-wins by a monotonic `version`
counter on the state snapshot, with `updatedAt` as a tiebreaker.
Two devices tapping at the same time → one increment overrides the
other, host can correct with a single `−1` tap. Acceptable for a
scoreboard and keeps the protocol trivial.

Late-join: when presence sync fires, every connected peer
rebroadcasts its current state. The peer with the highest `version`
wins, so a fresh subscriber catches up within a round-trip.

  chrome). Giant tap-target per team for + point, smaller `−1` /
  `Win set` controls floating below. Top bar shows room code,

  Wake Lock API requested on mount to keep the gym TV awake.

    — phone-sized controller. Big `+` / `−` per team, "Win set" CTA
    appears at set point. Joins the same realtime channel.
- **NEW** `_lib/types.ts` — pure functions (`increment`, `commitSet`,
  `isSetWon`, `matchWinner`, `swapSides`, `resetMatch`) with no
  framework or Supabase dependencies. Kept under the route folder
  (not promoted to `packages/domain`) because the scoreboard is not
  yet a domain concept — it's an ephemeral utility. Promote when
  Pro persistence lands.
- **NEW** `_lib/room-code.ts` — 4-char codes from a non-ambiguous
  alphabet (no `0/O/1/I/L`), ~1.4M combos. Collision risk is fine
  because there's no data at rest to leak; two hosts on the same
  code would just see each other's increments.
- **NEW** `_lib/storage.ts` — `localStorage` mirror, keyed by code,
  24h TTL with prune-on-touch so a host tablet doesn't accumulate
  dead games across a season.
- **NEW** `_lib/use-scoreboard-sync.ts` — the realtime hook. Mirrors
  state to `localStorage` on every set, broadcasts with `self: false`,
  uses presence sync as the cue to re-announce state for late
  joiners.
- **MOD** [apps/web/src/app/tools/page.tsx](../../apps/web/src/app/tools/page.tsx)
  — surfaced "Open →" on the now-live scoreboard, kept the other
  three tools as "Coming soon".

### 3. Things deferred (intentionally)

- **QR code on the share modal.** Keeps the dependency footprint
  clean for v1. URL + copy + Web Share API covers it. Add `qrcode`
  later if users ask.
- **Pro persistence.** No DB schema yet. The state model is shaped
  so a future `scoreboard_sessions(event_id, snapshot jsonb, ...)`
  table can serialize `ScoreboardState` directly.
- **Multi-set undo.** Current model is `±1` point and `Reset match`.
  Good enough for a v1; a proper undo stack is a clean follow-up.

## Pitfalls hit

- `typedRoutes` rejected the raw string literal `'/tools/scoreboard'`
  in the tools-index `Tool` type. Cast with `as Route` — same pattern
  noted in `followups.md` from the Next 16 stage.
- `exactOptionalPropertyTypes: true` tripped on
  `onWinSet={cond ? fn : undefined}` for `TeamPanel`. Switched to
  the spread pattern `{...(cond ? { onWinSet: fn } : {})}` per
  AGENTS.md. Repeat-offender — worth keeping the muscle memory.
- `react-hooks/refs` is a hard error (not a demoted warning): writing
  `stateRef.current = state` at the top level of a render is now
  banned by the new React lint rules. Moved into `useEffect(() => {
stateRef.current = state; }, [state])`.
- Three `react-hooks/set-state-in-effect` warnings remain (theme
  hydrate from `localStorage` + share-URL derivation from
  `window.location`). Consistent with the repo-wide demotion in
  `apps/web/eslint.config.mjs`. Proper fix is `useSyncExternalStore`
  with `getServerSnapshot` — captured in `followups.md` already as a
  general housekeeping item.
