# 2026-05-22 — Bundle 35: API reference doc

## Context

After Bundle 34 closed the testing-strategy P2, the remaining P2 docs
cluster was api-reference / JSDoc-backfill / monitoring / DB-ops.
api-reference is the highest-signal of the four because the README's
6-endpoint list at the time of the audit was both stale (missing 9
routes) and the only HTTP surface inventory anywhere in the repo. The
audit's parenthetical hint also listed routes that don't exist
(`/api/auth/*`, OG image route handlers) — worth correcting since
those are easy to chase.

## What shipped

**[docs/api-reference.md](../api-reference.md).** One entry per route
handler under [apps/web/src/app/api/](../../apps/web/src/app/api/):

- **Conventions section** up front: error envelope shape, the
  `DomainError` → HTTP status mapping table pulled from
  [api-helpers.ts](../../apps/web/src/lib/api-helpers.ts), the
  `dynamic = 'force-dynamic'` default, the no-CSRF-token /
  same-origin-cookie posture.
- **15 route entries** grouped by area (health / events / statements /
  notifications / webhooks / geocode / diagnostics). Each entry
  includes source link, auth model, schema reference, error codes,
  and behavior notes pulled from the JSDoc blocks already in the
  source. Cron schedules pulled from
  [apps/web/vercel.json](../../apps/web/vercel.json).
- **"Adding a new endpoint" checklist** at the bottom — `force-dynamic`,
  Zod parse, `requireUser` / `getViewer`, delegate to a CQRS handler,
  throw typed `DomainError`, wrap in `try { … } catch { handleError }`,
  add a row to this doc.
- **Cross-links** to ADR 0011 (Stripe webhook dedupe),
  [docs/stripe-webhooks.md](../stripe-webhooks.md),
  [docs/integrations.md](../integrations.md),
  [docs/runbook.md](../runbook.md).

**[README.md](../../README.md) endpoint list refreshed.** The stale
6-entry bullet list became a 7-line summary by area plus a pointer to
the full reference. Avoids drift between the two places — the README is
discoverability, the reference is canonical.

## Patterns surfaced

- **Audit hints can be wrong about absent code, not just present
  code.** Bundle 34 hit this with "no tests exist"; Bundle 35 hits the
  inverse — the audit _added_ nonexistent endpoints (`/api/auth/*`, OG
  image routes) to its hint list. Supabase Auth's callback is a page
  under `/auth/callback`, not an API route; OG images use the
  `opengraph-image` file convention, not a route handler. Worth
  verifying both "what's missing" and "what's mentioned" against tree
  before treating the audit as ground truth.
- **JSDoc on route handlers is already a near-complete API reference.**
  Most handlers had a multi-line JSDoc preamble explaining auth model,
  source-of-truth table, and column lists (the statement CSVs are
  especially well-documented). The doc-writing pass was mostly
  consolidation, not authorship. Worth keeping that JSDoc convention
  on new handlers — the cost is "remember to add a row to
  api-reference.md" rather than "design the doc from scratch".
- **Status-code mapping table is high-value even if duplicated.** It
  lives in [api-helpers.ts](../../apps/web/src/lib/api-helpers.ts)
  source, in [AGENTS.md](../../AGENTS.md), and now in
  api-reference.md. Three copies, but each serves a different
  reader: the file is for code search, AGENTS is for agents writing
  new actions, api-reference is for integrators reading curl output.
  Drift risk is real — if a 7th error class lands, all three need
  updating. Mitigation: the existing AGENTS pattern of "throw typed,
  let helpers map" means changes are concentrated in one file.
