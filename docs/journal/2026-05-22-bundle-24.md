# 2026-05-22 — Bundle 24: events/[id] JSX componentization (P2 follow-up)

## Context

Bundle 23 extracted the data layer of `events/[id]/page.tsx` into a
`loadEventDetail()` helper, dropping the page from 887 → 566 LOC. The
audit's aspirational ≤300 LOC target wasn't reached because the
remaining bulk was JSX render branches, not orchestration. That was
explicitly carried as a P2 follow-up. This bundle delivers it.

## Decisions

- **Six new components under `_components/`, all server-rendered.** Each
  absorbs one cohesive render branch. The split lines were drawn around
  what shares props rather than what visually clusters on screen — the
  signup-area switcher (one decision tree across external/open-play/
  tournament/closed) was kept as one component, while structured data,
  flash banners, location, host tools, and the attendees panel each
  became their own file.
- **Pass typed slices, not the whole view-model.** Components take only
  the fields they need. The signup-area component is the exception —
  it takes ~15 props because every branch needs a different slice and
  threading them through individual leaf panels would duplicate the
  switching logic. Worth the prop count for the locality.
- **Inline trivial sections.** When/Spots, Description/Rules, and the
  bracket-CTA block stayed inline (~50 LOC combined). They're each
  10-15 LOC, have no internal logic, and extracting them would trade
  page LOC for boilerplate file count without improving readability.
- **No barrel index.** New components imported directly. `_components/`
  has 30+ files already and the conventional pattern in this repo is
  named-export-per-file with no barrel.

## Patterns surfaced

- **Two-pass page diets work.** Splitting data extraction (Bundle 23)
  from JSX componentization (Bundle 24) made each pass mechanical and
  easy to review. Doing both in one bundle would have produced a much
  larger diff and made type-bridge issues harder to isolate.
- **Signup-area switchers are a recurring page-detail pattern.** Any
  page with `external | published-open | published-closed` × multiple
  registration modes tends to grow a giant ternary chain. Promoting it
  to its own component with a typed prop bag turns the chain into a
  flat `if/return` ladder that's easier to read and lint.
- **Per-section components scale better than per-feature components.**
  The temptation was to group "everything tournament-related" into one
  component, but tournament rendering touches the signup area, the
  bracket CTA, the teams list, and host tools — all at different points
  in the page flow. Cohesion-by-section (where they appear in the
  scroll) won over cohesion-by-feature.
