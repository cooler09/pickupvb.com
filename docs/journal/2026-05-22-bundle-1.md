# Bundle 1 — billing typed errors, Next.js peer floor, force-dynamic cleanup (2026-05-22)

## Context

First post-audit remediation sweep after the security/performance/architecture
audits landed. Backfilled retroactively after Bundle 2 to give the journal a
starting point.

Audit sources:

- [docs/audits/security.md](../audits/security.md) — billing flows throwing raw
  `Error` strings.
- [docs/audits/performance.md](../audits/performance.md) — three pages pinned
  to `force-dynamic` with no cache-bust reason.
- [docs/audits/architecture.md](../audits/architecture.md) — `packages/supabase`
  pinned an older Next.js peer that masked the real version in `apps/web`.

## Decisions

- **Bumped Next.js peer floor in `packages/supabase` to match `apps/web`
  (16.2.6)** rather than downgrading the app. The phantom 14.2.35 entry in
  the lockfile came from a stale peer range; aligning the floor is the
  smaller blast radius.
- **Threw typed `DomainError` subclasses in billing flows** —
  `InvariantViolation` for missing config (Stripe key / price IDs),
  `UnauthorizedError` for "no active subscription". Rejected returning
  `{ ok: false, error }` shapes because the rest of `application/` already
  throws `DomainError`; consistency wins.
- **Removed `export const dynamic = 'force-dynamic'` from 3 pages** that had
  no per-request data dependency. Replaced with route-segment revalidation
  where the page reads mutable Stripe data. Stripe-return pages keep an
  explicit `revalidatePath` comment instead.

## Changes

- `packages/supabase/package.json` — Next.js peer floor `>=16.2.0`.
- `apps/web/src/app/profile/billing/**` — billing actions throw
  `InvariantViolation` / `UnauthorizedError`.
- `apps/web/src/app/{events,teams,groups}/...` — 3 `force-dynamic` exports
  removed; Stripe-return paths annotated with deferred-revalidation
  comments.
- `AGENTS.md` — new "Patterns surfaced by audits" section (6 rules).

## Patterns observed

- The lockfile can pin a phantom older version of a framework when one
  workspace package declares a stale peer range. Always check
  `packages/*/package.json` peer ranges when a major upgrade looks
  half-applied.
- `force-dynamic` was being used as a "make it work" cargo cult. Default
  to static / revalidate; only opt out when there's a real per-request
  data read.
- Billing code was the worst offender for `throw new Error(string)`. The
  rest of `application/` already used typed errors — billing was an
  outlier, not a precedent.
