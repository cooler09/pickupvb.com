## What shipped

### Root `CODE_OF_CONDUCT.md` (new)

[CODE_OF_CONDUCT.md](../../CODE_OF_CONDUCT.md) — the Contributor
Covenant 2.1 verbatim text. Two deliberate choices:

1. **No bespoke wording.** The Contributor Covenant is the GitHub-default
   template and the most widely-recognised CoC in OSS. Authoring a
   custom version invites pointless debate over wording and signals
   nothing useful. Verbatim adoption is the right move for a
   personal-project repo that doesn't have the bandwidth to defend a
   custom doc.
2. **Enforcement channel = private security advisory.** The project
   has no Discord, no email list, no separate moderation team. The
   only existing private channel is the GitHub security-advisory
   route already documented in CONTRIBUTING.md. Reusing it for CoC
   reports keeps the contributor surface small and consistent — one
   private channel, two valid reasons to use it.

The doc covers the standard Contributor Covenant sections: Pledge,
Standards, Enforcement Responsibilities, Scope, Enforcement,
Enforcement Guidelines (the four-step ladder: Correction → Warning →
Temporary ban → Permanent ban), and Attribution back to
contributor-covenant.org.

## Pattern notes

### Closing a gated finding can unlock a downstream gated finding

Bundle 56's CONTRIBUTING.md framing ("PRs welcome but ad-hoc") was
itself the answer to a gating question on its own audit row, **and**
simultaneously the answer to the gate on the code-of-conduct P3.
Worth a sweep next audit: any time a gated finding closes, re-check
whether other findings that depend on the same gate are now
actionable. Both Bundle 56's open-vs-closed answer and Bundle 57's
"accepting contributions ⇒ ship CoC" flowed from the same upstream
decision.

### Verbatim-template wins over bespoke text for governance docs

The first impulse on a CoC is to "make it ours" — write something
that sounds like the project's voice. That's the wrong move for
governance documents. The Contributor Covenant is universally
recognised; reporters and contributors don't have to learn a new
ruleset; the text doesn't drift under maintenance pressure. Same
logic applied to MIT (Bundle ~17), which we shipped verbatim from
choosealicense.com rather than tailoring. Standard governance text is
a feature, not a constraint to escape.
